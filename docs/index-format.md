# 목차 갱신 기준

[README로 돌아가기](../README.md#writing-guide)

목차는 GitHub 플러그인으로 직접 편집하거나 `tools/build_index.py`로 갱신할 수 있습니다.
**Python 실행은 필수가 아닙니다.** 갱신 방법과 관계없이 아래 기준을 적용하고,
커밋의 **TIL Index Check** 결과를 확인합니다. CI는 목차를 수정하지 않고 표준 결과와의 일치 여부만 검사합니다.

## 1. 원본 읽기

- 현재 도구의 대상은 `2026-*/2026-*.md`입니다. 월별 `README.md`는 기록 수에 넣지 않습니다.
- 파일명의 `YYYY-MM-DD`가 날짜, 앞 7글자가 월입니다. 모든 기록을 날짜 오름차순으로 읽습니다.
- 머리말의 `> **단계:**`와 `> **주제:**` 값을 사용합니다. 끝의 `<br>`와 앞뒤 공백은 제외합니다.
- 두 값 중 하나라도 없으면 `tools/legacy_index.tsv`에서 같은 날짜의 단계와 주제를 함께 가져옵니다. 거기에도 없으면 원본을 확인하고 보완합니다.
- 단계는 `/` 또는 `·`로 나누고 각 값의 앞뒤 공백을 없앱니다. 빈 값은 제외하며 이름을 임의로 합치거나 바꾸지 않습니다.
- 주제 요약은 90자 이하면 그대로, 더 길면 앞 89자의 끝 공백을 제거한 뒤 `…`를 붙입니다. 원본 주제는 줄이지 않습니다. Python의 문자 수 기준이며 바이트 수가 아닙니다.

## 2. README 목차 구간

`<!-- 목차 시작: 기록 머리말 기준으로 갱신합니다. docs/index-format.md 참고. -->`와
`<!-- 목차 끝 -->` 사이만 갱신합니다. 배너와 작성 가이드 등 구간 밖 내용은 유지합니다.

1. `<a id="latest"></a>`, 빈 줄, `### 01 / 최근 기록`, 빈 줄을 둡니다.
2. 최신 3건을 날짜 내림차순으로 나열합니다. 3건 미만이면 있는 기록만 표시합니다.
   각 기록은 아래의 두 문단으로 씁니다. `원본 단계`는 머리말 값을 그대로 사용합니다.

   ```markdown
   **[YYYY-MM-DD](./YYYY-MM/YYYY-MM-DD.md)** · 원본 단계

   주제 요약
   ```

3. 빈 줄 뒤 `<a id="archive"></a>`, 빈 줄, `### 02 / 월별 아카이브`와 3열 표를 둡니다.
   월은 **내림차순**입니다. 첫 열의 월 이름이 월별 목차 링크입니다.

   ```markdown
   | 월 / 목차 | 기록 | 주요 단계 |
   | :--- | :---: | :--- |
   | [**YYYY-MM →**](./YYYY-MM/README.md) | N건 | 주요 단계 |
   ```

4. 주요 단계는 해당 월의 단계별 출현 수 상위 4개를 ` · `로 연결합니다.
   동률이면 날짜 오름차순 기록과 그 기록의 단계 표기에서 **먼저 등장한 순서**를 유지합니다.
5. 표 아래 한 줄: `**기록 N건.** 날짜를 모를 때는 [주제별 색인](./docs/topics.md)에서 찾습니다.`

## 3. 월별 목차

- 제목은 `# YYYY-MM 학습 기록`입니다. 빈 줄 뒤 `**MONTHLY ARCHIVE / 배움의 현장 기록**`을 둡니다.
- 탐색 줄은 `[전체 목차](../README.md#learning-log) · [주제별 색인](../docs/topics.md)`입니다.
  이전 기록 월이 있으면 ` · [← YYYY-MM](../YYYY-MM/README.md)`, 다음 기록 월이 있으면
  ` · [YYYY-MM →](../YYYY-MM/README.md)`를 이 순서로 추가합니다. 기록이 없는 달로 연결하지 않습니다.
- 안내는 `이 달의 기록 **N건** · 최신 날짜부터 정리합니다. 날짜를 누르면 기록을 읽을 수 있습니다.`입니다.
- 표 머리는 `| 날짜 | 기록 / 단계 |`, 구분 줄은 `| :---: | :--- |`입니다.
- 날짜 **내림차순**으로 `| [**DD일**](./YYYY-MM-DD.md) | 주제 요약<br>원본 단계 |`를 적습니다.
  `<br>` 앞뒤에 공백을 넣지 않습니다. 단계와 요약을 같은 셀의 두 줄로 읽게 해 좁은 화면의 열 수를 줄입니다.
- 새 월을 추가하면 이전 마지막 월의 다음 월 링크도 갱신합니다.

## 4. 주제별 색인

- 제목은 `# 주제별 색인`, 다음 문단은 `**SUBJECT INDEX / 날짜 대신 주제로 찾기**`입니다.
  돌아가기 링크와 두 줄 안내 문장은 현재 파일의 형식을 유지합니다.
- 분류는 기록 수 내림차순, 동률이면 태그 문자열 오름차순입니다. 분류 안의 날짜는 **내림차순**입니다.
- 첫 분류부터 1번을 부여하고, 상단 탐색 줄에 `[태그 (N)](#topic-번호)`를 ` · `로 연결합니다.
- 각 분류에는 `<a id="topic-번호"></a>`, 빈 줄, `### 태그 (N건)`, 빈 줄, 기록 목록을 둡니다.
- 각 기록은 `- [YYYY-MM-DD](../YYYY-MM/YYYY-MM-DD.md) · 주제 요약`입니다.
  날짜만 나열하지 않고 주제도 함께 표시해 브라우저 찾기와 Markdown 검색으로 내용을 찾을 수 있게 합니다.
- 분류 순서가 바뀌면 상단 링크와 앵커 번호를 함께 갱신합니다.

## 5. 확인과 저장

각 제목·문단·표·목록 사이에는 빈 줄 하나를 둡니다. 파일은 UTF-8, LF 줄바꿈과 마지막 개행을 유지합니다.
목차 구간 시작/끝 주석과 본문 사이에도 빈 줄 하나를 둡니다. 현재 파일 또는 렌더 함수의 형식을 기준으로 맞춥니다.

- 기록 파일 추가·수정과 관련 목차를 같은 변경 묶음에 포함합니다.
- 전체 건수, 월별 건수, 태그별 건수, 최근 3건, 요약과 모든 상대 링크를 대조합니다.
- 로컬 실행이 가능하면 `python tools/build_index.py --check`로 확인할 수 있습니다.
  단위 테스트는 `python -m unittest discover -s tools -p "test_*.py"`로 실행합니다.
  불일치 시 직접 수정하거나 `python tools/build_index.py`로 한 번에 갱신합니다.
- 직접 편집한 경우에도 해당 커밋의 CI가 성공했는지 확인합니다. 대기·실패·미실행을 성공으로 보고하지 않습니다.
- 형식 자체를 바꾸는 작업은 이 문서, `tools/build_index.py`, 목차 파일과 테스트를 함께 수정합니다.
- 현재 2026년 전용 탐색 규칙을 다음 해에도 쓰려면 도구·문서·테스트를 먼저 함께 확장합니다.
