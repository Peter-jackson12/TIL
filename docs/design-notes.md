## 목적과 보존 범위

독자는 기록을 다시 찾는 작성자와 학습 과정을 살펴보는 동료입니다.
GitHub README에서 **최근 배움 → 월별 아카이브 → 주제별 탐색**으로 들어갑니다.
표현은 과감하게 바꾸되 원문, 날짜·단계·주제, 코드와 출처는 그대로 보존합니다.
기준 버전은 `65663bc44b4e763b006c19fa2b9761fb9d960859`입니다.
기존 일별 기록 40개와 `tools/legacy_index.tsv`, 작성 템플릿은 수정하지 않습니다.

## 구조 먼저

색을 넣기 전에 세 가지 구성을 흑백으로 비교했습니다.

1. **Library register**: 주제 분류를 먼저 보여주는 카탈로그. 기록 축적은 잘 보이지만 최근 학습이 뒤로 밀립니다.
2. **Editorial journal / 선택**: 큰 표제와 짧은 탐색 줄 뒤에 최근 기록·월별 아카이브를 둡니다. 첫 화면의 개성과 실용적인 탐색을 함께 유지합니다.
3. **Lab notebook**: 세로 여백과 날짜를 따라 내려가는 실험노트. 연속 읽기는 좋지만 README의 전체 탐색에는 길어집니다.

선택한 구조에서 색·글자·간격을 정했습니다. 도구 배지는 접을 수 있는 텍스트 표로 옮겨
최신 기록보다 먼저 눈에 들어오지 않게 했습니다. 도구의 이름과 Python 버전은 유지했습니다.

## 시각 규칙

- 종이 `#f1eee6`, 먹색 `#20211f`, 주홍 `#df3b26`. 주홍은 표지의 책등·별표에만 사용합니다.
- 표지는 `1200 × 340` SVG 한 장입니다. 오래될 수 있는 기록 수나 날짜를 이미지에 넣지 않습니다.
- 표제 역할은 굵은 sans-serif, 본문 역할은 GitHub 기본 글꼴, 실행 명령은 기본 monospace입니다.
- 표지 영문은 60px와 296px의 두 크기, 선은 3px, 강조 선은 13px입니다. 시스템 글꼴 대체를 허용합니다.
- 표지 내부 여백은 왼쪽 56px, 위아래 24px를 기준으로 잡고, 원형 카드·그림자·그라데이션은 사용하지 않습니다.
- 본문은 Markdown 문단과 제목 간격을 따릅니다. 날짜·단계·주제·통계·링크를 SVG로 바꾸지 않습니다.
- 월별 아카이브는 3열, 일별 월 목차는 2열로 줄였습니다. 주제별 색인에는 날짜와 요약을 함께 보여 줍니다.
- 색은 정보를 인코딩하지 않습니다. 섹션 번호, 제목, 날짜, 링크가 탐색의 기준입니다.

## 유지 관리

`docs/index-format.md`는 GitHub에서 직접 편집하는 경우와 선택 도구 양쪽의 기준입니다.
Python은 필수가 아닙니다. 목차 표시 구간의 기존 시작·끝 주석, `learning-log`·`writing-guide`
앵커를 유지하며 `latest`·`archive`를 추가했습니다. 주제별 분류와 기존 숫자 앵커 규칙도 유지합니다.

표지는 정적인 신원 표시이므로 매일 수정할 필요가 없습니다. 일별 기록 작성 후 README·월별·주제별
목차만 같은 변경 묶음으로 갱신합니다. CI는 단위 테스트와 생성 결과 일치를 검사하고 파일을 수정하지 않습니다.

- 실제 GitHub 렌더의 표지·한글 줄바꿈·탐색 링크·접기/펼치기를 넓은 화면과 좁은 화면에서 확인

최종 검증 결과와 커밋별 CI는 작업 완료 보고에 따로 기록합니다. 이 문서의 항목만으로 미실행 검사가 통과했다는 뜻은 아닙니다.
