## 1. 문제 인식 (Problem Recognition)

1. **`append()` 폐기 오해와 퀀트 엔진 구조 분석:**
   * Pandas 2.0에서 `df.append()`가 완전 삭제되었다는 소식을 듣고, 기존 퀀트 백테스팅 레거시 엔진(`legacy_engine.py`)의 `self.trading['pnl'].append(...)` 코드 역시 전부 구식 레거시인 것인지 의구심이 생김.
2. **단일 집계와 다중 집계(`agg`)의 필요성 의문:**
   * 단순히 `.sum()`, `.mean()`을 쓰면 되는데 왜 굳이 `agg()` 메서드와 Named Aggregation 문법을 써야 하는지, `pivot_table`에서 다중 집계 함수를 표현하는 원리가 무엇인지 확인 필요.
3. **`str.split`의 `expand` 파라미터 에러:**
   * `expand=False`를 주고 2개 컬럼에 대입할 때 발생하는 `ValueError: shape mismatch`의 원인과 Pandas 함수들의 기본값(Default) 설계 철학 파악.
4. **SQL `LEFT JOIN`과 `ON` 조건의 필터링 동작 오해:**
   * `LEFT JOIN ... ON Users.user_id = Logs.user_id`에서 매칭되지 않는 데이터가 `WHERE`절처럼 아예 탈락하는 것으로 오해하여 정답 판별에 혼선 발생.
5. **EDA와 이상치(Outlier)의 정의 구분:**
   * 통계 공식(IQR 1.5배)으로 걸러진 수치적 이상치와, 비즈니스 도메인상 불가능한 에러값(예: `Age = -1`)을 어떻게 분리하여 전처리할 것인가에 대한 기준 확립.

### 실험 1: Pandas `df.append()` vs Python `list.append()`의 본질적 차이

```python
import pandas as pd
import numpy as np
import time

# ❌ 나쁜 패턴 (Pandas 2.0에서 삭제됨 & O(N^2) 메모리 복사 발생)
# df = df.append(new_row) 

# ⭕ 퀀트 엔진의 정석 패턴: 메모리에 파이썬 순수 리스트로 O(1) 적재 후 1회 변환
trading_records = {'today': [], 'pnl': [], 'entry_price': []}

start = time.time()
for i in range(10000):
    trading_records['today'].append('2026-08-25')
    trading_records['pnl'].append(np.round(np.random.randn(), 3))
    trading_records['entry_price'].append(50000 + i)

# 백테스팅 루프 종료 후 단 1번 DataFrame으로 일괄 생성
df_trading = pd.DataFrame(trading_records)
print(f"✅ 리스트 적재 후 DF 생성 소요 시간: {time.time() - start:.4f}초 (Shape: {df_trading.shape})")
```

### 실험 2: `agg()` 다중 집계 & `pivot_table` 멀티 인덱스 검증

```python
import pandas as pd

df_orders = pd.read_csv('./ecommerce_orders_online.csv', encoding='utf-8-sig')

# 1. 단일 groupby 3번 호출 대신 Named Aggregation 1회 적용
summary_df = df_orders.groupby('product_category').agg(
    total_revenue=('revenue', 'sum'),
    avg_revenue=('revenue', 'mean'),
    order_count=('order_id', 'count')
).reset_index()

# 2. pivot_table 다중 집계함수(sum, mean) 및 margins 적용
pivot_res = pd.pivot_table(
    df_orders,
    index='region',
    columns='payment_method',
    values='revenue',
    aggfunc=['sum', 'mean'],
    fill_value=0,
    margins=True,
    margins_name='전체합계'
)

print(summary_df.head(3))
print(pivot_res.round(1).head(3))
```

### 실험 3: `str.split(expand=False)` vs `expand=True` 동작 및 예외 검증

```python
df_codes = pd.DataFrame({'product_code': ['FOOD-001', 'BOOK-002', 'TOY-003']})

# 1. expand=False (기본값): 1차원 Series of Lists 반환
s_list = df_codes['product_code'].str.split('-', expand=False)
print("expand=False 타입:", type(s_list), "\n", s_list)

# ❌ df_codes[['cat', 'num']] = s_list  --> ValueError 발생 (차원 불일치)

# 2. expand=True: 2차원 DataFrame으로 펼침
df_expanded = df_codes['product_code'].str.split('-', expand=True)
df_codes[['category', 'number']] = df_expanded
print("expand=True 적용 결과:\n", df_codes)
```

### 실험 4: `rrule`과 `pd.date_range`의 요일 자동 스냅(Anchor Snap) 검증

```python
from datetime import datetime
from dateutil.rrule import rrule, WEEKLY, MO
import pandas as pd

# 시작일을 '목요일(2026-01-01)'로 지정해도 첫 번째 월요일(2026-01-05)부터 자동 생성되는지 검증
dt_start = datetime(2026, 1, 1)

# 1. rrule (byweekday=MO)
rrule_dates = list(rrule(WEEKLY, count=3, byweekday=MO, dtstart=dt_start))

# 2. pd.date_range (freq="W-MON")
pd_dates = pd.date_range(start="2026-01-01", periods=3, freq="W-MON")

print("rrule 결과    :", [d.strftime("%Y-%m-%d (%a)") for d in rrule_dates])
print("pd.date_range :", [d.strftime("%Y-%m-%d (%a)") for d in pd_dates])
# 출력: 둘 다 2026-01-05 (Mon)부터 3주 생성 완료
```

## 3. 트러블슈팅 및 해결 (Troubleshooting & Resolution)

### Issue 1: SQL `LEFT JOIN`에서 `ON` 조건의 역할 오해
* **증상/오해:** `FROM Users LEFT JOIN Logs ON Users.user_id = Logs.user_id` 쿼리에서 로그인 기록이 없는 회원은 결과에서 완전히 누락(`WHERE`절처럼 탈락)된다고 오판함.
* **원인:** `ON` 조건은 탈락시키는 필터가 아니라 **"오른쪽 테이블에서 가져올 기준 키"**일 뿐이며, `LEFT JOIN`의 본질은 **"왼쪽 테이블 100% 보존"**임을 간과함.
* **해결:**
  ```sql
  -- 로그인 이력이 전혀 없는 '민수'도 이름은 출력되고 login_date만 NULL로 채워짐
  SELECT Users.user_name, Logs.login_date
  FROM Users
  LEFT JOIN Logs ON Users.user_id = Logs.user_id;
  ```

---

### Issue 2: `sort_values` 정렬 옵션 및 `reset_index` 인덱스 처리
* **증상:** `sort_values(descending=True)` 작성 시 `TypeError: got an unexpected keyword argument 'descending'` 발생.
* **원인:** Pandas 정렬 메서드는 `descending` 파라미터가 없으며, 오직 `ascending=False`로만 내림차순을 제어함.
* **인덱스 처리 원리:**
  * `reset_index(drop=False)`: 0부터 새 인덱스를 부여하면서, 기존의 뒤죽박죽된 인덱스를 `'index'` 컬럼으로 보존.
  * `reset_index(drop=True)`: 기존 인덱스를 버리고 순수 정수 인덱스로만 재배열.

---

### Issue 3: EDA 단계에서의 '통계적 이상치' vs '도메인 에러' 판별 (`Age`)
* **발견 사실:** `Medical_Appoingtment_No_Shows.csv` 탐색 결과
  * $Q3 + 1.5 \times IQR$ 기준 상한선(110.5세)을 넘는 `Age = 115`는 5건 존재 (통계적 이상치이나 실제 존재하는 참값).
  * 최솟값 `Age = -1`은 1건 존재 (도메인상 불가능한 명백한 시스템 입력 에러).
* **해결 원칙:** 통계적 이상치는 데이터의 맥락을 고려해 보존/로그변환을 고려하되, 도메인 에러(`Age < 0`, `ScheduledDay > AppointmentDay`)는 머신러닝 학습 전 필터링(`df = df[df['Age'] >= 0]`)을 통해 선제거 필수.

## 4. 아키텍처 & 퀀트/금융 엔지니어링 인사이트

### 1. 퀀트 리스크 관리와 비대칭 손실(Downside Ruin)의 수학
* **손실 복구의 비대칭성:** -20% 손실 복구에는 +25%가 필요하지만, -50% 손실 복구에는 +100%가 필요함.
* **종목 성격별 차등 대응 (패닉 셀 금지):**
  * 대형 가치/실적주(기아 등): 실적 펀더멘털과 배당이 살아있다면 반등 및 보유 전략.
  * 소형 모멘텀주(라온텍 등): 수급이 꺼지면 장기 횡보 및 하락 위험이 크므로 엄격한 손절선(-7~10%) 기준 비중 축소 1순위.

### 2. 세제 혜택 계좌 운용 전략 (무소득/취준 기간)
* **연금저축펀드:** 연말정산 세액공제(16.5% 환급)는 근로소득세 납부 실적이 있을 때 유효하므로 취업 후 본격 납입.
* **중개형 ISA:** **소득이 0원이어도 개설 가능**하며, 투자 수익 200만~500만 원 전액 비과세 + 원금 언제든 인출 가능. **지금 개설하여 3년 의무 가입 시계를 가동하는 것이 최적의 전략**.
* **주택청약종합저축 (8년 4개월/100회 유지):** 가입 기간 10점 및 민영주택 1순위 예치금(300만 원) 요건을 완비한 핵심 자산이므로 절대 해지하지 않고 월 2만 원으로 기간/회차 유지.

## 5. 핵심 요약 (Key Takeaways)

| 영역 | 핵심 개념 | 실무 및 개발 원칙 |
| :--- | :--- | :--- |
| **Pandas 결합** | `concat` vs `merge` vs `join` | 위아래 단순 적재는 `concat(ignore_index=True)`, 키 매칭은 `merge(how='left')`, 인덱스 기준은 `join()` |
| **Pandas 집계** | `agg()` Named Aggregation | 단품 `sum()` 다중 호출을 지양하고, `agg(new_col=('col', 'func'))`로 1회 패스 연산 최적화 |
| **Pandas 변환** | `str.split(expand=True)` | 단일 열 리스트 보존은 `expand=False`, 다중 컬럼 분리는 `expand=True` 명시 |
| **날짜 시퀀스** | `rrule` vs `pd.date_range` | 단순 등간격은 `pd.date_range`, 정교한 캘린더 규칙(특정 요일/주차)은 `rrule` 활용 |
| **Git / VCS** | Snapshot & Immutable Hash | 텍스트 Diff가 아닌 스냅샷 기반 저장, 3단계 영역(`add` $\rightarrow$ `commit`), SHA-1 무결성 보장 |
| **EDA 사이클** | 질문 $\rightarrow$ 탐색 $\rightarrow$ 인사이트 $\rightarrow$ 새 질문 | 대기 기간(`waiting_days`) 증가 시 No-show 비율이 4.6%에서 33%로 급증하는 핵심 피처 발굴 |
