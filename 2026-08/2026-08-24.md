### Experiment 1: `iloc` vs `loc` 및 Pandas Boolean Indexing 메커니즘 검증

```python
import pandas as pd
import numpy as np

# 1. 데이터프레임 생성 (결측치는 np.nan 또는 None 활용)
customers = pd.DataFrame({
    "name": ["민수", "지수", "철수", "영희", "준호"],
    "region": ["서울", "부산", "서울", "서울", "대전"],
    "point": [1500, 4200, 3500, 5000, 2800]
})

# [검증 1] iloc(정수 순번) vs loc(라벨 이름표)
# 기본 인덱스 [0, 1, 2, 3, 4]에서는 1번째 위치와 라벨 '1'이 우연히 같아 둘 다 '지수' 반환
assert customers.iloc[1]["name"] == customers.loc[1]["name"] == "지수"

# [검증 2] 필터링 후 인덱스 보존 시 차이점 검증
vip = customers[(customers["region"] == "서울") & (customers["point"] >= 3000)]
# vip의 인덱스는 [2, 3] (철수, 영희)
print("vip.iloc[0] (0번째 행 위치) :", vip.iloc[0]["name"])  # 철수
print("vip.loc[2]  (라벨 '2' 검색) :", vip.loc[2]["name"])   # 철수

try:
    _ = vip.loc[0]  # 라벨 0이 존재하지 않으므로 KeyError 발생
except KeyError:
    print("✅ vip.loc[0] -> 의도된 KeyError 정상 포착 (라벨 기반 검색 증명)")
```

### Experiment 2: 순수 Python OOP 기반 판매 관리 및 상속/오버라이딩 (`CarSale`)

```python
# PEP 515: 금액 가독성을 위한 숫자 언더바 리터럴(70_000_000) 적극 도입
class CarSale:
    def __init__(self, sale_id, manufacturer, model, final_sale_amount, delivery_days, stock_status, is_returned):
        self.sale_id = sale_id
        self.manufacturer = manufacturer
        self.model = model
        self.final_sale_amount = int(final_sale_amount)
        self.delivery_days = int(delivery_days)
        self.stock_status = stock_status
        self.is_returned = is_returned

    def get_amount_category(self):
        if self.final_sale_amount >= 70_000_000:
            return "고가"
        elif self.final_sale_amount >= 40_000_000:
            return "중가"
        return "일반"

    def needs_delivery_check(self):
        return (self.delivery_days >= 20) and (self.stock_status != "출고완료")

    def is_high_value_return(self, min_amount=70_000_000):
        return (self.final_sale_amount >= min_amount) and (self.is_returned == "Y")


class CarSalesManager:
    def __init__(self, sales: list[CarSale]):
        self.sales = sales

    def get_summary(self):
        return {"total_sales": len(self.sales)}


# 부모 클래스 상속 및 get_summary() 오버라이딩
class PremiumCarSalesManager(CarSalesManager):
    def __init__(self, sales: list[CarSale], premium_threshold=70_000_000):
        super().__init__(sales)
        self.premium_threshold = premium_threshold

    def find_premium_sales(self):
        return [s for s in self.sales if s.final_sale_amount >= self.premium_threshold]

    def get_summary(self):
        # super()를 호출하여 부모의 요약 딕셔너리를 가져와 확장
        summary = super().get_summary()
        summary["premium_threshold"] = self.premium_threshold
        summary["premium_count"] = len(self.find_premium_sales())
        return summary
```

### Experiment 3: SQL 서브쿼리 3대 위치별 표준 패턴

```sql
-- 1. WHERE절 서브쿼리 (평균 동적 계산)
SELECT product_id, product_name, list_price 
FROM products 
WHERE list_price > (SELECT AVG(list_price) FROM products);

-- 2. FROM절 인라인 뷰 (임시 가상 테이블 - AS 별칭 필수)
SELECT store_id, total_stock
FROM (
    SELECT store_id, SUM(quantity) AS total_stock
    FROM stocks
    GROUP BY store_id
) AS store_summary
WHERE total_stock >= 500;

-- 3. EXISTS 상관 서브쿼리 (NULL 안전성 확보 및 고속 존재 체크)
SELECT c.customer_id, c.first_name 
FROM customers c
WHERE NOT EXISTS (
    SELECT 1 FROM orders o WHERE o.customer_id = c.customer_id
);
```

## 3. 트러블슈팅 및 해결 (Troubleshooting & Resolution)

### Issue 1: 한글 디렉토리명으로 인한 `uv init` 패키지 네이밍 에러
* **현상:** `C:\Projects\python-basic-assignment-박종원`에서 `uv init` 실행 시 `error: The current directory is not a valid package name` 발생.
* **원인:** Python 공식 패키지 명명 규칙(PEP 508)은 ASCII 영문, 숫자, `-`, `_`만 허용하는데, 폴더명에 한글(`박종원`)이 포함되어 자동 추론 실패.
* **해결:** `--name` 플래그로 영문 패키지명을 명시적으로 지정하여 해결.
  ```powershell
  uv init --name python-basic-assignment
  ```

---

### Issue 2: PowerShell 가상환경 활성화 및 VS Code 커널 미인식
* **현상:** `activate` 명령어 인식 불가 및 노트북에서 `ModuleNotFoundError: No module named 'pandas'` 발생.
* **원인:**
  1. Windows PowerShell에서는 배치 파일이 아닌 스크립트 확장자(`.ps1`)를 붙여야 함.
  2. VS Code Notebook이 가상환경(`.venv`)이 아닌 글로벌 인터프리터를 바라봄.
* **해결:**
  ```powershell
  .\.venv\Scripts\Activate.ps1
  uv pip install pandas numpy ipykernel
  ```
  이후 VS Code 우측 상단 커널을 `.venv (Python 3.14.x)`로 재지정하여 해결.

---

### Issue 3: Pandas 조건문에서 `and` 에러 및 괄호 누락
* **현상:** `df[df['age'] >= 30 and df['gender'] == 'F']` 실행 시 `ValueError: The truth value of a Series is ambiguous` 발생.
* **원인:**
  1. `and`는 스칼라(단일 불리언) 연산자라 다수의 행으로 이루어진 Series의 진릿값을 결정할 수 없음.
  2. `&` 연산자는 비교 연산자(`>=`, `==`)보다 우선순위가 높아 괄호가 없으면 `30 & df['gender']`를 먼저 계산함.
* **해결:** 반드시 **원소별(Element-wise) 연산자 `&`**를 쓰고 각 조건을 **소괄호 `()`**로 감싸서 해결.
  ```python
  df[(df['age'] >= 30) & (df['gender'] == 'F')]
  ```

### Issue 4: CSV 인코딩 호환성 (`utf-8` vs `utf-8-sig`)
* **현상:** 파이썬에서 `to_csv()`로 저장하고 다시 `read_csv()`할 때는 안 깨지는데, 윈도우 엑셀로 열면 한글이 `ë…¸íŠ¸ë¶`로 깨지는 현상.
* **원인:** 파이썬은 기본 `utf-8` 규격으로 상호 통신하지만, 윈도우 엑셀은 BOM(Byte Order Mark)이 없는 UTF-8 파일을 레거시 ANSI/CP949로 오인함.
* **해결:** 파일 저장 및 로드 시 **`encoding='utf-8-sig'`**를 표준 규칙으로 적용.

## 4. 핵심 요약 (Key Takeaways)

1. **`iloc` vs `loc`의 본질:**
   - `iloc`은 컴퓨터 기준 0-based **정수 위치(Integer Position)**.
   - `loc`은 사람이 부여한 **라벨/인덱스 이름(Label)**. 인덱스가 리셋되지 않은 필터링 데이터셋 조회 시 `KeyError`를 주의할 것.
2. **PEP 515 숫자 리터럴(`_`):**
   - `70_000_000`과 `70000000`은 파이썬 내부에서 동일한 `int` 자료형. 퀀트/금융 데이터 분석 시 0 개수 누락 버그를 방지하는 실무 표준.
3. **SQL 서브쿼리 선택 기준:**
   - 두 테이블의 컬럼을 모두 출력해야 하면 ➔ **`JOIN`**
   - 다른 테이블의 데이터를 단순히 필터링/존재 여부 체크로만 쓴다면 ➔ **`WHERE / EXISTS 서브쿼리`** (특히 `NOT IN` 대신 `NOT EXISTS`가 `NULL`로부터 안전함)
4. **EDA 및 데이터 탐색 함수:**
   - `shape` (크기 튜플) ➔ `info()` (타입, 결측치, 메모리) ➔ `describe()` (기초 통계) ➔ `nunique()` (고유값 개수) ➔ `value_counts()` (빈도표)
