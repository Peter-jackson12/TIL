## 2. 직접 코드 실험 및 수학적 검증 (Direct Code Experiment)

### ① 이항분포 분산 공식 $\text{Var}(X) = np(1-p)$ 완전 수리 증명

기본 정의식에 기댓값의 선형성을 적용하여 중간항 $-2\mu X$가 어떻게 정리되는지 검증했다.

$$\begin{aligned}
\text{Var}(X) &= E\left[(X - \mu)^2\right] = E\left[X^2 - 2\mu X + \mu^2\right] \\
&= E[X^2] - 2\mu \underbrace{E[X]}_{=\mu} + \mu^2 \\
&= E[X^2] - 2\mu^2 + \mu^2 = \mathbf{E[X^2] - (E[X])^2}
\end{aligned}$$

- **단 1회 시행(베르누이, $Y \in \{0, 1\}$):**
  - $E[Y] = (1 \times p) + (0 \times (1-p)) = p$
  - $E[Y^2] = (1^2 \times p) + (0^2 \times (1-p)) = p$
  - $\text{Var}(Y) = E[Y^2] - (E[Y])^2 = p - p^2 = \mathbf{p(1-p)}$
- **$n$회 독립 시행의 합($X = \sum_{i=1}^n Y_i$):**
  - 독립 변수의 분산 덧셈성에 의해 $\text{Var}(X) = \sum_{i=1}^n \text{Var}(Y_i) = \mathbf{np(1-p)}$ 증명 완료.

### ② IEEE 754 부동소수점 오차 검증: $1 - \text{CDF}$ vs $\text{SF}$

동전 1,000회 투입 중 800회 이상 앞면이 나올 확률(극단값 리스크)을 직접 연산하여 부동소수점 자리취소 현상을 증명했다.

```python
from scipy.stats import binom

n, p, k = 1000, 0.5, 800

# 1. 1 - CDF 방식 (유효숫자 상실)
prob_cdf = 1 - binom.cdf(k, n, p)

# 2. 전용 생존함수 SF 방식 (Right-tail 정밀 계산)
prob_sf = binom.sf(k, n, p)

print(f"1 - CDF 결과 : {prob_cdf}")       # 출력: 0.0 (오류로 완전 증발!)
print(f"SF() 결과    : {prob_sf}")          # 출력: 2.0494431351478518e-86 (정밀 보존!)
```

### ③ Python `set` 해시 무작위화 및 DFS 결정론적 순서 분리

`set`의 비결정론적 특성을 배제하고 방문 순서를 보장하기 위해 중복 체크 집합과 순서 기록 리스트를 분리하는 정석 패턴을 확립했다.

```python
graph = {
    "A": ["B", "C"],
    "B": ["A", "D"],
    "C": ["A"],
    "D": ["B"]
}

stack = ["A"]
visited = set()     # O(1) 중복 탐색 방지용
visit_order = []    # 결정론적 순서 기록용

while stack:
    current = stack.pop()
    if current not in visited:
        visited.add(current)
        visit_order.append(current)
        for next_node in graph.get(current, []):
            stack.append(next_node)

print("실제 DFS 탐색 순서:", visit_order)  # ['A', 'C', 'B', 'D'] 순서 엄격 보장
```

### ④ PostgreSQL 관계형 정규화 및 서브쿼리 실적 분석 SQL

`sales`, `products`, `customers`, `sales_departments` 간 조인 및 서브쿼리를 통한 2025년 2분기 실적 분석 파이프라인을 구축했다.

```sql
-- 2025년 2분기 전체 평균 판매금액을 초과하는 우수 거래 조회 (서브쿼리 + JOIN)
SET search_path TO ch1, 제약회사_제품판매_데이터;

SELECT 
    s.sale_id,
    s.sale_date,
    p.product_name,
    c.customer_name,
    c.customer_type,
    c.customer_region,
    s.sales_type,
    s.quantity,
    s.sale_amount,
    s.payment_status
FROM sales s
INNER JOIN products p ON s.product_id = p.product_id
INNER JOIN customers c ON s.customer_id = c.customer_id
WHERE s.sale_date >= '2025-04-01' 
  AND s.sale_date < '2025-07-01'
  AND s.sales_type != '반품'
  AND s.sale_amount > (
      SELECT AVG(sale_amount)
      FROM sales
      WHERE sale_date >= '2025-04-01' 
        AND sale_date < '2025-07-01'
        AND sales_type != '반품'
  )
ORDER BY s.sale_amount DESC, s.sale_date DESC;
```

## 3. 트러블슈팅 및 해결 (Troubleshooting & Resolution)

### Issue 1: `uv add` 실행 시 `error: No pyproject.toml found`
- **원인:** `uv add`는 프로젝트 명세 파일(`pyproject.toml`)에 의존성을 기록하는 명령인데, 단순 `uv venv`만 실행된 빈 디렉토리여서 명세서가 부재했음.
- **해결:** `uv init`을 최초 실행하여 `pyproject.toml`을 생성한 후 `uv add`를 실행하거나, 임시 가상환경인 경우 `uv pip install`을 활용함.

### Issue 2: `uv add sklearn` 패키지 빌드 실패
- **원인:** PyPI에서 `sklearn` 더미 패키지가 공식 폐기(deprecated)되어 직접 빌드가 차단됨.
- **해결:** 공식 배포 명칭인 `uv add scikit-learn`으로 패키지를 교체 설치함.

### Issue 3: DBeaver `SQL Error [42P01]: "public.제약회사_제품판매_데이터" 릴레이션이 없습니다`
- **원인:** 원본 CSV 테이블이 `ch1` 스키마에 적재되어 있었으나, 쿼리에서 `public."제약회사_제품판매_데이터"`로 절대 스키마 경로가 고정되어 불일치 발생.
- **해결:** SQL 스크립트 상단에 `SET search_path TO ch1, 제약회사_제품판매_데이터;`를 지정하고 쿼리의 `public.` 접두사를 전면 제거/치환하여 정상 실행 완료.

### Issue 4: SQL 파일 내 Python 삼중 따옴표(`'''`) 주석 Syntax Error
- **원인:** 파이썬 문자열 문법인 `'''`를 SQL 파일에 그대로 기입하여 파서가 구문 에러를 일으킴.
- **해결:** ANSI SQL 표준 주석인 `--` (단일행) 및 `/* */` (다중행)으로 전면 수정.

### Issue 5: 세부 폴더 재배치 시 Git 서브모듈(회색 폴더) 잠김 현상
- **원인:** 상위 묶음 폴더(`01_Lecture_Study`)로 과제를 병합할 때, 하위 과제 폴더 내부에 예전 `.git` 디렉토리가 남아있어 깃허브가 이를 독립 서브모듈로 인식하여 웹상에서 폴더가 열리지 않음.
- **해결:** 하위 폴더의 `.git`을 재귀 삭제(`Remove-Item -Recurse -Force .\subfolder\.git`)한 후, 상위 폴더 루트에서만 단일 `git init` 및 `.gitignore`를 적용하여 깔끔한 모노레포로 푸시 완료.

### Issue 6: Matplotlib 차트 한글 폰트 깨짐(`□□`)
- **원인:** 윈도우 환경 기본 Matplotlib Sans-serif 폰트가 한글 유니코드를 지원하지 않고 마이너스 부호를 깨뜨림.

## 4. 퀀트 & 통계학적 인사이트 (Key Takeaways)

### 💡 1. 꼬리 위험(Tail Risk / Black Swan) 연산과 생존함수(`sf`)의 당위성
- 금융 시장의 급락, 파산 위험, VaR(Value at Risk) 등 $10^{-5}$ 이하의 극단적 희박 확률을 모델링할 때, 일반적인 $1 - \text{CDF}$ 연산은 컴퓨터의 64비트 실수 연산 한계로 인해 위험 확률을 `0.0`으로 뭉개버린다.
- **퀀트 시스템 구축 시 꼬리 확률 추정에는 반드시 대수적 정밀 적분을 지원하는 생존함수(`sf` / `log-sf`)를 사용해야만 치명적인 리스크 과소평가를 방지할 수 있다.**

### 💡 2. 자유도(Degrees of Freedom) 상실과 베셀 보정(Bessel's Correction)의 본질
- 모집단 평균 $\mu$를 모르는 상태에서 표본평균 $\bar{x}$를 기준점으로 잡으면, 표본 데이터들은 본래 모평균보다 자기들끼리의 중심인 $\bar{x}$에 더 가깝게 모이게 된다.
- 이로 인해 발생하는 **편차 제곱합의 계통적 과소평가(Underestimation Bias)를 보상하기 위해 분모를 $n$이 아닌 $n-1$로 나누어 분산을 키워주는 것**이 베셀 보정의 수학적 본질이다.

### 💡 3. 조건부 확률 vs 베이즈 정리 ($P(A|B)$의 이중적 접근법)
- **기본 조건부 확률 ($P(A|B) = \frac{P(A \cap B)}{P(B)}$):** 교차표나 원천 데이터 로그에서 사건 $A$와 $B$가 동시에 일어난 교집합 빈도를 직접 셀 수 있을 때 사용.
- **베이즈 정리 ($P(A|B) = \frac{P(B|A)P(A)}{P(B)}$):** 교집합을 직접 모르고 원인과 결과가 뒤집힌 우도($P(B|A)$)와 사전 확률($P(A)$)만 주어졌을 때, **새로운 증거 $B$를 반영하여 원인 $A$의 사후 확률을 갱신**하는 통계적 추론 도구.

### 💡 4. 단일 선형회귀의 결정계수($R^2$)와 다변량 확장 필요성
- 실제 고객 487건 데이터 실증 결과, 월간 방문횟수($X$)와 구매금액($y$)의 상관계수는 $r \approx 0.5755$, 단순 선형회귀 모델의 설명력은 $R^2 \approx 0.3312$로 나타났다.
- 즉, 방문횟수만으로는 전체 구매금액 변동의 약 33%만 설명 가능하며, 나머지 67%의 잔차를 설명하기 위해서는 `MembershipGrade`(VIP 가중치), `CouponUsed`(할인 민감도), `PurchaseQty` 등의 다중 변수를 결합한 다중회귀(Multiple Regression)로 파이프라인을 고도화해야 한다.
