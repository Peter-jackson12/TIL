## 1. 강의 자료 요약 — 1장 1강: 벡터와 행렬의 기본 개념

학습 목표: 스칼라·벡터·행렬 구분, 데이터와 모델 파라미터의 벡터·행렬 표현, 차원과 Shape, L1/L2 Norm, 머신러닝 활용.

- 스칼라는 숫자 하나, 벡터는 숫자를 순서대로 나열한 것(하나의 데이터의 여러 특성), 행렬은 행·열로 배열한 것(여러 데이터). 행렬 원소 Xᵢⱼ는 수학 표기상 1부터 센다.
- 머신러닝 표현: 특성 벡터(데이터 1건), 입력 행렬 X(`(n, d)`: 데이터 수 × 특성 수), 타깃 벡터 y, 가중치 w(벡터)·W(행렬), 편향 b(스칼라 또는 벡터). 예시 `score = w₁x₁ + w₂x₂ + b`에서 고객 A는 17이며, 이는 확률이 아니라 가중합 점수다(확률 변환은 이후 Sigmoid에서 다룬다고 안내됨).
- 차원과 Shape: 벡터의 차원은 원소 개수, NumPy의 `ndim`은 축 개수라 구분해야 한다. `(2,)`(1차원), `(1,2)`(행 벡터 형태), `(2,1)`(열 벡터 형태)는 서로 다르며 `reshape`는 원소 수를 유지한다. 입력 특성 수와 가중치 수(Shape)가 맞아야 연산할 수 있다.
- 노름(Norm): L1은 절댓값의 합, L2는 제곱합의 제곱근. `[3,4]`에서 L1 = 7, L2 = 5이고 `np.linalg.norm(x, ord=...)`로 계산한다. 두 벡터의 차이에 적용하면 맨해튼 거리(L1), 유클리드 거리(L2)가 된다. L2 Norm으로 나누면 방향은 유지하고 길이가 1인 단위 벡터(0벡터는 불가)가 된다.
- 구분할 개념: 벡터 정규화(길이 조정) / 규제(Regularization, 가중치에 제약을 줘서 과적합 완화: L1은 희소한 해, L2는 가중치 억제) / 특성 스케일링·표준화(특성별 범위·분포 조정).
- 코딩테스트 연습: DFS(스택, `visited`)와 "센서 이상 영역 중 가장 큰 영역 크기" 문제(상하좌우 연결, 대각선 불가). 풀이 제출 여부는 미확인.
- 연습문제 1~4는 문제만 확인했고, 접힌 "예시 답안"은 확인하지 못했다.

## 3. AI 설명 (직접 실행한 결과 아님, 강의 자료에 없는 보충)

### 노름의 조건과 L∞

- 노름은 "벡터 크기를 숫자로 나타낸 것"이라는 설명을 넘어, 세 조건을 만족하는 함수다: 0 이상이며 0벡터일 때만 0, 상수배 `‖cx‖ = |c|‖x‖`, 삼각부등식 `‖x+y‖ ≤ ‖x‖ + ‖y‖`.
- L2도 삼각부등식이 성립한다. `x=[3,0], y=[0,4]`이면 `‖x+y‖₂ = 5 ≤ 3 + 4 = 7`이고, 두 벡터가 같은 방향이면 등호가 된다. 증명은 코시-슈바르츠 부등식을 쓰며 이후 내적에서 다룰 가능성이 있다.
- Lp Norm `‖x‖ₚ = (Σ|xᵢ|ᵖ)^(1/p)`에서 p를 무한대로 보낸 극한이 L∞ Norm이며 `max(|x₁|, …, |xₙ|)`이다. `[3,-4]`에서 L1 = 7, L2 = 5, L∞ = 4. NumPy는 `np.linalg.norm(x, ord=np.inf)`. 이번 강의 범위에는 없다.

### 노름과 거리, 원방정식

- 맨해튼 거리는 차이 벡터의 L1 Norm, 유클리드 거리는 차이 벡터의 L2 Norm이다(노름은 벡터 하나의 크기, 거리는 두 점의 차이 벡터의 크기). L∞에서 나오는 거리는 체비쇼프 거리다.
- 유클리드 거리는 고등학교의 두 점 사이 거리 공식 `√((x₂−x₁)² + (y₂−y₁)²)`와 같다. 원방정식 `x² + y² = r²`은 "원점에서 L2 거리가 r인 점들의 모임"이다.
- 원점에서 노름이 1인 점들의 모양: L2는 원, L1은 마름모(`|x|+|y|=1`), L∞는 정사각형(`max(|x|,|y|)=1`).

### 라쏘·릿지와의 연결

- 라쏘는 손실 + λ‖w‖₁(L1 규제), 릿지는 손실 + λ‖w‖₂²(L2 규제)다. 릿지는 보통 L2 Norm의 제곱을 쓰는데, 제곱근이 없어 미분이 단순하기 때문이다.
- 규제를 "가중치를 이 영역 안에서만 고른다"는 제약으로 보면 라쏘의 영역은 마름모, 릿지의 영역은 원이다. 손실 등고선이 제약 영역에 처음 닿는 점이 해다.
- 그림(가중치 평면 w₁–w₂, 대화 중 SVG로 그림, 여기에는 글로 기록):
  - 라쏘: 마름모 꼭짓점이 축 위에 있어 등고선이 꼭짓점에 먼저 닿기 쉽고, 그때 한 가중치가 정확히 0이 된다(희소한 해).
  - 릿지: 원에는 모서리가 없어 닿는 점이 축 위가 아니며, 가중치가 모두 작아지지만 0이 되지는 않는다.
  - 라쏘에서도 최소점의 위치에 따라 꼭짓점이 아닌 변에 닿을 수 있고, 그 경우 두 가중치 모두 0이 아니다. 따라서 정확한 표현은 "라쏘는 항상 0을 만든다"가 아니라 "0이 되기 쉽다"이다. 그림에서 등고선을 원으로 단순화했고(실제로는 보통 타원) 최소점 위치도 설명용으로 골랐다.

### 제약 영역이 손실 최소점에 닿으면(포함하면) 안 되는 이유

- 손실 최소점(제약 없을 때의 최적 가중치)이 제약 영역 안에 있거나 경계에 있으면, 제약을 걸어도 그 점을 그대로 고를 수 있어서 해가 최소점과 같아진다. 즉 규제가 아무 효과를 내지 못한다.
- 규제는 일부러 가중치를 훈련 데이터에 가장 잘 맞는 최소점에서 끌어당겨(작게 만들어) 과적합을 완화하려는 장치다. 그래서 의미 있는 규제는 최소점이 영역 밖에 있어 제약이 실제로 작동할 때다.
- 영역의 크기는 규제 강도와 반대로 움직인다(영역이 작을수록 규제가 강하고, λ가 클수록 영역이 작아진다). 영역이 충분히 커져서 최소점을 포함하면 규제를 안 건 것과 같은 해가 된다.
- 제약식 형태의 설명과 λ를 쓰는 페널티 형태의 대응 관계는 자세히 확인하지 않았고, 이후 수업에서 다시 확인이 필요하다.

### 수학적으로 곱씹을 만한 점 (AI 정리)

- 노름이 조건을 만족하는 함수라는 점, L1·L2의 모양 차이와 규제의 관계, L2 Norm이 피타고라스 정리의 일반화라는 점, 정규화가 크기를 버리고 방향만 남긴다는 점(`[3,4]`와 `[6,8]`은 정규화하면 같아짐), 수학의 차원과 NumPy `ndim`의 차이, 1부터 세는 수학 인덱스와 0부터 세는 NumPy 인덱스.

### 숫자 예시: 최소점이 영역 안이면 규제 효과가 없다 (AI가 만든 설명용 예시, 실행 결과 아님)

- 손실 `L = (w₁−3)² + (w₂−2)²`로 가정하면 최소점은 (3, 2), 손실 0. 라쏘 제약은 `|w₁|+|w₂| ≤ t`.
- t = 10: 최소점의 `|3|+|2| = 5 ≤ 10`이라 영역 안. 해는 (3, 2), 손실 0으로 규제 효과 없음.
- t = 5: 최소점이 경계 위. 마찬가지로 해는 (3, 2), 규제 효과 없음.
- t = 3: `5 > 3`이라 영역 밖. 해는 (2, 1)(손으로 확인, 코드 미실행), 손실 2. 훈련 손실은 올라가지만 가중치 크기 합은 5에서 3으로 줄어든다.
- 예산이 충분하면 모델이 원하는 값을 그대로 고르고, 예산이 모자라야 "가중치를 줄여라"는 압력이 실제로 생긴다.

### 실제 상황 예시: 집값 예측 (설명용 가정, 실제 데이터·실험 아님)

- 집 30채, 의미 있는 특성 5개와 무관한 특성 15개(총 20개)로 집값을 예측한다고 가정.
- 규제가 없으면 훈련 데이터의 우연한 잡음까지 맞추려고 무관한 특성에도 큰 가중치가 붙어 과적합이 된다(훈련은 잘 맞고 새 집은 크게 틀림).
- 규제를 걸면 예산이 모자라 손실을 크게 줄이는 특성에만 가중치를 쓰게 되고, 라쏘는 무관한 특성의 가중치를 0으로 만들 수 있다. 훈련 손실은 올라가지만 새 데이터에는 더 안정적일 가능성이 크다.
- t가 너무 작으면 중요한 특성의 가중치까지 깎여 과소적합이 된다.

### 예산 t(λ)는 누가 어떻게 정하나

- 가중치 w는 모델이 훈련으로 학습하는 파라미터이고, 예산 t(또는 λ)는 사람이 정해 넣는 하이퍼파라미터다.
- 훈련 손실만 보고 t를 고르면 영역이 가장 큰 쪽(규제 없음)이 항상 이기므로, 훈련에 쓰지 않은 검증 데이터 성능으로 고른다. 후보 여러 개를 훈련 → 검증 성능 비교 → 가장 좋은 값을 선택. scikit-learn에는 `LassoCV`, `RidgeCV`가 있다.
- 제약식의 t와 페널티 형태의 λ(sklearn은 `alpha`)는 반대로 움직인다(λ가 크면 영역이 작아짐). 정확한 대응 관계는 확인하지 않음.

### 교차검증 종류 (AI 정리, 강의 자료 외)

- K-Fold: 데이터를 K조각으로 나눠 한 조각씩 검증, 나머지로 학습, 점수를 평균. K = 5, 10이 흔함. 한 번만 나눌 때 분할 방식에 점수가 휘둘리는 문제를 줄임.
- Stratified K-Fold: 각 조각의 클래스 비율을 전체와 비슷하게 유지. 분류에서 클래스 불균형일 때 중요하며 회귀에는 기본적으로 쓰지 않는다. scikit-learn 분류기에서 `cv=5`를 주면 기본으로 Stratified가 적용된다고 알고 있으나 직접 확인하지 않았다.
- 그 밖: Leave-One-Out(데이터가 매우 적을 때, 계산량 큼), Group K-Fold(같은 집단 데이터가 훈련·검증에 섞이면 안 될 때), TimeSeriesSplit(과거로 학습하고 미래로 검증, 섞으면 누수 위험).

### 예산과 맨해튼·유클리드 거리의 관계

- 예산 t는 "가중치 벡터의 크기에 허용하는 상한"이라는 숫자이고, 크기를 재는 방식이 L1이면 맨해튼, L2이면 유클리드다. 즉 제약 영역은 "원점에서 w까지의 거리가 t 이하인 점들"이다.
- L1이면 원점에서의 맨해튼 거리 ≤ t라서 마름모(라쏘), L2이면 원점에서의 유클리드 거리 ≤ t라서 원(릿지)이다. t는 마름모·원의 크기(반지름)를 정한다. 릿지는 제곱을 쓰기도 하지만 영역의 모양은 같은 원이다.
- 수업에서 다룬 "두 데이터 사이의 거리"(차이 벡터의 노름)와 달리, 여기서는 원점과 가중치 벡터 사이의 거리를 쓴다.

## 4. 강의 자료 요약 — 1장 2강: 벡터 내적과 행렬 곱

학습 목표: 내적의 계산·의미, 내적으로 가중합과 벡터 관계 설명, 행렬곱 계산, 행렬곱 가능 조건과 결과 Shape 판단, 머신러닝 예측 연산에서의 활용.

- 벡터 내적: 대응하는 원소끼리 곱해 모두 더한 값(결과는 스칼라). `a=[2,3], b=[4,5]`이면 `2×4 + 3×5 = 23`. 두 벡터의 원소 개수가 같아야 하며 `np.dot(a, b)` 또는 1차원 배열의 `a @ b`로 계산한다. 원소 수가 다르면 오류.
- 기하학적 의미: `a · b = ‖a‖₂ ‖b‖₂ cos θ`(1강에서 배운 L2 Norm 사용). 내적이 양수면 사이각 < 90°, 0이면 수직, 음수면 > 90°(0벡터가 아닐 때). 내적 값은 크기에도 영향을 받으므로 내적이 크다고 방향이 더 비슷한 것은 아니다.
- 코사인 유사도: `(a·b) / (‖a‖₂‖b‖₂)`로 크기의 영향을 제거하고 방향만 비교한다(−1~1, 0벡터는 계산 불가). `[3,4]`와 `[6,8]`은 내적 50, 노름 5와 10이라 유사도 1. 임베딩 유사도 비교에 쓴다. 1강에서 L2 정규화가 크기를 버리고 방향만 남긴다고 한 내용과 이어진다.
- 가중합 활용: 고객 입력 벡터 `x=[3,2]`와 가중치 `w=[2,4]`의 내적이 점수 14. 고객 A, B는 입력이 달라도 점수가 같고(14), C는 20. 이 점수는 확률이 아니며 실제로는 편향·활성화 함수가 추가된다고 안내됨.
- 행렬곱: 첫 행렬의 행과 두 번째 행렬의 열을 내적해 결과 행렬의 각 원소를 만든다. `Cᵢⱼ = Σₖ AᵢₖBₖⱼ`. 예시 `[[1,2],[3,4]] @ [[5,6],[7,8]] = [[19,22],[43,50]]`. `@` 또는 `np.matmul`. `*`는 원소별 곱셈이라 다른 연산이다(결과 `[[5,12],[21,32]]`).
- 차원 조건: `(m,n) @ (n,p) → (m,p)`. 가운데 n이 같아야 하고 바깥 m, p가 결과 Shape를 정한다. 예 `(5,3)@(3,2)→(5,2)`, `(3,2)@(4,2)`는 불가. 실제 계산 없이 Shape만으로 판단할 수 있다.
- 행렬과 벡터의 곱: `X(3,2) @ w(2,)`는 `(3,)`, `X @ w_col(2,1)`은 `(3,1)`로 값은 같고 구조만 다르다(1차원 배열과 2차원 배열을 구분).
- 순서: 일반적으로 `A @ B ≠ B @ A`이고, `(3,2)@(2,4)`는 가능하지만 반대 순서 `(2,4)@(3,2)`는 불가능. 예시 `A=[[1,2],[0,1]]`, `B=[[1,0],[3,1]]`에서 `A@B=[[7,2],[3,1]]`, `B@A=[[1,2],[3,7]]`.
- 머신러닝 Shape 규칙: `X(n_samples, n_features) @ W(n_features, n_outputs) → Y(n_samples, n_outputs)`. 예 `X(4,3) @ W(3,2) → (4,2)`. Shape가 안 맞으면 `ValueError`가 나며, 오류가 나면 각 Shape → 첫 행렬 열 수와 두 번째 행렬 행 수 → 입력과 가중치의 순서를 확인하라고 안내됨. 1강에서 본 가중치 행렬 `W`(열 하나가 출력 하나)가 여기서 행렬곱으로 이어진다.
- 연습문제 1~3은 문제만 확인했고 접힌 "예시 답안"은 확인하지 못했다. 실습 파일 내용도 확인하지 못했다.
- 확인 메모: 강의 자료의 숫자 예시(2×2 곱, `X@W` 3×2, 4×3 예시, `A@B`·`B@A`)는 손계산으로 맞음을 확인했고 코드는 실행하지 않았다. 페이지에는 수업 중 추가된 것으로 보이는 필기가 섞여 있다(시력 예시 `1.5 x 3 + 1.0- x 2.5`의 오타로 보이는 표기, 내적 코드 블록 안의 `result = a * 3`).

### 내적 vs 행렬곱 vs 외적 (AI 설명, 강의 자료 외, 손계산 확인·코드 미실행)

- `A @ B ≠ B @ A`는 내적이 아니라 행렬곱에 대한 말이다. 벡터 내적은 `a·b = b·a`로 순서를 바꿔도 같다(예: `[2,3]·[4,5] = 23 = [4,5]·[2,3]`).
- 행렬곱의 각 칸은 "첫 행렬의 행"과 "두 번째 행렬의 열"의 내적이다. 순서를 바꾸면 어떤 행과 어떤 열이 짝지어지는지가 달라진다. 강의의 `A=[[1,2],[0,1]]`, `B=[[1,0],[3,1]]`에서 왼쪽 위 칸은 `A@B`가 `[1,2]·[1,3] = 7`, `B@A`가 `[1,0]·[1,0] = 1`이다.
- 행렬곱은 외적이 아니다. 행렬곱은 (행 · 열)의 내적을 칸마다 모은 연산이다.
- 외적(outer product): 열벡터와 행벡터를 곱해 행렬을 만드는 연산으로 `(m,1) @ (1,n) → (m,n)`이다. 예 `a=[1,2]`, `b=[3,4,5]`이면 `[[3,4,5],[6,8,10]]`(Shape `(2,3)`). NumPy는 `np.outer(a, b)`.
- 두 관점은 연결된다: `A @ B`는 "A의 k번째 열 ⊗ B의 k번째 행"(외적)을 k에 대해 모두 더한 것과 같다. 위 예시에서 `[[1,0],[0,0]] + [[6,2],[3,1]] = [[7,2],[3,1]]`로 `A@B`와 일치한다.
- 외적(outer product)과 3차원 벡터의 벡터곱(cross product, `×`)은 한국어로 모두 "외적"이라 불려 혼동하기 쉽다. 이번 강의 범위에는 둘 다 없다.

### `@` 연산자와 수학 기호 (AI 설명, 강의 자료의 NumPy 예시 외 보충, 직접 실행하지 않음)

- NumPy의 `@`는 "행렬곱 연산자"(`np.matmul`)이고, 피연산자의 차원에 따라 동작이 달라진다. 1차원 두 배열이면 내적(스칼라), 2차원 두 배열이면 행렬곱, `(3,2) @ (2,)`처럼 2차원과 1차원이면 행렬과 벡터의 곱(결과 `(3,)`)이다. 즉 내적과 행렬곱은 같은 규칙(안쪽 차원을 맞춰 곱해서 더함)의 특수한 경우라 기호가 같다.
- 수학 표기는 다르다. 내적은 `a · b`(또는 `aᵀb`), 행렬곱은 `AB`(또는 `A × B`)로 쓰고, 둘 다 NumPy에서는 `@`로 옮긴다. 강의는 내적에 `np.dot(a, b)`와 `a @ b`를, 행렬곱에 `A @ B`와 `np.matmul(A, B)`를 쓴다.
- 구분할 연산: `*`는 원소별 곱셈이라 다른 연산이다. `np.dot`과 `@`는 1·2차원에서는 같은 결과로 알고 있으며 3차원 이상 배열에서는 동작이 달라진다(이 부분은 직접 확인하지 않음).

### Shape와 값의 구분: `(3,2) @ (2,4)` (AI 설명, 손계산 확인·코드 미실행)

- `(3,2)`, `(2,4)`는 값이 아니라 행렬의 Shape(행 수, 열 수)다. 결과의 Shape `(3,4)`도 숫자 두 개가 나오는 것이 아니라 3행 4열 행렬(원소 12개)이 나온다는 뜻이다.
- 예시: `A = [[1,2],[3,4],[5,6]]`(Shape `(3,2)`), `B = [[1,0,2,1],[0,1,1,2]]`(Shape `(2,4)`)이면 `A @ B = [[1,2,4,5],[3,4,10,11],[5,6,16,17]]`(Shape `(3,4)`). 예: 3행 3열은 `[5,6]·[2,1] = 16`.
- `(10,30)`이 값이면 `[10,30]`이라는 숫자 두 개(벡터)이고, Shape라면 10행 30열 행렬을 뜻한다. 표기는 같아도 "Shape"인지 "값"인지 구분해야 한다.

### 같은 `@`인데 결과 종류가 다른 이유 (AI 설명, 손계산 확인·코드 미실행)

- 내적은 벡터 두 개 사이의 연산이다. A(3,2), B(2,4)처럼 행렬에는 "내적을 구하라"가 성립하지 않고, `A @ B`는 항상 행렬곱이라 Shape `(3,4)` 행렬이 나온다.
- `@`의 결과 종류는 단어가 아니라 입력으로 정해진다: 벡터 @ 벡터 → 스칼라, 행렬 @ 행렬 → 행렬.
- 행렬곱 안의 내적: A의 1행 `[1,2]`와 B의 1열 `[1,0]`의 내적 `1×1 + 2×0 = 1`이 결과의 1행 1열 칸이다. 결과 12개 칸이 각각 내적 한 번이다.
- `np.dot(A, B)`에 2차원 행렬 둘을 넣어도 스칼라가 아니라 행렬곱 결과가 나온다(1·2차원에서 `@`와 같다고 알고 있으나 직접 확인하지 않음).
- 같은 Shape의 행렬 둘을 원소별로 곱해 모두 더하는 행렬의 내적(프로베니우스 내적, `np.sum(A * B)`)은 이번 강의 범위 밖이며 A(3,2), B(2,4)처럼 Shape가 다르면 쓸 수 없다.

### 1차원 배열 `(2,)`와 1행 2열 `(1, 2)` (AI 설명, 1강 실습 문제 1-1 Q4 관련)

- 사용자 질문: `x_a = np.array([5, 2])`도 1행 2열이 아니라 원소 2개인 1차원 배열로 치는가?
- 그렇다. 대괄호 한 겹의 `np.array([5, 2])`는 축이 하나뿐인 1차원 배열(`ndim = 1`, `shape = (2,)`)이고, 대괄호 두 겹의 `np.array([[5, 2]])`가 1행 2열(`shape = (1, 2)`), `np.array([[5], [2]])`가 2행 1열(`shape = (2, 1)`)이다. 행과 열이라는 두 축이 있어야 "1행 2열"이라 부를 수 있고, 1차원 배열에는 가로·세로 구분이 없다.
- 방향을 분명히 해야 하면 `x_a.reshape(1, 2)`(행 벡터 형태), `x_a.reshape(2, 1)`(열 벡터 형태)로 2차원 배열로 바꾼다. 이 설명을 1강 실습 노트북 Q4 답변에도 덧붙였다.
