## 1. 이번 주 결정

- **실주문 실험 설계가 독립 리뷰에서 승인으로 수렴했다.** 사용자 결정 26개를 표 하나로 묶어 하루 아침에 정했다.
- **모의투자는 1주가 아니라 비드당 약 100만 원으로 한다.** 1주 가격이 100만 원을 넘는 종목만 1주로 한다. 실전 1주·소액 단계는 실전을 시작할 때 다시 정한다.
- **금액 기준 주문과 시장가 매수의 충돌은 모의에서만 예외로 풀었다.** "100만 원 ÷ 최우선 매도호가, 최소 1주" 시장가를 허용하고, 실전 2단계부터는 지정가 IOC만 쓴다. 모의 계좌는 상시 모의투자 계좌를 쓰고 동시 보유는 7종목까지로 정했다.
- **실주문 전 탐침을 3단계로 나눴다.** 주문 없는 API 확인 → 모의 1주 주문(이틀) → 장중 시계 기록 순서다. 각 단계는 독립 리뷰 → 고정 실행 사본(detached worktree) → 해시가 붙은 사용자 카드 → 운영 타워의 "GO" 한 줄 뒤 사용자가 직접 실행하는 절차를 밟는다.
- **연구 쪽 결정 세 가지.** 주간 피처 빌드는 첫 조립이 통과(해시 일치, 누락 0)할 때만 자동 시작하고 실패하면 멈추고 다시 묻는다. 재생성의 유일한 원천인 압축 사본은 보관한다. 포트폴리오 사례에는 실패(음수) 결과와 "holdout을 봉인한 채 운영하는 방법론"을 그대로 쓴다.
- **새 연구 후보는 "매도벽·매수벽"이다.** 호가 잔량을 시가총액 대비로 본다. 1단계 필드 확인에서 체결 행의 10단계 호가는 전체 체결의 약 40~50%에만 있고, 하루 전체 데이터가 있는 탐색일은 3일뿐이며, 소진과 취소는 "체결로 설명되지 않는 순변화"로만 구분할 수 있다는 점을 알게 됐다.
- **큰 기능 PR은 노트북에서 전체 시험(5천 개 넘게 통과)을 돌린 뒤 사용자가 병합했다.**

## 2. 실패와 원인

- **새 디스크에 복사한 사본이 검증에 실패했다.** 디스크 오류 이벤트도 같이 났다. 바로 쓰기를 멈추고 첫 조치로 SATA 전원선만 바꿨다. 긴 자가진단이 오류 없이 끝났고 SMART 값도 0이라 재개를 승인했다. 바꾼 것이 전원선뿐이라 데이터 케이블·포트 원인은 "배제 안 됨"으로 남겼다.
- **새 야간 파이프라인이 첫날 밤 바로 실패했다.** 함수에 인자 하나(profile)가 빠져 KeyError가 났다. 원본은 건드리지 않았다. 핫픽스를 내고, 대기 중이던 다음 변경을 핫픽스 위로 다시 쌓았다.
- **복사 도구가 모의 실행에서 숨은 결함을 드러냈다.** 검증에 실패한 사본도 "이미 복사됨"으로 보고 재실행 때 건너뛰었다. 삭제 관문은 검증 통과를 따로 요구해서 원본은 안전했다. 다음 코드 회차에 고친다.
- **전달받은 말을 사용자 결정으로 기록했다.** 총괄 창의 짧은 말을 노트북 쪽 결정으로 받아 적었는데, 노트북 로그에는 "사용자 확인 전"으로 남아 있었다. 두 기록을 함께 두었다가 사용자가 노트북에서 직접 확인한 뒤 닫았다.
- **"권고대로"를 너무 넓게 읽었다.** 권고안이 없는 항목까지 결정된 것으로 볼 뻔했다. 실행 타워에 제안을 받아 사용자에게 다시 물었다.
- **승인과 다른 환경에서 시험이 돌았다.** 사용자는 "별도 venv"를 승인했는데 기존 venv로 돌았다. 그대로 보고했고 사용자가 받아들였다.
- **작은 도구 실수 셋.** Python heredoc 안의 `\f`가 폼피드 문자로 바뀌어 위키 경로가 깨졌다. `gh pr create --fill`은 그 작업 폴더에 로컬 브랜치가 없어서 실패했다. 휴지통으로 보내려던 가상환경은 알 수 없는 프로세스가 `.pyd`를 잡고 있어 옮겨지지 않았다.

## 3. 바뀐 규칙

- 다른 창이나 세션이 전한 말은 결정이 아니다. 당사자 창에서 직접 확인하기 전에는 "갈린 기록"으로 두 쪽을 다 적는다.
- "권고대로"는 권고안이 있는 항목에만 적용된다.
- 실주문 코드의 안전 규칙: 주문 상태를 모를 때는 추가 주문을 내지 않는다. 늦게 온 조회 한 번으로 "미체결"이라고 판단하지 않는다(2주 보유나 초과 매도를 막기 위해서다). 시작할 때 이미 그 종목을 들고 있으면 거부한다.
- 검증 날짜에 나온 실험 산출물에는 "연구에서 읽지 말 것" 표식을 단다.
- 노트북의 메모리 정지선을 사용자가 직접 상향해 상시 기준으로 고정했다.

## 4. 배운 점

- **하드웨어 원인은 한 번에 하나씩 바꿔야 판정할 수 있다.** 바꾸지 않은 원인은 배제된 것이 아니다.
- **쓰기 없는 모의 실행(dry-run)은 도구가 실제로 무엇을 "이미 됐다"고 보는지 드러낸다.**
- **실주문 전에 "주문 없는 API 확인"을 따로 두면 비용 없이 걸러낼 수 있다.** 인증·시계·정지 경로 문제를 돈과 상관없이 먼저 확인한다.
- **결정은 표 하나로 묶고 항목마다 권고·근거·영향을 붙이면 빨리 끝난다.** 26개가 아침 한 번에 끝났고, 남은 것은 "권고 없음" 항목뿐이었다.
