### 4장 1강: Attention 메커니즘

- **Attention의 목적:** 현재 처리하는 정보와 다른 위치의 정보 사이 관련성을 계산하고, 관련성이 높은 정보는 크게 반영하고 낮은 정보는 작게 반영하여 새로운 표현을 만든다.
- **RNN/LSTM과의 구조적 차이:** RNN 계열은 이전 Hidden State를 순차적으로 전달하지만, Self-Attention은 같은 시퀀스의 여러 위치 사이 관계를 직접 계산한다.
- **Attention Score와 Weight:** Query와 Key를 비교해 관련성 점수를 계산하고, Softmax로 합이 1인 Attention Weight로 바꾼다.
- **최종 출력:** Attention Weight 자체가 출력이 아니라, Weight를 각 Value에 적용한 **가중합(Weighted Sum)** 이 새로운 표현이 된다.
- **Self-Attention:** Query, Key, Value를 같은 입력 시퀀스에서 만든다.
- **Cross-Attention:** Query는 한쪽 표현에서, Key와 Value는 다른 입력/표현에서 가져온다.

#### Query, Key, Value

- **Query(Q):** 현재 위치에서 어떤 정보가 필요한지 판단하는 기준
- **Key(K):** Query와 비교하여 관련성 점수를 계산할 대상
- **Value(V):** 계산된 Attention Weight에 따라 실제로 결합할 정보

입력 표현을 (X)라고 하면 각 표현은 서로 다른 학습 가능한 가중치 행렬로 만든다.

```math
Q = XW_Q, \qquad K = XW_K, \qquad V = XW_V
```

같은 입력에서 출발하더라도 (W_Q), (W_K), (W_V)가 서로 다르므로 Q, K, V는 일반적으로 서로 다른 값을 갖는다.

#### Scaled Dot-Product Attention

Transformer의 대표적인 Attention 계산은 다음 순서다.

1. Query와 Key의 내적으로 관련성 점수 계산
2. 점수를 (sqrt{d_k})로 나누어 Scaling
3. Softmax로 Attention Weight 계산
4. Weight를 이용하여 Value를 가중합

```math
\mathrm{Attention}(Q,K,V)
=
\mathrm{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V
```

Scaling은 차원이 커지면서 내적값이 커지고 Softmax가 한 위치에 과도하게 몰리는 현상을 완화한다.

강의의 가상 예시에서는 (Q=[2,0,0,0])일 때 세 Key와의 내적 점수가 ([0,4,2]), Scaling 후 ([0,2,1]), Softmax 후 Attention Weight가 약 ([0.090,0.665,0.245])가 된다. 이 Weight로 Value를 가중합한 최종 표현은 약 ([0.335,1.575])다.

### 4장 2강: Transformer 아키텍처

#### Multi-Head Attention

하나의 Attention도 여러 위치의 정보를 섞을 수 있지만, Transformer는 여러 **Attention Head**를 병렬로 사용한다.

```text
입력 X
 ├─ Head 1 ─→ Attention 결과 1
 ├─ Head 2 ─→ Attention 결과 2
 └─ Head 3 ─→ Attention 결과 3
                    ↓
              Concatenation
                    ↓
             Output Projection
                    ↓
                 최종 출력
```

각 Head는 같은 입력 (X)에서 출발하지만 서로 다른 (W_Q, W_K, W_V)를 학습한다. 따라서 Head마다 Q/K/V, Attention Score, Attention Weight가 달라질 수 있고 서로 다른 관점의 관계를 표현할 가능성이 생긴다.

다만 Head 1은 항상 주어, Head 2는 항상 목적어처럼 역할이 미리 정해지는 것은 아니다. 여러 Head가 비슷한 관계를 학습할 수도 있다.

#### Concatenation과 Output Projection

각 Head의 결과는 더하거나 평균내는 것이 아니라 먼저 이어 붙인다.

```text
Head 1 = [0.8, 0.2]
Head 2 = [0.3, 0.7]

Concat = [0.8, 0.2, 0.3, 0.7]
```

이후 학습 가능한 (W_O)로 다시 선형 변환한다.

```math
\mathrm{Output}
=
\mathrm{Concat}(Head_1, Head_2, \ldots)W_O
```

예를 들어 입력 Shape가 ((2,3,8)), Head가 2개라면 Head당 차원을 4로 나눠 각 Head 출력은 ((2,3,4)), Concatenation 후 ((2,3,8)), Output Projection 후에도 ((2,3,8))로 유지할 수 있다.

#### Positional Encoding

Self-Attention 연산 자체에는 토큰이 몇 번째 위치인지 나타내는 정보가 없다. 따라서 Transformer는 위치 정보를 별도로 반영한다.

```math
\text{Input Representation}
=
\text{Token Embedding}
+
\text{Positional Encoding}
```

같은 토큰이라도 위치 벡터가 다르면 Transformer에 들어가는 최종 입력 표현도 달라진다. 강의에서는 Sin/Cos를 이용한 **Sinusoidal Positional Encoding**과 학습 가능한 **Learned Positional Embedding**을 소개했고, 최근 모델에서는 RoPE처럼 위치를 Q/K에 반영하는 다른 방식도 사용한다.

#### Encoder와 Decoder

원래 Transformer는 입력을 처리하는 Encoder와 출력을 생성하는 Decoder로 구성된다.

```text
입력 토큰
   ↓
Embedding + Position
   ↓
Encoder
(Self-Attention → FFN)
   ↓
Encoder 출력
   ↓
Decoder
(Masked Self-Attention → Cross-Attention → FFN)
   ↓
Linear / Logit
   ↓
다음 토큰 예측
```

- **Encoder:** 입력 시퀀스의 토큰들 사이 관계를 Self-Attention으로 계산하고, 각 토큰에 문맥이 반영된 표현을 만든다.
- **Decoder:** 이전에 생성된 출력 토큰을 이용해 다음 토큰을 예측한다.
- **Masked Self-Attention:** 미래 토큰을 미리 볼 수 없도록 Causal Mask를 적용한다.
- **Cross-Attention:** Decoder의 Query가 Encoder 출력에서 만든 Key/Value를 참조하여 입력 문장 정보를 가져온다.
- **FFN:** Attention으로 결합된 각 위치의 표현을 추가로 변환한다.

#### Causal Mask

Autoregressive 생성에서는 미래 정답을 미리 참조하면 안 된다.

```text
        K1   K2   K3
Q1      O    X    X
Q2      O    O    X
Q3      O    O    O
```

참조할 수 없는 위치의 Attention Score를 (-\infty)에 가깝게 만들어 Softmax 후 Weight가 0이 되도록 한다.

#### Transformer 구조의 세 가지 대표 형태

- **Encoder-only:** BERT 계열. 입력 전체 문맥을 반영한 표현 생성과 분류/이해 작업에 적합하다.
- **Decoder-only:** GPT 계열. Causal Self-Attention으로 이전 토큰을 바탕으로 다음 토큰을 생성한다.
- **Encoder-Decoder:** 원래 Transformer, T5 등. Encoder가 입력을 처리하고 Decoder가 이를 참조하여 출력 시퀀스를 생성한다.

핵심 흐름을 한 줄로 연결하면 다음과 같다.

```text
RNN/LSTM의 순차 상태 전달
        ↓
Attention으로 위치 간 관계 직접 계산
        ↓
Multi-Head로 여러 관계를 병렬 관찰
        +
Positional Encoding으로 순서 정보 보강
        ↓
Encoder / Decoder 블록으로 연결
        ↓
Transformer
```

### 코딩 테스트 연습: 이분 탐색(Binary Search)

- 정렬된 리스트에서 가운데 값을 기준으로 탐색 범위를 절반씩 줄여 목표 값을 찾는 방법이다.
- 핵심 변수는 `left`, `right`, `mid`.
- 목표값보다 가운데 값이 작으면 `left = mid + 1`, 크면 `right = mid - 1`로 범위를 줄인다.
- 시간 복잡도는 일반적으로 (O(\log n)).
- 오늘 문제는 정렬된 `data_ids`에서 여러 `queries`의 위치를 각각 찾아 인덱스를 반환하고, 없으면 `-1`을 반환하는 형태였다.
- 강의에서는 `list.index()`, `in`을 이용한 순차 검색 대신 이분 탐색을 직접 구현하도록 했다.
- 이 문제를 내가 직접 제출하거나 정답 판정을 받은 기록은 이번 대화에는 없어 **미확인**이다.

## 2. 수업 흐름에서 잡은 연결

- **Q/K와 V의 역할을 분리해서 보기:** Q와 K는 "어디를 얼마나 볼지"를 정하고, V는 "실제로 가져올 정보"다.
- **Attention → Multi-Head:** Attention 계산을 여러 개 병렬로 두고 각 Head가 서로 다른 투영을 학습하게 만든 것이 Multi-Head Attention이다.
- **Self-Attention → 위치 정보 문제:** 토큰 관계만 계산하면 순서 자체는 별도로 주어지지 않으므로 Positional Encoding이 필요하다.
- **Encoder와 Decoder의 차이:** Encoder는 입력의 문맥 표현을 만들고, Decoder는 미래를 가린 상태에서 이전 출력과 필요한 입력 정보를 사용해 다음 토큰을 생성한다.
- **GPT와 원래 Transformer의 차이:** 원래 Transformer는 Encoder-Decoder 구조지만, 일반적인 GPT 계열은 Decoder-only 구조를 사용한다.
- **학습과 생성의 차이:** 학습 시에는 정답 토큰들이 있어 Causal Mask를 적용하면서 여러 위치의 손실을 병렬 계산할 수 있지만, 실제 Autoregressive 생성에서는 이전에 생성한 결과에 의존해 다음 토큰을 순차 생성한다.
