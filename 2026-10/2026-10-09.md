오늘은 기존 프로젝트 설명을 최신 근거와 대조하고, 포트폴리오의 읽기 순서와 시각 표현을 정리했다. 결과를 더 잘 전달하는 디자인과 결과를 더 크게 주장하는 표현은 구분해야 한다는 점을 배웠다.

## 1. 오늘 배운 것

### 1.1 구현·테스트·실행 기록·직접 재실행은 서로 다른 근거다

- **코드 구현:** 기능을 처리하는 코드가 있다는 근거다. 실제 데이터에서 해당 기능이 정상 동작했다는 뜻까지 포함하지 않는다.
- **합성 데이터 테스트:** 정해진 입력과 예외 조건에 대한 기대 동작을 검사한다. 현실 데이터의 모든 품질 문제를 대표하지 않는다.
- **제한 범위의 실제 데이터 실행 기록:** 기록에 명시된 데이터와 조건에서 관찰한 결과다. 전체 데이터나 다른 운영 환경으로 자동 확대할 수 없다.
- **직접 재실행:** 현재 검토자가 실행 환경과 입력을 확보해 결과를 다시 확인한 경우다. 저장소의 과거 보고서를 읽는 것과 구분한다.
- **실제 운영 효과:** 앞 단계의 근거만으로 입증되지 않는다. 별도의 운영 조건과 관찰 결과가 필요하다.

문서에 적힌 오래된 한계가 지금도 유효한지는 이후 근거를 읽고 판단해야 한다. 반대로 새 코드나 테스트가 추가됐다는 이유만으로 미확인 항목을 완료로 바꾸어서도 안 된다.

### 1.2 근거의 기준 시점과 오늘 검토한 날짜를 분리한다

문서를 오늘 읽었다고 원본 결과까지 오늘 실행된 것은 아니다.

- 원본 revision과 실행 기록의 날짜는 **그 결과가 어느 상태를 설명하는지**를 나타낸다.
- 상태 검토일은 **언제 근거를 읽고 설명을 갱신했는지**를 나타낸다.
- 역할 확인은 **누가 무엇을 책임졌는지**에 대한 근거이며, 성능이나 기술 숙련도를 대신 증명하지 않는다.
- 저장소에서 확인되지 않는 로컬 작업은 없었다고 단정하지 않고 확인 범위 밖으로 남긴다.

### 1.3 디자인은 장식보다 읽기 순서와 사실 보존부터 정한다

포트폴리오 디자인은 소개 → 대표 프로젝트 → 결과를 읽는 기준 → 개발 방식과 근거 → 추가 학습의 순서로 정리했다.

- 배경·주요 문자·강조선의 색을 명시적인 토큰으로 정하면 자산을 옮겨도 표현 기준을 유지할 수 있다.
- 제목·부제·본문의 위계와 여백을 사용하고, GitHub Markdown 본문은 기본 글꼴·테마를 따른다.
- 단일 열과 짧은 문단은 좁은 화면을 고려한 설계 선택이다. 실제 모바일 검수를 했다는 뜻은 아니다.
- 결과 가까이에 조건과 한계를 두고, 근거 링크와 개인 역할의 범위를 유지한다.
- 이미지에는 대체 텍스트를 제공하고, 중요한 설명과 탐색 링크는 이미지 밖의 실제 텍스트로도 남긴다.

다른 프로젝트의 표현 방법을 참고하더라도 색이나 모양만 복제하기보다 독자가 어떤 순서로 근거를 읽을지 먼저 정해야 한다.

### 1.4 자산 형식도 저장소의 검사 계약에 맞아야 한다

이번 저장소의 기존 검사는 추적 파일을 UTF-8 텍스트로 읽는다. PNG 같은 바이너리 이미지를 그대로 추가하는 방식은 이 검사와 맞지 않는다.

Canva에서 편집 가능한 원본을 준비한 뒤, 미리보기의 레이아웃과 색을 저장소용 정적 SVG로 재구성했다. SVG는 UTF-8 텍스트이며 스크립트·외부 이미지·외부 글꼴 없이 사용할 수 있다.

- 결과물은 **Canva 직접 export나 픽셀 단위 복제**라고 설명하지 않는다.
- 검사를 약화해 자산을 통과시키지 않고, 기존 검사와 문서 fixture에 맞는 형식과 위치를 선택한다.
- 이미지가 표시된다는 것, 자동 검사가 성공한다는 것, 실제 화면이 읽기 좋다는 것은 각각 따로 확인한다.

## 2. 작업에서 확인한 것과 결과

### 2.1 포트폴리오 변경과 병합 후 검사

- 공개 포트폴리오의 README·사례 탐색 구조·표현 기준·정적 SVG를 정리한 [PR #4](https://github.com/Peter-jackson12/career-portfolio/pull/4)가 병합됐다.
- 병합 커밋 `0af632a250e9736b0e0bb02d36c3087de788ef7d`의 [후속 CI](https://github.com/Peter-jackson12/career-portfolio/actions/runs/37890210359)를 확인했다.
- Ubuntu/Python 3.11과 Windows/Python 3.13 모두 lint, format 검사, tracked-file 검사, pytest 단계가 성공했다.
- 데스크톱 GitHub 화면 검수는 당일 작업에서 확인했다. 모바일 화면 검수는 아직 하지 않았다.
- 이 TIL 정리 과정에서는 연결된 GitHub 도구로 원격 문서와 검사 결과를 확인했다. 로컬 테스트나 프로젝트 데이터 재실행을 새로 수행한 것으로 쓰지 않는다.

### 2.2 변경 전후의 사실 범위 유지

이번 표현 변경은 결과의 조건·분모·기준 revision·역할 범위와 AI 개발 보조 공개를 보존했다. 생성 인덱스나 데이터 계약을 디자인 변경만으로 다시 정의하지 않았다.

CI 성공은 해당 커밋에 설정된 검사가 통과했다는 뜻이다. 모든 화면의 접근성, 외부 링크의 영구 가용성, 프로젝트 전체의 운영 완성을 보증하지 않는다.
