### 문제: 연구마다 틱을 처음부터 다시 재생하고 있었다

- 진입 피처(모멘텀·변동성·체결 대금 등)를 연구마다 원본 틱에서 다시 계산했다. 설계 문서 기준으로 한 연구의 격자 계산은 날짜당 1.6~2.0시간이 걸렸고, 같은 이름의 피처가 연구마다 다른 정의로 구현될 위험도 있었다.
- 목표: **전 보통주 × 30초 격자** 피처 표(약 114개 열, float32)를 날짜별로 한 번 만들고, 이후 연구는 같은 정의·같은 해시의 표를 읽는다.

### 해결 1: 누수 차단을 구조로 고정

| 원칙 | 설계 내용 |
|---|---|
| 시각 절단 | 시각 `t`의 피처는 `received_ns < t_ns` 이벤트만 사용(같은 ns는 미래로 봄). 기존 동결 함수와 정의가 같은지 회귀 검사 |
| 결측 | 창 전체를 관측하지 못했으면 null. 부분 창 외삽·0 채우기 금지 |
| 횡단면 순위 | 같은 `t`의 행끼리만 계산 |
| 정적 자료 | 공개 시각이 `t`보다 늦은 값은 사용하지 않음 |
| 라벨(미래 수익) | 별도 봉인 저장소. 피처 코드가 라벨 코드를 import하지 못하게 함 |
| 결속 | 날짜별 manifest에 입력·코드·피처 목록·환경의 SHA256 |

아래는 "엄격한 `<` 절단"을 이해하려고 AI가 정리한 예시 코드다(프로젝트 코드 아님).

```python
import numpy as np

def signal_cut(received_ns: np.ndarray, t_ns: int) -> int:
    """t 시점에 알 수 있는 이벤트 수. 같은 ns는 포함하지 않는다."""
    return int(np.searchsorted(received_ns, t_ns, side="left"))
```

## 6. 오늘 수업: AI를 위한 기초 수학 1장 1~2강

수업 자료(노션 강의 페이지 1강·2강)에 적힌 내용을 정리했다. 교안에 있는 내용이며 이 절의 설명을 직접 새로 실험한 것은 아니다. 3강은 수업 진도 여부를 확인하지 못해 포함하지 않았다.

### 1강: 벡터와 행렬의 기본 개념

- 스칼라는 숫자 하나, 벡터는 숫자를 순서대로 나열한 것(데이터 한 건의 여러 특성), 행렬은 숫자를 행과 열로 배열한 것(여러 데이터)이다. 고객의 방문 횟수·장바구니 추가 횟수 예시로 설명한다. 행렬 원소 `Xᵢⱼ`는 수학 표기상 1부터 센다.
- 머신러닝 표현: 입력 행렬 `X`는 `(n, d)`(데이터 수 × 특성 수), 타깃 벡터 `y`, 가중치 `w`(벡터)와 `W`(행렬, 열 하나가 출력 하나), 편향 `b`다. 예시 `score = w₁x₁ + w₂x₂ + b`에서 고객 A는 `2×5 + 3×2 + 1 = 17`이며 이 값은 확률이 아니라 가중합 점수다(확률로 바꾸려면 Sigmoid 같은 추가 변환이 필요하다고 안내됨).
- 차원과 Shape: 벡터의 차원은 원소 개수이고 NumPy의 `ndim`은 축 개수다. `(2,)`, `(1, 2)`, `(2, 1)`은 서로 다르며 `reshape`는 원소 개수를 유지한다. 입력의 특성 수와 가중치 수가 맞아야 연산할 수 있다.
- 노름: L1은 절댓값의 합, L2는 제곱합의 제곱근이다. `[3, 4]`에서 L1 = 7, L2 = 5이고 `np.linalg.norm(x, ord=1 또는 2)`로 계산한다. 두 벡터의 차이에 적용하면 맨해튼 거리(L1)와 유클리드 거리(L2)가 되고, L2 Norm으로 나누면 방향은 유지하고 길이가 1인 단위 벡터가 된다(0벡터는 불가).
- 구분할 개념: 벡터 정규화(길이 조정), 규제(Regularization, 가중치에 제약을 줘서 과적합을 완화하며 L1은 희소한 해, L2는 가중치 억제), 특성 스케일링·표준화(특성별 범위·분포 조정).
- 코딩 테스트 연습: DFS(스택과 `visited`)와 "센서 이상 영역 중 가장 큰 영역의 크기" 문제가 있었다. 풀이 여부는 미확인이다.

### 2강: 벡터 내적과 행렬 곱

- 벡터 내적은 대응하는 원소끼리 곱해 모두 더한 값이며 결과는 스칼라다. `[2, 3]·[4, 5] = 23`. 원소 개수가 같아야 하고 `np.dot(a, b)`나 1차원 배열의 `a @ b`로 계산한다.
- 기하학적 의미는 `a · b = ‖a‖₂‖b‖₂ cos θ`다. 내적이 양수면 사이각 90° 미만, 0이면 수직, 음수면 90° 초과(0벡터가 아닐 때)이고, 내적은 크기에도 영향을 받으므로 내적이 크다고 방향이 더 비슷한 것은 아니다.
- 코사인 유사도 `(a·b) / (‖a‖₂‖b‖₂)`는 크기의 영향을 없애고 방향만 비교한다(−1~1, 0벡터는 계산 불가). `[3, 4]`와 `[6, 8]`은 내적 50, 노름 5와 10이라 유사도가 1이다. 임베딩 유사도 비교에 쓴다.
- 가중합 활용: `x = [3, 2]`, `w = [2, 4]`의 내적이 점수 14다. 입력이 달라도 점수가 같을 수 있다(고객 A·B 모두 14, C는 20).
- 행렬곱은 첫 행렬의 행과 두 번째 행렬의 열을 내적해 결과 행렬의 각 원소를 만든다. `[[1,2],[3,4]] @ [[5,6],[7,8]] = [[19,22],[43,50]]`. `*`는 원소별 곱셈이라 다른 연산이다(`[[5,12],[21,32]]`).
- Shape 규칙은 `(m,n) @ (n,p) → (m,p)`다. 가운데 n이 같아야 하고 바깥 m, p가 결과 Shape가 된다. 실제 계산 없이 Shape만으로 판단할 수 있다. `(3,2) @ (2,)`는 `(3,)`, `(3,2) @ (2,1)`은 `(3,1)`로 값은 같고 구조만 다르다.
- 순서: 일반적으로 `A @ B ≠ B @ A`이고, 한쪽만 가능한 Shape도 있다. 머신러닝에서는 `X(n_samples, n_features) @ W(n_features, n_outputs) → Y(n_samples, n_outputs)`이며, 안 맞으면 `ValueError`가 난다.

## 7. 수업 중 질문과 정리

질문과 처음 헷갈린 점은 내가 한 것이고, 아래 설명은 Claude Code 세션에서 AI가 정리한 것이다(교안에 없는 보충 포함). 직접 실행해 확인한 것이 아니다.

### 노름·거리

- 질문: L2 Norm도 삼각부등식이 성립하는가? L∞(무한대 노름)는 무엇인가?
  - 노름은 "크기를 숫자로 나타낸 것"을 넘어 세 조건(0 이상이며 0벡터일 때만 0, 상수배 `‖cx‖ = |c|‖x‖`, 삼각부등식 `‖x+y‖ ≤ ‖x‖+‖y‖`)을 만족하는 함수다. L2도 성립한다(`x=[3,0], y=[0,4]`에서 `5 ≤ 3+4 = 7`). 증명은 코시-슈바르츠 부등식을 쓰며 내적과 이어진다.
  - L∞는 Lp Norm에서 p를 무한대로 보낸 극한으로 `max(|x₁|, …, |xₙ|)`다. `[3,-4]`에서 L1 = 7, L2 = 5, L∞ = 4이고 `np.linalg.norm(x, ord=np.inf)`로 계산한다. 이번 강의 범위 밖이다.
- 질문: 맨해튼 거리는 L1, 유클리드 거리는 L2라고 생각해도 되는가?
  - 차이 벡터에 적용한 값이라는 조건에서 그렇다. 노름은 벡터 하나의 크기, 거리는 두 점의 차이 벡터의 크기다. L∞로 만든 거리는 체비쇼프 거리다.
- 질문: 유클리드 거리는 고등학교 원방정식과 같은 것인가?
  - 유클리드 거리는 두 점 사이의 거리 공식 `√((x₂−x₁)² + (y₂−y₁)²)`와 같고, 원방정식 `x² + y² = r²`은 "원점에서 L2 거리가 r인 점들의 모임"이다. 원점에서 노름이 1인 점들은 L2는 원, L1은 마름모, L∞는 정사각형이다.

### 라쏘·릿지와의 연결 (강의 범위 밖 보충)

- 라쏘는 손실 + λ‖w‖₁(L1 규제), 릿지는 손실 + λ‖w‖₂²(L2 규제)다. 규제를 "가중치를 이 영역 안에서만 고른다"는 제약으로 보면 영역은 라쏘가 마름모, 릿지가 원이다. 손실 등고선이 영역에 처음 닿는 점이 해다.
- 마름모는 꼭짓점이 축 위에 있어 꼭짓점에서 닿기 쉽고, 그때 한 가중치가 정확히 0이 된다(희소한 해). 원은 모서리가 없어 닿는 점이 보통 축 위가 아니어서 가중치가 작아지지만 일반적으로 0이 되지 않는다(릿지는 라쏘와 달리 일반적으로 희소성을 유도하지 않는다는 뜻이다. 한 특성이 타깃과 정확히 직교하는 등 특수한 경우에는 릿지도 계수가 정확히 0일 수 있다). 최소점의 위치에 따라 라쏘도 변에 닿을 수 있고 그 경우 두 가중치 모두 0이 아니다. 따라서 "라쏘는 0이 되기 쉽다"가 정확한 표현이다(이 설명은 AI가 대화에서 그림으로 그려 준 모식도이며 등고선을 원으로 단순화했다).
- 질문: 제약 영역이 손실 최소점에 닿으면 안 되는 이유는?
  - 최소점이 영역 안이나 경계에 있으면 그 점을 그대로 고를 수 있어 해가 최소점과 같아지고 규제 효과가 없다. 의미 있는 규제는 최소점이 영역 밖에 있어 제약이 실제로 작동할 때다. 예: 손실 `(w₁−3)² + (w₂−2)²`에서 `|w₁|+|w₂| ≤ t`일 때 t = 10, 5이면 해가 (3, 2) 그대로이고 t = 3이면 해가 (2, 1)(손계산)이며 손실이 0에서 2로 올라간다.
- 질문: 예산 t는 훈련 데이터로 최적값을 찾아 두는 것인가? 예산이 맨해튼·유클리드 거리와 같은 것인가?
  - 가중치 w는 모델이 훈련으로 학습하는 파라미터, 예산 t(또는 λ)는 사람이 정하는 하이퍼파라미터다. 훈련 손실만 보면 규제 없는 쪽이 항상 이기므로 검증 데이터 성능으로 고른다.
  - 예산은 "가중치 벡터 크기의 상한"이고, 크기를 재는 방식이 L1이면 맨해튼, L2이면 유클리드다(제약 영역 = 원점에서 w까지의 거리가 t 이하). 수업에서 배운 두 데이터 사이의 거리와 달리 원점과 가중치 벡터 사이의 거리다.
- 질문: 교차검증은 5-fold 같은 것이 대표적인가? Stratified도 있는가?
  - K-Fold(K = 5, 10)가 기본이고, Stratified K-Fold는 각 조각의 클래스 비율을 전체와 비슷하게 유지한다(분류, 클래스 불균형). 그 밖에 Leave-One-Out, Group K-Fold, 시계열의 TimeSeriesSplit이 있다.

### 내적·행렬곱·`@`·Shape

- 처음 헷갈린 점: `A @ B ≠ B @ A`를 내적에 대한 말로 이해했다.
  - 이는 행렬곱에 대한 말이다. 벡터 내적은 순서를 바꿔도 같고(`a·b = b·a`), 행렬곱은 칸마다 "행과 열의 내적"이라 순서를 바꾸면 짝지어지는 행과 열이 달라진다(`[[1,2],[0,1]] @ [[1,0],[3,1]]`의 왼쪽 위 칸이 7과 1).
- 질문: 행렬곱이 외적인가?
  - 아니다. 외적(outer product)은 열벡터와 행벡터를 곱해 행렬을 만드는 연산(`(m,1) @ (1,n) → (m,n)`, `np.outer`)이다. 행렬곱은 "A의 k번째 열 ⊗ B의 k번째 행"의 합으로도 볼 수 있다. 한국어 "외적"은 3차원 벡터곱(cross product)도 가리켜 혼동하기 쉽다.
- 질문: 내적과 행렬곱의 기호가 둘 다 `@`로 같은가? 같은 A, B에서 내적이면 스칼라, 행렬곱이면 행렬로 쓰는가?
  - `@`는 행렬곱 연산자이고 입력에 따라 결과 종류가 정해진다(벡터 @ 벡터 → 스칼라, 행렬 @ 행렬 → 행렬, 행렬 @ 벡터 → 벡터). 이 수업에서 배운 내적은 벡터 사이의 연산이고, 행렬 A, B에 `@`를 쓰면 내적이 아니라 행렬곱이며 그 안의 각 칸이 행과 열의 내적이다(같은 Shape의 두 행렬에는 원소별로 곱해 모두 더하는 프로베니우스 내적 `tr(AᵀB) = Σ AᵢⱼBᵢⱼ`가 따로 정의되지만 이번 강의 범위 밖이다). 수학 표기는 내적 `a·b`, 행렬곱 `AB`로 다르다.
- 처음 헷갈린 점: `(3,2) @ (2,4)`의 `(3,2)`를 값으로 읽어 결과도 `(10, 30)` 같은 숫자가 나와야 한다고 생각했다.
  - `(3,2)`는 Shape(3행 2열)이고, 결과 Shape `(3,4)`는 3행 4열 행렬(원소 12개)이 나온다는 뜻이다.
- 질문: `x_a = np.array([5, 2])`도 1행 2열이 아니라 원소 2개인 1차원 배열로 치는가?
  - 그렇다. 대괄호 한 겹은 `ndim = 1`, `shape = (2,)`이고 `[[5, 2]]`가 `(1, 2)`, `[[5], [2]]`가 `(2, 1)`이다. 방향이 중요하면 `reshape(1, 2)`나 `reshape(2, 1)`로 2차원으로 바꾼다.

## 8. 직접 해본 것과 결과

- 로컬 실습 폴더의 실습 노트북 3개(1강·2강·3강)의 코드 셀 18개는 내가 직접 푼 것이 아니라 AI(Claude)가 풀이를 작성해 실행한 결과다. 실행 출력은 모두 먼저 손계산한 값과 일치했고, 답변 작성란도 AI가 쓴 설명이다. 노트북 안에는 AI 작성 표시가 없다. 학생이 직접 푼 풀이와 구분해야 한다.
- 주요 결과(AI 실행): 1강 고객 A 점수 17·고객 C 점수 16, `[3,-4]`의 L1 7·L2 5, `[3,4]`와 `[6,8]`의 맨해튼 거리 7·유클리드 거리 5, 정규화 후 둘 다 `[0.6, 0.8]`. 2강 점수 14·14·20, 방향별 내적 2·0·−2, 코사인 유사도 1.0, `A @ B = [[19,22],[43,50]]`, `X @ W = [[14,9],[14,8],[20,14]]`. 3강 선형 변환 `[6,6]`·아핀 변환 `[7,4]`, 두 레이어 순전파 최종 출력 `[[7],[8],[-2]]`와 `[[3],[7]]`.
- 3강 노트북은 3강 교안을 읽지 않고 문제에 주어진 숫자·공식만으로 풀었다.
- 이 외에 직접 실행한 코드는 없다. 교안의 코드 예시와 대화의 숫자 예시는 재실행하지 않았다(손계산).

## 9. 아직 헷갈리는 것 / 다음에 확인할 것

- 제약식의 t와 페널티 형태의 λ(sklearn은 `alpha`)가 정확히 어떤 관계인지 확인하지 못했다(λ가 크면 영역이 작아진다는 방향만 설명받음).
