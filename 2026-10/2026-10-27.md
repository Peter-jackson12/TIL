## 2. 2장 핵심: 점수 → 확률 → 손실

- **점수(Logit)는 확률이 아니다.** `X @ w + b`는 음수·1 초과도 가능하고 Sigmoid·Softmax를 거쳐야 확률이 된다. 흐름은 점수 → 확률 → 클래스(Threshold 또는 Argmax)다.
  - 예: 점수 [0.8, −1.4, 2.2] → Sigmoid [0.690, 0.198, 0.900] → 임계값 0.5는 [1, 0, 1], 0.7은 [0, 0, 1]. 임계값을 바꿔도 확률은 그대로이고 판정 기준만 바뀐다.
  - Argmax는 확률이 아니라 위치 번호를 반환한다. Softmax([1, 2, 1]) = [0.212, 0.576, 0.212] → Argmax 1(식품)은 "100%"가 아니라 57.6%다.
- **우도는 "실제 결과에 맞는 확률을 골라 곱한 값"이다.** p는 항상 구매 확률이므로 y=1이면 p, y=0이면 1−p를 쓴다.
  - y = [1, 0, 1, 1, 0]에서 L(0.6) = 0.6³×0.4² = 0.03456, L(0.8) = 0.8³×0.2² = 0.02048. p가 크다고 좋은 게 아니라 미구매 고객의 확률(0.2)이 작아져 곱이 줄어든다.
  - 모두 같은 p를 쓰는 독립 베르누이 모델의 MLE는 평균(3/5 = 0.6)이다.
- **로그우도와 NLL:** 곱을 합으로 바꾸려고 로그를 씌우고, 음수를 피하려고 마이너스를 붙인 것이 NLL이다. y=[1,0,1], p=[0.8,0.3,0.7] → 로그우도 −0.9365, Total NLL 0.9365, Mean NLL 0.3122. 우도·로그우도는 클수록, NLL은 작을수록 좋고 세 기준이 같은 답을 고른다.
- **MSE·BCE·CE는 모두 NLL이다.** BCE는 베르누이, CE는 범주형 분포의 NLL이고, MSE는 분산을 고정한 정규분포 NLL에서 상수를 뺀 형태다.
  - CE는 가장 큰 확률이 아니라 **정답 칸의 확률**만 본다. 정답을 맞혀도 확률이 0.665면 손실 0.408이 남는다(Softmax [2,1,0] 예제).
  - MSE는 단위가 제곱(만 원²)이라 "평균 5.667만 원 틀림"으로 읽으면 안 되고, 제곱 때문에 큰 오차 하나(−4 → 16)가 손실 대부분을 차지한다.

## 3. 3장 핵심: 기울기 → 역전파 → 업데이트

- **함수값과 미분값은 다르다.** f(x)=x²에서 f(3)=9는 결과, f′(3)=6은 순간 변화율이다. h=1, 0.1, 0.01, 0.001일 때 변화율 7 → 6.1 → 6.01 → 6.001로 6에 다가간다. 미분값이 음수라는 건 "값이 음수"가 아니라 "늘리면 줄어든다"는 뜻이고, 손실을 줄이려면 부호 반대로 움직인다.
- **편미분과 Gradient:** L(w,b) = (10−2w−b)², (3,1)에서 ∂L/∂w = −12, ∂L/∂b = −6 → Gradient [−12, −6]. w만 0.1 늘리면 손실 9 → 7.84(−1.16), 편미분 근사 −1.2와 가깝다. [0.1, 0.1] 이동은 −∇L=[12, 6](2:1)과 방향이 같지 않다.
- **Chain Rule:** 연결된 단계의 미분값을 곱한다. f = (3x+1)², x=2 → z=7, df/dz=14, dz/dx=3, df/dx=42.
- **Sigmoid + BCE의 점수 기울기는 p − y**로 정리된다. x=2, y=1, w=0.5 → p=0.731, ∂L/∂z = −0.269, Gradient [w, b] = [−0.538, −0.269].
- **역전파는 기울기만 계산하고, 값을 바꾸는 것은 업데이트(`w ← w − α × 기울기`)다.** 기울기는 바뀐 위치에서 매번 새로 구한다.
  - x=2, y=10, w=3, b=1, α=0.05: 손실 9 → 2.25 → 0.5625(기울기 [−12, −6] → [−6, −3]).
  - 학습률 비교(L=(10−2w)², w=3에서 3회): 0.05는 천천히 수렴, 0.2는 5를 넘나들며 진동하지만 손실은 같은 값으로 감소, 0.25는 3↔7 제자리(손실 16 유지), 0.3은 발산(31.36 → 61.47 → 120.47).
  - 수렴은 0에 계속 가까워지는 것이지 정확히 0이 되는 게 아니다. L=(w−5)²에서 30회 뒤 w ≈ 4.995, 손실 ≈ 0.000025.
  - 데이터 4개 기준 한 Epoch 업데이트 횟수: Batch 1, 크기 2 Mini-Batch 2, SGD 4.
  - Early Stopping(patience=3): 검증 손실 최저는 Epoch 3(0.40), 종료는 Epoch 6. 종료 시점과 최적 시점은 다를 수 있다.

## 4. 질문을 통해 더 이해한 내용: 역전파를 숫자로 따라가기

내 질문: "중요하고 어려운 걸 설명해 달라"고 한 뒤, 그중 역전파를 숫자로 다시 풀어 달라고 했다. 아래는 AI 설명이다(3장 2강 문제 1-2·2-2 숫자 사용).

```
x=2 →[×w₁, +b₁]→ a →[×w₂, +b₂]→ ŷ →[(y−ŷ)²]→ L
       w₁=2, b₁=1        w₂=2, b₂=0        y=12
```

- **순전파:** a = 2×2+1 = 5, ŷ = 2×5 = 10, L = (12−10)² = 4. 예측이 정답보다 작아서 예측을 키우는 쪽이 손실을 줄인다.
- **역전파 규칙은 하나:** 뒤에서 받은 기울기 × 이번 연산의 미분값.
  1. ∂L/∂ŷ = 2(ŷ−y) = −4
  2. ∂L/∂w₂ = −4 × a(5) = −20, ∂L/∂b₂ = −4 × 1 = −4, ∂L/∂a = −4 × w₂(2) = −8
  3. ∂L/∂w₁ = −8 × x(2) = −16, ∂L/∂b₁ = −8
  - Gradient [w₁, b₁, w₂, b₂] = [−16, −8, −20, −4]
- **헷갈리던 지점:** w₂의 기울기에는 a를, a로 넘길 기울기에는 w₂를 곱한다. 곱셈에서는 상대편 값이 미분값이기 때문이다. 덧셈(+b)의 미분값은 1이다.
- 풀어 쓰면 ∂L/∂w₁ = (−4) × 2 × 2 = −16으로 세 단계의 곱이고, 역전파는 이 곱을 뒤에서부터 누적해 중간 결과(−8)를 재사용하는 방법이다.
- **검산(AI가 손으로 계산, 코드 실행 아님):** w₁을 2.01로 올리면 a = 5.02, ŷ = 10.04, L = 1.96² = 3.8416 → 변화량 −0.1584. 기울기 예측 −16 × 0.01 = −0.16과 거의 같다.
- **분류 + ReLU 버전(문제 2-2):** a=2 → h=ReLU(2)=2 → z=1 → p=0.731 → L=0.313. ∂L/∂z = p−y = −0.269에서 시작해 ∂L/∂w₂ = −0.538, ∂L/∂h = −0.269×0.5 = −0.134, ReLU 미분 1(a>0), ∂L/∂w₁ = −0.269 → Gradient [−0.269, −0.134, −0.538, −0.269]. a가 음수였다면 ReLU 미분이 0이라 w₁, b₁의 기울기도 0이 된다("죽은 ReLU").

## 5. Stock 프로젝트 회고 (10/25~27)

[inbox 회고 요약](../inbox/2026-10-27-stock.md)을 옮겨 정리했다. 계정·경로·해시·종목별 수치는 공개용으로 빠져 있고, 수치는 탐색 단계의 사후 보고라 검증 결과가 아니다. 이 세션에서 Stock 저장소나 실행 로그를 직접 확인하지는 않았다.

### 결정

- **실주문 실험 설계가 독립 리뷰에서 승인으로 수렴했다.** 사용자 결정 26개를 표 하나(항목마다 권고·근거·영향)로 묶어 하루 아침에 정했다.
- **모의투자는 비드당 약 100만 원**으로 한다(1주 가격이 100만 원을 넘으면 1주). 모의에서만 "100만 원 ÷ 최우선 매도호가, 최소 1주" 시장가 매수를 허용하고, 실전 2단계부터는 지정가 IOC만 쓴다. 동시 보유는 7종목까지다.
- **실주문 전 탐침 3단계:** 주문 없는 API 확인 → 모의 1주 주문(이틀) → 장중 시계 기록. 각 단계는 독립 리뷰 → 고정 실행 사본(detached worktree) → 해시가 붙은 사용자 카드 → "GO" 뒤 사용자가 직접 실행한다.
- **연구 쪽:** 주간 피처 빌드는 첫 조립이 통과(해시 일치, 누락 0)할 때만 자동 시작하고, 재생성의 유일한 원천인 압축 사본은 보관한다. 포트폴리오에는 실패(음수) 결과와 holdout 봉인 운영 방법론을 그대로 쓴다.
- **새 연구 후보 "매도벽·매수벽"**(호가 잔량 ÷ 시가총액): 체결 행의 10단계 호가는 전체 체결의 약 40~50%에만 있고, 하루 전체 데이터가 있는 탐색일은 3일뿐이며, 소진과 취소는 "체결로 설명되지 않는 순변화"로만 구분된다는 점을 1단계 필드 확인에서 알았다.

### 실패와 원인

- **새 디스크 사본 검증 실패**와 디스크 오류 이벤트: 쓰기를 멈추고 SATA 전원선만 바꾼 뒤, 긴 자가진단 무오류·SMART 0을 보고 재개했다. 데이터 케이블·포트 원인은 "배제 안 됨"으로 남겼다.
- **새 야간 파이프라인이 첫날 밤 KeyError로 실패:** 함수 인자(`profile`) 누락. 핫픽스 후 대기 중이던 변경을 그 위로 다시 쌓았다.
- **복사 도구의 숨은 결함:** 검증에 실패한 사본도 "이미 복사됨"으로 보고 재실행 때 건너뛰었다. 삭제 관문이 검증 통과를 따로 요구해 원본은 안전했다. 다음 코드 회차에 수정 예정.
- **기록·해석 실수:** 다른 창이 전한 말을 사용자 결정으로 적었고, "권고대로"를 권고안이 없는 항목까지 넓게 읽을 뻔했다. 승인된 "별도 venv" 대신 기존 venv로 시험이 돌았고 그대로 보고했다.
- **작은 도구 실수:** Python heredoc 안의 `\f`가 폼피드로 바뀌어 경로가 깨짐, 로컬 브랜치가 없어 `gh pr create --fill` 실패, `.pyd`를 잡은 프로세스 때문에 가상환경을 휴지통으로 옮기지 못함.

### 바뀐 규칙

- 다른 창·세션이 전한 말은 결정이 아니다. 당사자 창에서 확인하기 전에는 두 기록을 모두 "갈린 기록"으로 둔다. "권고대로"는 권고안이 있는 항목에만 적용한다.
- 실주문 안전 규칙: 주문 상태를 모르면 추가 주문을 내지 않는다. 늦게 온 조회 한 번으로 "미체결"이라 판단하지 않는다(2주 보유·초과 매도 방지). 시작할 때 이미 그 종목을 보유 중이면 거부한다.
- 검증 날짜에 나온 실험 산출물에는 "연구에서 읽지 말 것" 표식을 단다.

### 배운 점

- 하드웨어 원인은 한 번에 하나씩 바꿔야 판정할 수 있고, 바꾸지 않은 원인은 배제된 것이 아니다.
- 쓰기 없는 dry-run은 도구가 실제로 무엇을 "이미 됐다"고 보는지 드러낸다.
- 실주문 전 "주문 없는 API 확인" 단계를 두면 인증·시계·정지 경로 문제를 비용 없이 먼저 걸러낼 수 있다.
