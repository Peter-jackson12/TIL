### 1.1 CV 기반 하이퍼파라미터 탐색

- 모델이 학습하는 계수·분할 규칙은 파라미터, 학습 전에 정하는 트리 수·깊이·규제 강도 등은 하이퍼파라미터다.
- `GridSearchCV`는 지정한 조합을 탐색하고, `RandomizedSearchCV`는 지정한 후보/분포에서 일부 조합을 뽑아 탐색한다.
- `best_params_`만 보지 말고 `cv_results_`의 평균 점수·표준편차·학습 시간을 함께 본다. `best_score_`는 탐색에 사용한 CV 점수이며, 손대지 않은 최종 테스트 점수와 다르다.
- 후보 4개 × 5-fold이면 CV 학습은 20회다. `refit=True`라면 선택된 설정으로 전체 탐색용 학습 데이터에 다시 학습하는 1회가 추가된다.
- 테스트 데이터를 반복해서 보며 설정을 바꾸면 그 데이터도 사실상 선택에 사용된다. 선택용 검증과 최종 평가를 나눠야 한다.

### 1.2 재현 가능한 Pipeline

`원자료 → 결측 대치 → 인코딩/스케일링 → 모델`을 하나의 Pipeline으로 묶는다.

- `ColumnTransformer`: 수치형에는 중앙값 대치·스케일링, 범주형에는 최빈값 대치·원-핫 인코딩처럼 서로 다른 처리를 적용한다.
- 원-핫 인코딩은 범주마다 열을 만들고 해당 범주만 1로 표시한다. 단순히 A=1, B=2, C=3으로 넣어 존재하지 않는 크기·거리 관계를 만들지 않기 위한 방법이다.
- 로지스틱 회귀는 입력의 선형 결합을 확률로 바꾸는 분류 모델이다. 이진 분류에서는 시그모이드를 사용하고, 확률과 최종 판정을 나누는 임계값은 별개다.
- `fit` 때 대치값·스케일링 기준·범주와 모델을 학습한다. `predict` 때는 학습한 변환을 적용하며 새 데이터로 기준을 다시 학습하지 않는다.
- CV 바깥에서 전처리를 미리 학습하면 검증 폴드의 정보가 들어갈 수 있다. **전처리까지 포함한 Pipeline 전체를 CV에 넣는 것**이 핵심이다.
- `model__C`처럼 `단계명__파라미터명`으로 내부 설정을 탐색한다. 로지스틱 회귀의 C는 규제 강도의 역수이므로, C가 작을수록 규제가 강해진다.
- `handle_unknown="ignore"`에서 미지 범주는 해당 범주형 변수의 원-핫 열들이 모두 0이 된다. 전체 입력 행이 모두 0이 된다는 뜻은 아니다.
- 저장할 때 모델만이 아니라 전처리와 결합된 전체 Pipeline을 보존한다. 재사용 입력의 열 이름·의미·자료형도 맞아야 한다.

### 1.3 데이터 문제 해결의 흐름

“방문은 비슷한데 결제가 줄었다” 같은 질문에서 바로 복잡한 모델을 고르는 대신 다음을 연결한다.

1. 문제와 판단 지표를 정한다.
2. 데이터의 단위·기간·누락·중복·조인 관계를 확인한다.
3. 퍼널·세그먼트·통계·분류·시계열 중 질문에 맞는 방법을 고른다.
4. 결과를 행동으로 연결하고 다시 측정한다.

퍼널 분석은 **방문 → 조회 → 신청 → 결제** 같은 단계의 전환율·이탈을 보는 방법이다. 단계 순서와 관측 기간, 사용자/이벤트 중 무엇을 세는지를 먼저 정해야 한다.

A/B 테스트는 사용자를 무작위로 나누어 다른 처치를 적용하고 결과를 비교하는 실험이다. 단순 전후 비교와 달리 같은 시기의 비교군을 둔다. 유의성뿐 아니라 효과 크기와 불확실성도 함께 본다.

SHAP은 특정 예측이 기준값에서 얼마나 달라졌는지를 특성별 기여로 설명하는 방법이다. **모델 예측의 설명이지 현실의 인과관계 증명은 아니다.** 오늘은 개념을 질문했으며 SHAP 분석을 실행한 결과는 기록하지 않는다.

### 1.4 단일 트리 → 배깅 → 랜덤포레스트 → 부스팅

| 방법 | 어떻게 학습하고 합치는가 | 기억할 점 |
|---|---|---|
| 의사결정나무 | 조건으로 데이터를 계속 나누고 리프에서 예측 | 깊게 자라면 학습 데이터에 과적합하기 쉽다 |
| 배깅 | 복원 추출한 여러 표본으로 모델을 각각 학습하고 예측을 결합 | 회귀는 평균, 주로 분산 감소 |
| 랜덤포레스트 | 여러 트리를 만들면서 분할 후보 특성에도 무작위성을 적용 | 트리 간 상관을 줄이는 것이 중요 |
| 부스팅 | 앞 단계의 부족한 부분을 다음 모델이 순차 보완 | 작은 모델들의 기여를 누적하며 과도한 학습은 제어 |

- AdaBoost는 잘 맞히지 못한 표본의 가중치에 집중한다. Gradient Boosting은 손실의 음의 기울기를 학습하며, 제곱오차 회귀에서는 잔차를 학습하는 설명으로 이해할 수 있다.
- `learning_rate`가 작으면 한 단계의 기여가 작아져 더 많은 단계가 필요할 수 있다. **작게 만들기만 하면 항상 좋아지는 것은 아니다.**
- level-wise는 얕은 깊이부터 같은 수준의 노드를 확장하는 방식이다. leaf-wise는 현재 리프 중 개선 이득이 큰 곳을 우선 나눠 한쪽이 더 깊어질 수 있다.
- 수업의 XGBoost/LightGBM 비교는 기본 성장 방식을 설명한 것이다. XGBoost도 성장 정책 설정에 따라 동작이 달라질 수 있으므로 “항상 level-wise”라고 외우지 않는다.
- 트리를 많이 평균내도 서로 비슷한 오류를 내면 분산 감소에 한계가 있다. 나무 수만 늘리는 것과 다양성을 확보하는 것은 다르다.

## 2. 내가 궁금했던 질문과 이해한 답

### Q1. 부트스트랩은 겹쳐 뽑는데, K-fold는 안 겹치게 나누는 것 아니었나?

둘 다 데이터를 여러 번 활용하지만 목적과 추출 방식이 다르다.

| 구분 | 부트스트랩 | 일반적인 K-fold CV |
|---|---|---|
| 만드는 방식 | 복원 추출로 표본을 반복 생성 | 전체 자료를 겹치지 않는 K개 폴드로 분할 |
| 한 학습 표본 안의 같은 행 | 중복될 수 있음 | 같은 행을 중복 복사하지 않음 |
| 반복 간 학습 데이터 | 겹칠 수 있음 | 대부분 겹침 |
| 대표 목적 | 배깅·통계량의 불확실성 추정 | 모델의 검증 성능 평가·선택 |

K-fold에서 “안 겹친다”는 것은 **폴드 자체**와 **한 회차의 학습/검증 집합**이다. 여러 회차의 학습 집합까지 서로 안 겹친다는 뜻은 아니다. 일반적인 K-fold 한 바퀴에서는 각 행이 검증 데이터로 한 번씩 사용된다.

부트스트랩에서 특정 나무 학습에 뽑히지 않은 행은 OOB(out-of-bag)다. 원본과 같은 크기로 복원 추출할 때 빠질 확률은 `(1 - 1/n)^n`으로, 큰 n에서 약 36.8%다. OOB 평가는 유용하지만 시간 순서·그룹 분리 같은 검증 설계를 자동으로 해결하지 않는다.

### Q2. staged_predict는 무엇인가?

이미 학습한 부스팅 모델에서 **1단계까지, 2단계까지, … 누적한 예측**을 차례로 얻는 기능이다. 각 트리 하나만의 예측도 아니고, 호출할 때마다 모델을 처음부터 다시 학습하는 것도 아니다.

단계별 검증 오차를 그리면 나무를 추가할 때 어디까지 도움이 되는지 볼 수 있다. 실습은 Test RMSE 곡선을 그렸지만, 그 곡선으로 최적 단계를 선택한다면 해당 데이터는 선택용 검증 데이터가 된다. 최종 성능 보고에는 별도 테스트가 필요하다.

### Q3. BaggingRegressor의 max_features="sqrt"가 왜 문제였나?

붙여 넣은 코드에는 `max_features="sqrt"`가 있었지만, `BaggingRegressor`의 이 인수는 **정수 개수 또는 실수 비율**을 받는다. 현재 저장된 실행 셀은 `max_features=1.0`으로 바뀌어 있다.

`estimator`와 옛 `base_estimator` 이름을 바꾸는 `try/except TypeError`는 버전별 인수명 호환 처리다. 잘못된 `max_features`의 의미까지 고쳐 주지는 않는다.

또한 배깅의 특성 부분집합 선택과 랜덤포레스트의 **각 노드 분할 후보 특성 선택**은 구별해야 한다. 실습의 `RandomForestRegressor` 셀은 `max_features`를 생략했으므로, 실제 기본값도 확인해야 한다. 클래스 이름만으로 sqrt 후보 선택을 실행했다고 단정하지 않는다.

### Q4. //와 round는 어떻게 달랐나?

- `5 // 2 == 2`: 바닥 나눗셈이다. 음수에서는 `-5 // 2 == -3`이므로 단순 소수점 삭제와도 다르다.
- `math.ceil(5 / 2) == 3`: 올림.
- `round(2.5) == 2`, `round(3.5) == 4`: 정확히 중간이면 짝수 쪽으로 간다.
- 짝수 선택은 **동률일 때만**이다. `round(2.6) == 3`처럼 평소에는 더 가까운 값을 택한다.

## 4. Airplane 설명을 다시 읽으며 연결한 점

### 4.1 Macro F1과 지연 클래스 F1

`Macro F1 = (정상 클래스 F1 + 지연 클래스 F1) / 2`로 두 클래스를 같은 비중으로 본다. 지연 탐지만이 목적이라면 지연 precision·recall·F1이 직접적인 지표가 된다. Macro F1이 반드시 더 옳은 것이 아니라 **무엇을 균형 있게 평가하려는지**가 다르다.

현재 프로젝트의 내부 임계값 선택 목적과 보고 지표를 일치시키되, 실제 활용을 설명할 때는 클래스별 지표·혼동행렬도 함께 봐야 한다. Macro F1 상승을 지연 recall의 큰 상승이나 운영 비용 절감으로 바꾸어 말하지 않는다.

### 4.2 OOF와 공정한 비교

OOF(out-of-fold)는 해당 행을 학습에 쓰지 않은 폴드 모델의 예측이다. 폴드별 검증 예측을 모으면 각 행에 대한 학습 밖 예측으로 지표를 계산할 수 있다. 전처리·임계값 선택에도 그 행의 정답이 들어가지 않도록 경계를 지켜야 한다.

Airplane의 LightGBM 전처리 조건 비교는 **알고리즘을 고정해 입력 처리의 차이를 보는 실험**이다. 여러 전처리 조건이나 확률 보정법을 서로 다른 분류기 3종으로 세면 안 된다. 다른 알고리즘보다 LightGBM이 우수하다는 실험적 결론도 아직 아니다. 오늘의 Ames 회귀 비교 결과를 Airplane 분류 비교의 근거로 옮기지 않는다.

### 4.3 날씨의 “10분 지연”은 무엇인가?

이 값은 항공편이 10분 늦어진다는 가정이 아니라 **관측 정보가 사용 가능해지기까지의 지연 가정**이다.

- 관측 시각과 예측 시각, 가정한 가용 시각을 구분한다.
- 가정한 가용 시각이 예측 시점보다 뒤인 정보를 넣지 않는다.
- 이것만으로 항공사가 관측 후 일정을 변경해서 지연됐다는 인과 경로를 가정하거나 검증한 것은 아니다.
- 실제 운항 중 악천후의 인과 영향을 따로 검증한 것도 아니다. 예측 시점 이후에 알게 된 실제 관측값을 사전 예측 입력으로 넣을 수는 없다.
- 가정 아래 시각 위반이 없다는 검사와 실제 과거 수신 이력 확인은 다르다. 결합률 민감도 분석과 모델 성능 강건성 검증도 구별한다.

오늘 공개 저장소에 보존한 피드백 인계는 **문서 정리**다. 기존 집계로 보완할 수 있는 표와 새 알고리즘 비교 실험을 구분했으며, 새 학습·성능 검증을 완료한 것으로 기록하지 않는다.

## 5. 아직 헷갈리는 것 / 다음에 확인할 것

- 단일 트리의 분할을 출발점으로, 서로 독립적으로 평균내는 배깅과 오차를 순차 보완하는 부스팅을 작은 예제로 다시 설명해 보기.
- RF 실습의 실제 특성 선택 설정과 OOB 출력 확인. 저장 출력이 없는 셀을 실행 완료로 간주하지 않기.
- CV 탐색·단계 선택·최종 테스트가 어디에서 분리되는지 노트북의 데이터 흐름으로 점검하기.
- Airplane의 서로 다른 분류기 비교는 후속 실험 후보다. 현재 문서에 있는 결과와 앞으로 실행할 작업을 구분하기.
