## 1. 오늘 배운 것

### Claude Code 세션 압축은 고정 주기보다 맥락과 보존 기준이 중요하다

- `/context`로 컨텍스트 사용 상황을 확인하고, `/compact`는 기존 작업을 이어 가기 위해 대화의 앞부분을 요약한다. `/clear`는 이전 작업과 분리해 새 작업을 시작할 때 사용한다.
- 자동 압축은 모델과 세션의 컨텍스트 한도에 따라 발생한다. 모든 작업에 적용되는 하나의 적정 압축 주기가 공식적으로 정해져 있는 것은 아니다. 컨텍스트가 커졌거나 하나의 작업 단계가 끝났을 때를 기준으로 판단한다.
- 압축 요약에서는 실험 설정, 정확한 수치, 실패 원인, Git 상태, 미완료 작업 같은 세부 정보가 빠질 수 있다. 목표·제약·파일 경로·커밋·검증 결과·실패·다음 작업은 저장소 문서나 인계 기록처럼 세션 밖에서도 확인할 수 있는 곳에 남긴다.
- 이번 대화에서 정리한 운영안은 **컨트롤 타워 세션은 필요할 때 압축하고, 하위 작업 세션과 그 결과는 보관하는 방식**이다. 이는 사용자의 작업 방식에 맞춘 운영 제안이지, 공식 규칙이나 실제 세션에서 검증한 결과는 아니다.
- 압축 1회당 비용 절감 또는 추가 비용을 하나의 고정값으로 단정하지 않는다. 실제 사용량은 도구의 사용량 표시와 해당 계정·모델의 과금 기준으로 확인해야 한다.

### NXT 수능일 거래시간은 날짜별 임시 공지를 확인해야 한다

- 넥스트레이드의 2025년 11월 13일 수능일 공지는 2025년 10월 30일 게시됐다. 해당 날짜에는 **프리마켓을 운영하지 않았고**, 메인마켓은 10:00:30~16:20, 애프터마켓은 16:40~20:00으로 안내됐다.
- 프리마켓 미운영은 단순히 전체 거래가 한 시간씩 밀렸다는 뜻이 아니다. 시장별 운영 여부와 시작·종료 시각을 각각 확인해야 한다.
- 이 시간표는 2025년 해당일의 임시 변경이다. 2026년 수능일에도 그대로 적용된다고 가정하지 않는다. 대화에서 KRX의 정확한 거래시간은 별도로 확인하지 못했다.

## 2. 내가 궁금했던 질문과 이해한 답

### 압축은 얼마나 자주 해야 할까?

매번 같은 대화 길이나 일정한 시간 간격을 기준으로 삼기보다, 컨텍스트 사용량과 작업의 논리적 경계를 함께 본다. 압축 전에 현재 상태를 기록하고, 압축 후 요약에 핵심 결정과 미완료 항목이 남았는지 확인하는 것이 중요하다.

### 컨트롤 타워와 하위 세션은 어떻게 관리할까?

컨트롤 타워는 전체 방향과 의사결정을 이어 가도록 압축할 수 있지만, 하위 세션의 원문·실행 결과·검증 자료는 보관한다. 세션 요약을 프로젝트의 유일한 진실 공급원으로 삼지 않고 Git 커밋, 보고서, 실험 데이터와 테스트 결과를 기준 자료로 유지한다.
