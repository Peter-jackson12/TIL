### 문제 → 해결: `.pth`로 패키지를 빌려 쓰던 venv가 정리 작업 뒤 깨졌다

- **문제:** 월요일 07:3x 수집 콘솔 시작이 `No module named streamlit`으로 실패했다. 운영 콘솔·수집기 venv 4개가 자기 패키지 없이 `development_dependencies.pth`로 다른 worktree의 `.venv/Lib/site-packages`를 빌려 쓰고 있었는데, 전날 worktree 정리에서 그 worktree가 휴지통으로 갔고 휴지통도 비워졌다. 정리 전 참조 검사는 `.pth` 파일을 보지 않았다.
- **해결:** 같은 경로에 같은 uv·CPython으로 venv를 새로 만들고, 운영 checkout의 `uv.lock`에서 뽑은 목록을 해시 검증으로 설치했다. 설치 뒤 `pip freeze` 75개가 9월에 남겨 둔 freeze 기록과 완전히 일치했고, 07:44 콘솔이 정상 기동해 그날 수집이 진행됐다.

```bash
uv export --locked --group dev --no-emit-project -o requirements-locked.txt
uv pip install --require-hashes -r requirements-locked.txt
```

(복구 기록에 적힌 명령의 요지다. 대상 venv 지정 등 정확한 인자는 생략했다.)

- **재발 방지:** 그 폴더는 "운영 의존 — 지우지 않음"으로 표시했고, 남은 정리 전에 `.pth`·venv 참조 검사를 추가하기로 했다. 휴지통을 바로 비우지 않았다면 폴더를 되돌리는 것으로 끝났을 것이다.

### 진입 신호가 실패한 이유: 비용 장벽 vs 신호 뒤 가격 이동

10/18의 결론(청산이 아니라 진입이 문제)에 이어 노트북에서 진입 신호의 비용 전 우위만 따로 탐색했다. 작업표에 기록된 집계는 다음과 같다(구체 조건·파라미터는 생략).

| 항목 | 기록 |
|---|---|
| 학습 날짜의 신호 뒤 mid 가격 이동 | 약 −1 ~ −3bp |
| mid 기준 비용 장벽 | 수수료·세금 약 23bp + 호가 차이 약 9bp ≈ 32bp |
| 이상적 지정가(양쪽 maker 체결 가정) | 약 +4~6bp 개선에 그침 |
| 구조 탐색 후 동결 10개 검증 | 전부 실패 |
| 사전 고정 30칸(고정 보유 + 추적 손절) 1회 개봉 | 30칸 모두 실패 |
| 추적 손절 vs 같은 조건 고정 600초 | 손실은 줄지만 여전히 음수 |

- 신호 뒤 이동이 0 근처인데 장벽이 32bp면, 주문 방식이나 청산 규칙 개선으로 메울 수 있는 거리가 아니다.
- 이 탐색 트랙에서 같은 검증일 2일을 단계마다 다시 써서 4회째 사용이 됐다. 결과를 본 날짜로 다음 후보를 고르면 그 날짜는 사실상 학습 데이터가 된다. 그래서 다음 주부터 새 날짜를 주 단위로 탐색 풀/검증 풀에 미리 번갈아 배정하고, 검증 풀은 노트북으로 보내지 않기로 했다.
