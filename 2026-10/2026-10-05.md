## 1. 오늘 정리한 것

발표 전에 README를 더 깊게 이해하고 싶어 프로젝트 안에 한국어 해설 문서를 요청했다. 오늘은 새 모델 실험보다 **기존 결과를 왜 그렇게 해석해야 하는지**를 정리하는 날이었다. 아래 내용은 새로 작성된 공개 해설본을 바탕으로 한 복습이며, 이해 완료나 발표 리허설 완료를 뜻하지 않는다.

### 전처리의 타당성과 점수 개선은 별개다

- 결측을 모두 채웠다고 더 정확한 데이터가 되는 것은 아니다. 여러 값이 가능한 경우에는 모르는 상태를 보존하는 편이 의미상 타당할 수 있다.
- 관측값, 규칙으로 추정한 값, 여전히 모르는 값을 구분해야 한다.
- 잘못된 의미를 고친 전처리와 예측 정보를 새로 추가한 변경은 다른 질문이다. 전처리 수정의 가치가 있다고 해서 성능 향상까지 자동으로 입증되는 것은 아니다.

### 타깃 인코딩은 정답을 쓰는 전처리다

타깃 인코딩(TE)은 범주별 정답 평균을 수치로 표현한다. 표본이 적은 범주의 극단값은 학습 집단 평균 쪽으로 평활할 수 있다.

중요한 것은 계산식보다 **어느 데이터의 정답을 사용했는가**다. 검증행의 정답이 인코딩에 들어가면 모델 학습 전에 이미 정답 정보가 새어 들어간다. 해설본의 현행 경로는 내부 분할 후 학습 라벨로 검증용 TE를 만들고, 학습행 자체도 교차 인코딩으로 자기 정답의 직접 유입을 피한다.

### 모델 선택과 최종 채점을 분리한다

Airplane의 현행 절차는 외부 교차검증 안에 내부 holdout을 둔다.

1. 내부 학습 데이터로 후보 모델을 학습한다.
2. 내부 holdout의 LogLoss로 트리 수를 고른다.
3. 내부 holdout의 Macro F1으로 분류 임계값을 고른다.
4. 선택된 모델과 임계값을 외부 검증행에 적용해 최종 채점한다.

여기서 nested selection은 반드시 내부 K-fold 전체를 수행한다는 뜻이 아니다. 이 프로젝트는 **내부 holdout 선택**이며, 선택 후 외부 학습 데이터 전체에 재학습하는 방식도 아니다. 명칭만 보고 실제 실행 절차를 추정하지 않고 코드와 기록을 함께 읽어야 한다.

### OOF는 단일 배포 모델의 예측이 아니다

OOF(out-of-fold)는 각 행을 외부 학습에 쓰지 않은 모델의 검증 예측을 모은 것이다. 이 프로젝트는 외부 fold 예측을 합친 뒤 시드별 지표를 계산한다.

F1은 비선형이므로 **fold별 F1의 단순 평균과 전체 OOF를 모아 계산한 F1은 일반적으로 다르다.** 여러 시드의 결과를 반복해서 얻었더라도 독립된 새 데이터셋을 여러 개 확보한 것은 아니다. 시드 간 표준편차를 미래 성능의 신뢰구간이나 유의성 검정 결과로 바꾸어 말하지 않는다.

## 2. 발표 준비 질문과 해설에서 확인한 답

**질문: “README를 발표하기 전에 더 깊게 이해하려면 무엇을 설명할 수 있어야 할까?”**

지표 숫자만 외우기보다 다음 세 가지를 연결하는 것이 중요하다.

- **무엇을 비교했나:** 같은 평가행·분할·모델 선택 규칙인지 확인한다.
- **무엇이 달라졌나:** 입력 정보 추가와 평가 집단 변경이 섞이지 않았는지 확인한다.
- **어디까지 결론 낼 수 있나:** 정적 교차검증, 선택된 집단, 입력 가용성 가정의 범위를 말한다.

날짜가 확인된 부분집단에서 날씨 사용 모델을 평가했다면, 예전의 더 큰 집단에서 얻은 기준 점수를 그대로 빼면 안 된다. **새 집단에서 날씨 미사용 조건도 다시 평가해야** 집단 변화와 입력 추가를 구분할 수 있다.

같은 조건이라는 말도 최종 트리 수와 임계값이 무조건 같다는 뜻은 아니다. 같은 후보·선택 규칙을 적용하면서 각 조건의 내부 데이터로 설정을 고를 수 있다. 이때 비교 대상은 정보 추가를 허용한 전체 학습 절차다.

**질문: “과거 관측이면 예측에 써도 되는가?”**

관측 시각과 실제 이용 가능 시각은 다르다. 예측 전에 관측됐어도 발표·수신이 늦었다면 그 시점에는 사용할 수 없다. 가용 시각을 실제 이력으로 확인한 것인지, 지연을 가정한 것인지 구분해야 한다. 정답 누수를 줄인 평가도 미래 운영 환경의 검증을 대신하지 않는다.
