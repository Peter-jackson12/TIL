## 1. 문제 인식 (Problem Recognition)

### ① 구매 예측 모델 파이프라인 구축 및 트리 모델의 기하학적 이해
- **전처리 파이프라인의 필요성:** 수치형 변수(중앙값 대체 + 정규화)와 범주형 변수(최빈값 대체 + One-Hot Encoding)를 분리하여 처리하고 모델 학습까지 이어지는 일관된 흐름(Pipeline)이 필요했다.
- **Tree 모델의 단조 변환 불변성:** 왜 $y=ax^2$ 같은 비선형 데이터에서 트리는 로그 변환이나 다항식 추가 없이도 계단형 분할(Step Function)을 통해 비선형 곡선을 스스로 추정해 내는지 내부 원리 이해가 요구되었다.

### ② 분류 모델의 비즈니스 임계값(Threshold) 최적화
- 단순히 기본 임계값(0.5)에서 도출된 Accuracy만으로는 마케팅 캠페인의 실질적 ROI를 대변할 수 없었다.
- False Positive(메시지 발송 비용 낭비)와 False Negative(잠재 구매고객 기회 손실) 사이의 트레이드오프를 계량화하여 최적의 Threshold를 찾는 방법론이 필요했다.

### ③ 로컬 AI 에이전트(Cline + Ollama) 환경 통신 에러
- VS Code의 Cline 익스텐션에 로컬 모델(`qwen2.5-coder:7b`)을 연결했을 때, `does not support thinking` 오류와 OpenAI API 키 결제 요구 에러가 혼재되어 발생하며 자율 에이전트(Act Mode)가 뻗어버리는 문제가 발생했다.

## 2. 직접 코드 실험 (Direct Code Experiment)

### ① Scikit-Learn 전처리 및 모델링 파이프라인 통합
```python
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler
from sklearn.impute import SimpleImputer
from sklearn.linear_model import LogisticRegression

# 1. 피처 스플릿
numeric_features = ['Age', 'VisitCount', 'AveragePurchaseAmount', 'TotalPurchaseAmount', 'SatisfactionScore', 'Recency', 'TenureDays']
categorical_features = ['Gender', 'Region', 'MembershipLevel', 'CouponUsed', 'PreferredCategory', 'AgeGroup', 'PurchaseGrade']

# 2. 전처리기 구성
preprocessor = ColumnTransformer(
    transformers=[
        ('num', Pipeline([
            ('imputer', SimpleImputer(strategy='median')),
            ('scaler', StandardScaler())
        ]), numeric_features),
        ('cat', Pipeline([
            ('imputer', SimpleImputer(strategy='most_frequent')),
            ('ohe', OneHotEncoder(drop='first', sparse_output=False, handle_unknown='ignore'))
        ]), categorical_features)
    ]
)

# 3. 모델 파이프라인 (L2 규제 0.1 및 클래스 가중치 보정)
improved_model = Pipeline([
    ('prep', preprocessor),
    ('clf', LogisticRegression(C=0.1, class_weight='balanced', random_state=42, max_iter=1000))
])
```

## 3. 트러블슈팅 및 해결 (Troubleshooting & Resolution)

### Issue 1: 로컬 Ollama 모델(`qwen2.5-coder:7b`) Cline 연동 시 `does not support thinking` 및 API 에러
* **원인:** Cline이 Plan 모드 혹은 Thinking 예산이 설정된 상태에서, 추론(Thinking)을 지원하지 않는 코딩 전용 로컬 모델을 강제 호출하여 내부 충돌이 발생함. 또한 Provider 설정 누락 시 디폴트로 OpenAI 실제 서버로 토큰을 요청하여 결제 차단됨.
* **해결:** 
  1. API Provider를 `Ollama` 대신 **`OpenAI Compatible`**로 우회 설정.
  2. Base URL을 `http://127.0.0.1:11434/v1` (끝에 `/v1` 필수 추가)로 지정하고 임의의 API Key(`ollama`) 입력.
  3. 설정에서 `Reasoning Effort`를 **None/Disabled**로 끄고, 반드시 기존 에러가 남은 채팅창 대신 **Start New Task(새 작업)**로 캐시를 리셋하여 해결.

### Issue 2: 단일 Decision Tree의 과적합(Overfitting) 착시 현상
* **원인:** `max_depth=4`인 단일 트리가 $y=x^2$ 형태의 과거 100개 데이터 노이즈까지 모두 계단으로 쪼개버리면서(16개 노드 분할) Train MSE는 우수하게 찍힘.
* **해결:** Out-of-Sample 미래 데이터 1,000개를 투입하여 Test MSE를 비교. 최소 분할 제한(`min_child_samples=20`) 등 기본 규제가 탑재되어 노이즈를 스무딩 처리하는 **LightGBM** 앙상블 모델이 실전 일반화 성능에서 압도적임을 시각화로 교차 검증함.

## 4. 퀀트 & 통계학적 인사이트 (Key Takeaways)

### 1. 회귀분석(Regression)과 선형계획법(OR)의 퀀트 분업 아키텍처
* 머신러닝/회귀분석은 **"과거 데이터로 미래 자산의 초과수익(Alpha)을 예측"**하는 재료 생성 역할을 한다.
* 반면 산업공학의 심플렉스/선형계획법(OR)은 **"도출된 수익률을 바탕으로 최대 비중 30%, 공매도 금지 등 제약조건(Constraints) 하에서 포트폴리오 샤프지수를 최적화"**하는 의사결정(Action) 역할을 수행한다. 두 수학적 도구는 대체재가 아닌 보완재다.

### 2. 트리 모델(Tree Ensemble)의 실무적 강력함 (단조 변환 불변성)
* 트리 모델은 선형 모델과 달리 수학 공식을 찾지 않고 데이터 정렬 순서 기반으로 '칼질(Split)'을 수행한다.
* 시가총액 500조 짜리 극단적 이상치가 들어와도 단순히 `if 시총 > 10조`라는 맨 끝단 노드 하나로 분류해버리므로 이상치에 면역이며, 로그 변환(Log Transform) 여부에 상관없이 완벽하게 동일한 구조를 학습한다.

### 3. F1-Score와 비즈니스 비용의 트레이드오프
* 임계값(Threshold)을 내리면 정밀도(Precision)는 떨어지지만 재현율(Recall)이 상승한다. 
* 마케팅 발송 비용(수십 원) 대비 구매 시 기대 수익(수만 원)이 압도적으로 큰 이커머스 도메인에서는, 오발송 리스크(FP)를 감수하더라도 잠재 구매자를 놓치는 기회비용(FN)을 최소화하기 위해 **임계값을 0.4 수준으로 보수적으로 하향 세팅하는 것이 수학적으로 유리하다.**
