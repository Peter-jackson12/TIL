## 1. 문제 인식 (Problem Recognition)

### ① 탐색 알고리즘과 데이터베이스 인덱스의 아키텍처적 연결
- **이분 탐색(Binary Search)의 본질:** 정렬(Sorted)된 데이터셋에서 매 단계마다 탐색 범위를 절반씩 소거하는 $O(\log N)$ 알고리즘의 원리를 코딩테스트 구현을 통해 체득했다.
- **B+Tree DB 인덱스로의 확장:** RDBMS가 왜 해시 테이블($O(1)$) 대신 B+Tree($O(\log_M N)$)를 인덱스로 쓰는지, 그리고 리프 노드의 연결 리스트(Linked List)가 어떻게 범위 검색(Range Scan, `BETWEEN`)을 $O(\log N + K)$로 가속하는지 시스템 디자인 관점에서 연결했다.

### ② 원-핫 인코딩(One-Hot Encoding)과 경사하강법(Gradient Descent)의 수학적 필연성
- 단순히 "문자형 데이터를 숫자로 바꾼다"는 차원을 넘어, **선형대수의 직교 기저 벡터(Orthogonal Basis Vector)**와 **경사하강법 미분 연쇄 법칙(Chain Rule)** 관점에서 왜 원-핫 인코딩이 필수적인지 파헤쳤다.
- 범주형 데이터를 단순 정수($1, 2, 3$)로 매핑하면 미분 기울기($\frac{\partial L}{\partial w} = \text{오차} \times x$)가 인위적인 숫자 크기에 비례해 뻥튀기(기울기 왜곡)되어 가중치 학습이 붕괴됨을 수학적으로 확인했다.
- 또한 OR(선형계획법)의 심플렉스(Simplex Tableau, 꼭짓점 탐색)와 머신러닝의 경사하강법(Gradient Descent, 곡면 하강)의 본질적 차이를 정리했다.

### ③ 단순 선형회귀(OLS)에서 잔차의 합($\sum e_i = 0$)과 잔차 제곱합(SSE)의 필연성
- OLS 회귀식이 데이터의 무게중심점($\bar{x}, \bar{y}$)을 반드시 관통하기 때문에, 잔차의 단순 합은 항상 수학적으로 정확히 $0$으로 상쇄된다는 사실을 검증했다.
- 따라서 모델 성능 평가는 분산(Variance)과 마찬가지로 **잔차 제곱합(SSE) ➔ MSE ➔ RMSE**로 부호를 없애고 큰 오차에 페널티를 부여해야 함을 증명했다.

### ① OLS 선형회귀의 3대 패러다임 구현 (NumPy pinv vs Sklearn vs PyTorch)
```python
import numpy as np
import torch
from torch import nn
from sklearn.linear_model import LinearRegression

# 1. 데이터 생성 및 절편(Bias) 열 [1, x] 결합
X_raw = np.array([[10], [20], [30], [40], [50]], dtype=np.float32)
y_raw = np.array([[25], [45], [65], [85], [105]], dtype=np.float32)
bias_term = np.ones((len(X_raw), 1), dtype=np.float32)
X_concat = np.concatenate([bias_term, X_raw], axis=1)

# 2. NumPy 정규방정식 (무어-펜로즈 의사역행렬 pinv로 Singular Matrix 방어)
w_np = np.linalg.pinv(X_concat) @ y_raw
print(f"NumPy OLS -> 절편: {w_np[0, 0]:.4f}, 기울기: {w_np[1, 0]:.4f}")

# 3. Scikit-learn (fit_intercept=True 기본값이므로 raw X 투입)
sklearn_model = LinearRegression().fit(X_raw, y_raw)
print(f"Sklearn   -> 절편: {sklearn_model.intercept_[0]:.4f}, 기울기: {sklearn_model.coef_[0, 0]:.4f}")

# 4. PyTorch SGD (bias_term이 이미 0번 열에 있으므로 bias=False 설정)
torch_model = nn.Linear(2, 1, bias=False)
optimizer = torch.optim.SGD(torch_model.parameters(), lr=1e-3)
criterion = nn.MSELoss()

for _ in range(5000):
    optimizer.zero_grad()
    loss = criterion(torch_model(torch.tensor(X_concat)), torch.tensor(y_raw))
    loss.backward()
    optimizer.step()

params = list(torch_model.parameters())[0].detach().numpy()
print(f"PyTorch   -> 절편: {params[0, 0]:.4f}, 기울기: {params[0, 1]:.4f}")
# 결과: 수학적 OLS(NumPy), 라이브러리(Sklearn), 딥러닝(PyTorch)이 완전히 동일한 계수로 수렴함
```

### ② EDA 전처리 & One-Hot Encoding (Dummy Variable Trap 방지)
```python
import pandas as pd
from sklearn.preprocessing import StandardScaler

# 범주형 변수의 drop_first=True 적용 (다중공선성 방지)
df = pd.DataFrame({
    'age': [25, 45, 30, 55],
    'smoker': ['yes', 'no', 'no', 'yes'],
    'region': ['southwest', 'southeast', 'northwest', 'northeast'],
    'charges': [16884, 1725, 4449, 21984]
})

# 원-핫 인코딩: 고유값 N개 중 N-1개 열만 남겨 공선성 제거
encoded_df = pd.get_dummies(df[['smoker', 'region']], drop_first=True, dtype=int)
scaler = StandardScaler()
scaled_age = scaler.fit_transform(df[['age']])

final_df = pd.concat([pd.DataFrame(scaled_age, columns=['age_std']), encoded_df], axis=1)
final_df['charges'] = df['charges'].values
print(final_df.head(2))
```

## 3. 트러블슈팅 및 해결 (Troubleshooting & Resolution)

### Issue 1: Matplotlib 윈도우 한글 폰트 누락 경고 (`Glyph missing from DejaVu Sans`)
* **원인:** Matplotlib의 기본 폰트(`DejaVu Sans`)가 한글 유니코드를 지원하지 않아 주피터 노트북 시각화 시 한글이 네모(□)로 깨지고 경고가 대량 발생함.
* **해결:** 시각화 코드 최상단에 `plt.rcParams['font.family'] = 'Malgun Gothic'` 및 `plt.rcParams['axes.unicode_minus'] = False`를 명시하여 윈도우 시스템 폰트로 바인딩함.

### Issue 2: OLS 역행렬 계산 시 Singular Matrix(역행렬 부존재) 에러 방지
* **원인:** 피처 간 다중공선성이 존재하거나 데이터 행렬 $X^T X$의 행렬식이 0에 가까울 때 `np.linalg.inv`는 런타임 크래시를 유발함.
* **해결:** SVD(특이값 분해) 기반의 **무어-펜로즈 의사역행렬(`np.linalg.pinv`)**을 사용하여 수치적 안정성을 100% 확보함.

### Issue 3: PyTorch 최신 CUDA 빌드 호환성 (RTX 5060 Blackwell)
* **상황:** 시스템 드라이버의 최대 지원 CUDA(13.1)와 PyTorch CUDA(13.0, `cu130`)를 `uv`로 설치.
* **검증:** `torch.cuda.is_available() -> True`, `RTX 5060 Laptop GPU` 인식을 확인. 
* **`uv` 캐시 최적화:** `uv`의 글로벌 캐시(`%LOCALAPPDATA%\uv\cache`) 및 하드링크(Hardlink) 구조 덕분에 프로젝트 가상환경(`.venv`)마다 2GB 패키지를 중복 다운로드하지 않고 즉시 재사용할 수 있음을 확인.

## 4. 퀀트 & 통계학적 인사이트 (Key Takeaways)

### 1. OLS 회귀선과 잔차의 기하학적 성질 ($\sum e_i = 0$)
* OLS의 정규방정식은 회귀선이 표본의 평균점 $(\bar{x}, \bar{y})$을 반드시 지나도록 유도된다.
* 따라서 양수 오차와 음수 오차의 단순 합은 언제나 정확히 0이 된다. 성능 평가 시 단순 합을 버리고 **잔차 제곱합(SSE)**을 채택해야만 오차의 절대 크기를 측정하고 큰 오차에 강한 페널티를 줄 수 있다.

### 2. 원-핫 인코딩이 경사하강법을 보호하는 메커니즘
* 경사하강법은 입력 $x$가 가중치 기울기 공식에 직접 곱해진다 ($\nabla_w L \propto x$).
* 명목형 범주를 정수($1, 2, 3$)로 두면 $x=3$인 클래스가 $x=1$인 클래스보다 3배 과도한 보폭으로 업데이트되어 모델이 심각하게 편향된다. 원-핫 인코딩($x \in \{0, 1\}$)을 적용해야만 **각 범주별 가중치가 독립적이고 공평하게 1보씩 학습**된다.

### 3. 고성능 퀀트 플랫폼 포트폴리오의 설계 원칙
* **전략 은닉 & 시스템 엔지니어링 집중:** 핵심 알파는 보호하되, "초봉/LOB 호가잔량 파이프라인 + CPU 멀티프로세싱 가속 + 인터랙티브 튜너 + REST/WebSocket 실거래 어댑터"라는 **End-to-End 시스템 아키텍처**를 면접관에게 증명하는 것이 시니어급 퀀트 포트폴리오의 정석이다.
