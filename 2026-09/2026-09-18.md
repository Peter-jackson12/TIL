### 1.1 Airplane: 공항-관측소 매핑의 "현재 정보"와 "당시 정보"는 다르다

**문제.** 기존 파이프라인(`map_weather_stations.py`)은 IEM 관측소 메타데이터의 **현재** 정보만으로 375개 공항을 매핑했다. 이 중 20개(시간대 충돌 8곳 + 식별자 미확인 9곳 + 관측 기간 미달 3곳)는 "2018~2019년 조사 대상 기간에도 이 매핑이 맞았는지"가 검증되지 않은 상태였다.

**실험.** NOAA/NCEI HOMR(공식 관측소 이력 DB)를 20개 공항 각각에 대해 조회해 원자료를 저장하고 SHA-256 해시로 무결성을 남겼다. 이 결과를 기존 IEM 캐시(`data/weather_probe/networks/*.geojson`)와 교차 대조해 식별자 불일치의 원인을 하나씩 규명했다.

**해결/확인된 결과.**

| 유형 | 결과 |
| --- | --- |
| ISN → XWA | HOMR 공식 기록에 "기후학적으로 호환 불가능한 이전"이라 명시 — 진짜 시설 이전으로 확인 |
| YUM | "YUM"(2007년 폐쇄된 옛 기상청 사무소)과 "NYL"(실제 공항, 1960~현재)이 2.3km 떨어진 **별개 시설**이었다. 파이프라인 코드가 identifier를 동일 시설로 가정한 버그 후보를 발견 |
| 식별자 불일치 8/9 | AZA·BKG·FCA·HHH·MQT·PBI·SCE·USA는 IATA 코드가 아닌 다른 ID로 이미 IEM에 등재돼 있었다(FCA→GPI는 2005-10-25 개명 기록까지 확인) |
| PBI (사이드 발견) | 현재 IEM/NOAA 기록상 공식 명칭이 "Donald J. Trump International Airport"로 바뀌어 있다. 2018~2019년 조사 당시는 "Palm Beach International"이었고, 개명은 조사 기간 이후 사건이라 데이터 라벨링에는 영향 없음 |
| SPN(사이판) | HOMR상 관측소는 존재하지만 파이프라인이 쓰는 IEM 캐시엔 없다. "자료 없음"이 아니라 "파이프라인 수집 공백"으로 재확인, 미해결 |
| STT/STX | 시간대 문자열 충돌은 정황 증거만 확보(버진아일랜드 서머타임 미적용). 등급은 보수적으로 유지 |

증거표(CSV, 20행, 출처 URL·SHA-256 포함) + manifest + 재현 가능한 검증 스크립트(`notebooks/verify_priority_station_identity.py`)를 산출물로 남겼다. README를 갱신했고, 기존 매핑표·캐시·테스트는 건드리지 않아 354개 테스트가 그대로 통과했다. 커밋 `fb2e830`으로 반영했다.

**배운 점.** IEM의 "현재 목록"과 "당시 유효했던 기록"은 다르다는 것을 YUM 사례로 실제 확인했다 — 겉보기엔 같은 IATA 코드라도 물리적으로 다른 관측소를 가리킬 수 있다. 또한 HOMR 같은 공식 소스의 자유 텍스트 remark를 읽고 "이전 vs 개명 vs 장비 교체"를 판단하는 것은 자동화가 어려운 analyst judgment 영역이다. 스크립트는 fetch·hash 같은 수집만 자동화하고, 판단 자체는 사람이 근거와 함께 기록해야 한다.

### 1.2 Stock: "테스트 통과" 보고와 실제 코드 계약은 다를 수 있다

**문제.** 이전 세션이 "애프터마켓 전환 완료, 테스트 813개 통과"라고 보고했다. 이 보고를 그대로 믿지 않고 코드를 직접 대조했다.

**실험/확인.** 대조 결과 다음과 같은 실결손이 드러났다.
- `aftermarket_plan`이 `duration_seconds`를 검증하지 않았고, 계획 모드엔 정규장 15:35 종료 조건조차 없어 전환 후 종료 조건이 사실상 전무했다.
- 전환 후에도 정규장 `SessionMonitor`가 살아 있어 애프터마켓 프로필이 적용되지 않을 수 있는 버그가 있었다.
- `note_first_event_after()`가 운영 연결 경로에서 실제로 호출되지 않아, "전환 후 수신 공백"을 측정하지 못하고 있었다.

**해결(07:46, `dbc2a7e`).**
- 필수 파라미터 `aftermarket_duration_seconds(1~300)`를 추가했다.
- 타이머 시작 기준을 "기존 로그인 시각"에서 "구독 성공 시점"으로 바꿨다. 로그인 시각 기준으로는 전환 시점에 이미 타이머가 만료돼 있을 수 있기 때문이다.
- 전환 스키마를 `session_transition_v1 → v2`로 올려 전환 식별자·세션 ID·코드 리비전·단계별 단조/UTC/KST 시각을 함께 기록하도록 했다.
- `note_first_event_after()`를 콜백 경로에 실제로 연결했다.
- 정규장 `SessionMonitor`가 전환 후에도 살아있던 버그를 수정했다.
- 합성 테스트 13개를 추가해 전체 1008 → 1021개 통과를 확인했다.

**배운 점.** "테스트 통과" 또는 "완료" 표시만으로 실제 동작을 확정하지 말고, 실제 코드 계약(파라미터 검증, 종료 조건, 콜백 연결 여부)을 직접 대조해야 한다.

**배운 점.** 이력 재작성처럼 되돌리기 어려운 작업은 사전 백업과 명시적 승인 조건을 먼저 문서화해두면 이후 실수를 방지하는 데 도움이 된다.
