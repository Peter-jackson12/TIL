## 1. 오늘 배운 것

### 1.1 독립 검증은 결과를 보기 전에 조건을 고정해야 한다

Stock에서는 과거의 별도 세션을 independent actual input으로 사전등록하고 Windows 환경에서 source protection, frozen snapshot, bounded prefix, selected input, replay/accounting 순서로 확인했다.

검증은 미리 정한 날짜·구간·입력 정책을 결과에 맞춰 다시 바꾸지 않는 방식으로 진행됐다. 해당 입력은 구조 검증과 selected input 검증을 통과했고, replay도 정해진 횟수만 수행했다.

핵심은 **파이프라인이 재현 가능하게 통과했다는 사실과 그보다 강한 연구·운영 주장을 분리하는 것**이다. 별도 입력에서 같은 경로가 성립했다는 증거는 얻었지만, 그것만으로 전체 데이터 품질이나 일반화된 연구 결과, 실제 운영 적격성을 승인하지 않았다.

### 1.2 실제 데이터 회귀와 탐색은 분리해야 한다

기존 selected input fixture를 새 accounting / provenance 코드로 다시 확인한 회귀도 PASS로 정리됐다. 목적은 코드 변경 뒤 execution trace와 accounting identity가 유지되는지 보는 것이다.

별도 development set에서 여러 설정을 탐색한 작업도 있었지만, 탐색 결과와 이후 독립 검증 입력은 분리했다. 후속 검증에서는 탐색 결과를 본 뒤 입력이나 설정을 계속 바꾸지 않도록 사전등록 규칙을 먼저 고정했다.

이 과정을 통해 **development 결과는 후보를 만드는 데 쓰고, 독립 검증은 그 후보를 다시 선택하는 데 쓰지 않는다**는 원칙을 확인했다.

### 1.3 잘못된 실행 조건은 부작용 전에 fail-closed 해야 한다

Stock PR #55에서는 NXT portfolio runner의 `close_ns`를 output 생성이나 input iteration보다 먼저 positive exact-int로 검증하도록 보강했다.

수정 전 신규 회귀는 9 failed로 문제를 재현했고, 수정 후 9 passed, focused 101 passed, documentation 27 passed를 기록했다.

잘못된 조건에서 파일이나 중간 상태를 만들기 전에 거부하면 재현성과 운영 안전성이 높아진다.

### 1.4 운영 UI는 상태 확인과 실행 권한을 분리해야 한다

오늘 Stock Operator에는 읽기 전용 환경 점검, preflight, `review_only` Run Plan, Windows shortcut 진입점이 정리됐다.

사용자 Windows에서 `.\stock.cmd ui`로 기존 Streamlit 화면이 열리는 것과 `Stock Operator` 바로가기를 더블클릭해 같은 UI에 진입하는 것을 실제 확인했다.

다만 이 검증은 UI 진입점에 한정된다. collector 로그인, 실제 수집, 시장 상태, 데이터 품질, 실행 승인을 인증하지 않는다. Run Plan도 queue/worker/launch token이나 managed capture와 연결되지 않은 review-only 계약이다.

### 1.5 Career System도 production 전에 audit와 shadow path를 둔다

career-agent PR #31의 **Search Discovery Audit 01**은 main에 병합됐다.

이 기능은 URL 기반 discovery를 production에 바로 연결하지 않고 file-only 입력으로 먼저 평가한다. canonical dedup과 incremental useful origin URL 집계를 제공하지만 DB/network/application submission은 하지 않는다.

PR #31 CI는 Ubuntu **640 passed, 1 skipped**, Windows **641 passed**로 성공했고 Ruff, format, tracked-file guard, installed-wheel smoke도 통과했다.

이어 PR #32에서는 role-first **Matcher V2 shadow routing**이 checkpoint로 열렸다.

- local full suite: 680 passed, 1 skipped
- frozen 49-user-label shadow regression 재현
- canonical 80-job shadow run 재현
- canonical DB와 application state 미변경
- GitHub CI #93 성공

PR #32는 기록 시점에 **open/unmerged**다. production Matcher V1의 weight와 threshold, 기본 match/shortlist 동작은 그대로 유지된다.

## 2. 확인된 것과 아직 확인하지 않은 것

### 확인된 것

- 별도 historical actual input에서 source protection부터 replay/accounting까지 정해진 검증 경로를 다시 수행했다.
- 기존 selected input의 actual accounting regression이 PASS로 정리됐다.
- 개발용 탐색과 이후 독립 검증을 분리하는 사전등록 규칙을 문서화했다.
- Stock Operator UI와 Windows shortcut 진입은 사용자 PC에서 실제 확인됐다.
- Career Search Discovery Audit 01은 PR #31로 병합됐고 CI가 성공했다.
- Matcher V2 shadow PR #32는 local regression과 GitHub CI가 성공한 open checkpoint다.

### 아직 완료하지 않은 것

- 개발용 탐색 결과를 일반화된 성능으로 해석하지 않는다.
- Stock 전체 데이터 적격성과 실제 운영 적격성은 승격되지 않았다.
- Operator UI/preflight/Run Plan은 실제 collector 실행 승인이 아니다.
- Search Discovery Audit 01에는 실제 외부 검색 provider 호출이 아직 없다.
- Matcher V2 PR #32는 production 전환도 main 병합도 아니다.

## 3. 오늘의 핵심 정리

오늘의 공통 원칙은 **탐색·검증·운영·production의 경계를 섞지 않는 것**이었다.

Stock에서는 development 탐색과 독립 검증을 분리하고, 실제 데이터 회귀가 통과해도 더 강한 주장으로 자동 승격하지 않았다. Career System에서는 discovery와 matcher 개선을 먼저 file-only audit와 shadow path에 두고 production 동작을 보존했다.
