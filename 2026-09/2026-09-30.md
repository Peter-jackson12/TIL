## 1. 오늘 배운 것

### 1.1 정상성은 값이 변하지 않는다는 뜻이 아니다

시계열 값은 계속 오르내릴 수 있다. 약한 정상성에서 확인하는 것은 평균과 분산이 시간에 따라 일정하고, 자기공분산이 관측 시점 자체보다 두 시점 사이의 간격에 의존하는지다.

2장 1강의 실습 흐름은 다음과 같다.

1. `datetime`을 변환하고 시간순으로 정렬한다.
2. 일별 `count`, `casual`, `registered`와 월별 `count`를 집계한다.
3. 시간 그래프와 최근 7개 관측값의 이동평균으로 수준 변화를 살펴본다.
4. 월별 시계열을 `seasonal_decompose(model="additive", period=12)`로 분해한다.
5. 원본과 필요한 경우 1차 차분에 ADF 검정을 수행한다.
6. 같은 진단을 `registered`에 적용하고 이후 모델링 방향을 설명한다.

`period=12`는 월별 관측값에서 12개 시점을 한 주기로 둔다는 뜻이다. `rolling(window=7)`과 `.diff()` 역시 관측 행 기준이므로, 날짜가 빠져 있다면 각각 연속된 7일과 전일 대비 변화라고 바로 해석하면 안 된다.

### 1.2 ADF의 기각 실패는 비정상성이 증명됐다는 뜻이 아니다

ADF 검정의 귀무가설은 단위근이 있다는 것이다.

- `p-value < 0.05`: 지정한 검정 조건에서 단위근 귀무가설을 기각한다.
- `p-value ≥ 0.05`: 귀무가설을 기각할 근거가 부족하다.

기각 실패를 귀무가설의 증명으로 바꾸면 안 된다. 특히 짧은 시계열에서는 검정력이 부족할 수 있고, 추세항·lag 설정 등에도 결과가 영향을 받는다. 기각했다고 모든 형태의 비정상성이 사라졌다고 단정하지 않고 그래프, 계절성, 잔차 구조를 함께 확인한다.

1차 차분은 현재 관측값에서 이전 관측값을 뺀 변화량이다. 차분으로 추세를 줄일 수 있지만 필요 이상으로 반복하면 유용한 구조를 잃고 불필요한 잡음을 만들 수 있어, 무조건 많이 차분하는 것이 좋은 것은 아니다.

### 1.3 ARIMA의 p·d·q는 서로 다른 역할을 한다

ARIMA는 차분한 시계열을 AR과 MA로 모델링한다.

- **AR(p)**: 과거 시계열 값의 지연항을 몇 개 사용할지 정한다.
- **I(d)**: 원본 시계열에 차분을 몇 번 적용할지 정한다.
- **MA(q)**: 과거 혁신 오차의 지연항을 몇 개 반영할지 정한다.

`ARIMA(2, 1, 1)`에서는 1차 차분한 시계열의 과거 값 두 개와 과거 혁신 오차 한 개를 활용한다. 여기서 MA는 관측값을 단순 평균 내는 `rolling().mean()`과 다르다. 모델이 이전 시점에 설명하지 못한 새로운 충격을 현재 값의 설명에 반영하는 요소다.

현재 수업의 `(2, 1, 1)`은 실습 설정이다. 실제 데이터에 가장 좋은 차수라고 검증된 결과는 아니다.

### 1.4 정상성 진단과 모델 설정도 Train 안에서 결정해야 한다

2장 2강 노트북은 시간순으로 정렬한 월별 자료의 마지막 6개 행을 Test로 분리한다. 과거를 학습하고 이후 시점을 예측하는 상황을 유지하기 위해 무작위 분리를 사용하지 않는다.

과제에서는 다음 흐름을 요구한다.

1. Train 원본과 최근 3개 관측값의 이동평균을 확인한다.
2. Train에만 ADF를 적용해 `d`를 선택한다. 과제의 설정은 `maxlag=1, regression="c", autolag="AIC"`다.
3. 원본의 귀무가설을 기각하지 못하면 1차 차분한 Train을 추가 진단한다.
4. 차분 후에도 기각하지 못하면 추가 진단이 필요함을 밝히고, 과제에서는 `d=1`을 잠정 사용한다.
5. **차분하지 않은 원본 Train**을 `ARIMA(order=(2, d, 1))`에 넣는다.
6. Test는 최종 평가에만 사용하며, Test 결과를 보고 다시 `d`를 고르지 않는다.

원본 입력에 `d=1`을 지정하면 모델이 내부에서 차분한다. 이미 차분한 데이터를 넣으면서 다시 `d=1`을 지정하면 의도하지 않은 이중 차분이 될 수 있다.

### 1.5 예측은 점예측·오차·예측 구간을 함께 봐야 한다

`forecast(steps=len(test))`는 Test 길이만큼 미래 관측 시점을 예측한다. 과제에서는 `get_forecast()`의 `predicted_mean`과 `conf_int(alpha=0.05)`를 이용해 점예측과 95% 예측 구간을 함께 확인한다.

- **MAE**: 예측 오차 절댓값의 평균으로, 원래 대여량 단위에서 오차 크기를 해석한다.
- **RMSE**: 오차를 제곱해 계산하므로 큰 오차에 더 민감하다.
- **예측 구간**: 하한·상한, 시점별 구간 폭, 실제값이 구간에 들어오는지를 함께 본다.

실제값이 구간에 모두 들어와도 구간이 지나치게 넓으면 유용한 예측이라고 바로 평가하기 어렵다. 짧은 월별 표본, 계절성, 외부 요인 같은 모델의 한계도 함께 남겨야 한다.

또한 월별 합계는 제공된 CSV에 있는 관측값의 합이다. 월 전체 날짜가 포함되지 않았다면 완전한 월간 총수요라고 해석하지 않는다.

## 2. 내가 궁금했던 질문과 이해한 답

### 정상성이 있으면 값이 거의 일정해야 하는가?

개별 값이 일정해야 하는 것은 아니다. 값이 변하더라도 평균·분산·시간 간 의존 구조가 안정적으로 유지되는지를 보는 개념이다.

### ADF에서 p-value가 크면 비정상이라고 확정할 수 있는가?

단위근 귀무가설을 기각하지 못한 것이다. 데이터가 짧거나 검정 조건에 맞지 않을 수도 있으므로, 비정상성이 증명됐다고 쓰지 않는다.

### 차분하면 무조건 더 좋은 데이터가 되는가?

차분은 데이터의 의미를 수준에서 변화량으로 바꾼다. 필요한 차분은 도움이 될 수 있지만 과도한 차분은 문제를 만들 수 있다. 차분 후 다시 진단해야 한다.

### ARIMA의 MA는 이동평균 그래프와 같은 것인가?

이름은 같지만 계산 대상이 다르다. 이동평균 그래프는 관측값을 평균 내고, ARIMA의 MA는 과거 혁신 오차를 반영한다.

### ARIMA에 차분한 데이터를 직접 넣어야 하는가?

이번 과제에서는 원본 Train과 `d`를 전달한다. 내부 차분과 외부 전처리를 중복 적용하지 않도록 입력의 의미를 확인한다.

## 3. 프로젝트에서 확인한 것

### 3.1 Career Agent: 구현·운영 전환·실데이터 검증을 구분한다

오늘 확인한 저장소 기록에는 Hub staged ingest와 Markdown Intake의 HTML 정규화, 저장된 HTML capture, 결정적 추출, 원문 근거 검증, Hub prefill 및 receipt v2 구현이 포함돼 있다. 이 기능들이 모두 오늘 처음 구현됐다는 뜻은 아니다.

v0.16.0은 별도 설치와 read-only canary를 거쳐 production 전환이 기록돼 있다. 다만 실데이터 Markdown capture → 사람 검토 → staging → ingest의 전체 경로를 완료했다고 확대하지 않는다. 전체 본문과 모집 상태 확인은 사람 절차로 남아 있고, 페이지 fetch와 LLM provider 도입도 별도 결정사항이다.

핵심은 **코드 구현, 합성 검증, 설치·전환, 실데이터 검증이 각각 다른 완료 조건을 갖는다**는 점이다.

### 3.2 Career Agent: 백업 파일 존재보다 격리 복구와 원본 불변 검증이 중요하다

`d7a3978`의 저장소 문서는 새 경로 승인과 writer 정지 확인 후 로컬 백업·격리 복구 검증을 완료하고, 원본 후검사와 완료 receipt를 남겼다고 기록한다.

복구 사본이 원본 경로나 환경변수의 입력을 대신 읽어 우연히 통과하지 않도록 참조 범위를 검사하고, 파일·DB 상태와 복구 환경의 읽기 결과를 비교하는 것이 중요했다. Windows 경로 길이 제한과 OWNER RIGHTS ACL 판정 문제는 별도로 진단·검증됐다.

이 결과는 저장소에 기록된 로컬 사본 복구 검증이다. 원본 운영 복구·전환, 정기 백업, 보존·삭제 정책의 자동 집행까지 완료했다는 뜻은 아니다.

### 3.3 Career Hub: 숫자와 함께 적용 범위·출처·미확인 상태를 보여준다

오늘의 Hub 표시 개선에서는 다음을 구분했다.

- 회사 분류값과 그 분류의 근거
- 해당 포지션 보상과 회사 평균·다른 직무의 보상
- 금액의 하한·상한·추정치, 통화, 기간, 기본급·총보상
- 현재 적용한 통근값과 원자료, 확인일, 출처, 신뢰도
- 미확인·오래된 근거·출처 충돌
- 지원 상태의 `expired`와 공고 활성 여부

오래되거나 충돌하는 원자료가 있다고 해서 현재 파생값을 그 숫자로 채우면 안 된다. `expired`는 공고 마감이 아닌 **지원 만료**로 표시하도록 수정됐다.

`d8ad378`의 CI는 성공했다. 이 변경은 개발 main의 표시 개선이며, 설치된 production 기준 revision은 `a87ba62`로 별도다.

### 3.4 Airplane: 기존 연구 결과를 유지하며 README 표현을 개선했다

`bd0824b`에서는 README의 발표용 구성을 개선했다. 기존 지표와 연구 결과를 유지한 문서 변경이며, 새 모델 실험이나 성능 향상으로 기록하지 않는다.

### 3.5 Stock: 원격에서 확인되지 않은 작업은 완료로 쓰지 않는다

오늘 KST 범위의 기본 브랜치 커밋 조회에서는 새 Stock 커밋이 확인되지 않았다. 이 결과만으로 로컬 작업이 없었다고 결론 내릴 수는 없다.

로컬 미푸시 변경이나 수집기 종료 상태는 이번 원격 확인으로 입증되지 않았으므로, 구현·종료 완료나 새로운 실험 결과를 추가하지 않는다.
