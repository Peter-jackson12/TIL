## 1. 문제 인식 (Problem Recognition)

### ① 통계학: 통계적 유의성($p$-value)과 실질적 유의성(Cohen's d)의 괴리 및 가설검정 기법 선택
* **$p$-value의 표본 크기($n$) 종속성:** 표본 크기가 수천~수만 건으로 커지면 현실적으로 무의미한 극미한 차이(예: 0.001%)조차 표준오차($SE = s/\sqrt{n}$)가 $0$으로 수렴하면서 $p < 0.001$로 무차별 기각되는 통계적 왜곡이 발생함.
* **실무적 기준 결합:** "통계적으로 유의미하다($p < 0.05$)"와 "비즈니스적으로 의미가 있다(예: 주택 판매가격 차이 $\ge \$100,000$)"는 완전히 별개의 문제임. 집단 간 분산 대비 순수한 신호의 크기를 재는 **Cohen's d**와 현실적인 비즈니스 손익분기점을 결합한 의사결정 체계 확립이 요구됨.
* **검정 기법 선택 트리:** 데이터의 척도(연속형 vs 범주형), 비교 집단의 수(2개 vs 3개 이상), 집단 간 관계(독립표본 vs 대응표본), 검정 가정(정규성·등분산성)에 따라 `ttest_ind`, `ttest_rel`, `ANOVA`, $\chi^2$ 검정으로 이어지는 엄밀한 결정 트리를 도출해야 함.

### ② t-검정의 수리적 본질과 등분산성(Levene) 검정의 내적 메커니즘
* **t-통계량의 물리적 의미:** $t = \frac{\bar{X} - \mu_0}{s/\sqrt{n}}$는 단순한 수식이 아니라, **"표본 오차(노이즈) 대비 관측된 차이(신호)가 몇 배나 큰가?"를 나타내는 신호 대 잡음비(SNR)**이자 표본 기반의 '시그마 배수'임.
* **$6\sigma$와의 수리적 비교:** 정규분포의 $Z=6$은 10억 분의 2 수준의 기적이지만, 자유도가 작은 t-분포($df=4$)에서의 $t=6$은 뚱뚱한 꼬리(Fat Tail)로 인해 발생 확률이 약 0.3%에 달한다는 분포적 차이를 인식함.
* **등분산성 판별의 의문:** "평균을 비교하는 t-검정을 하기 전에 등분산성을 확인해야 하는데, 등분산성은 분산 검정인데 어떻게 t-검정 개념과 연결되는가?"에 대한 알고리즘적 본질 규명이 필요함.

### ③ 머신러닝: 항공 지연 예측 조기종료(Early Stopping)의 배신과 `scale_pos_weight` 오진
* **에이전트 G의 오진:** 불균형 데이터 보정 파라미터인 `scale_pos_weight`(spw=4.67)가 `binary_logloss`와 목적함수 불일치를 유발한다는 진단하에 spw를 제거함. LogLoss는 0.4635에서 0.4553으로 개선되었으나, **랭킹 지표인 ROC-AUC(0.6305 ➔ 0.6252)와 Macro F1(0.5704 ➔ 0.5673)이 동반 하락**하는 역효과 발생.
* **진짜 병목 노드(Early Stopping) 포착:** spw 제거 후 5-Fold OOF를 분석한 결과, 평탄한 손실 곡선 위에서 `stopping_rounds=40`이 노이즈에 반응해 Fold별 최적 반복수가 $[54, 64, 502, 562, 567]$로 극단적으로 발산함. 54그루에서 멈춘 Fold는 AUC 0.6446을 기록한 반면, 560그루까지 폭주한 Fold는 과적합으로 AUC가 0.6138로 곤두박질치며 AUC 0.025를 증발시킴.

### ① 통계학: Ames Housing 데이터 기반 가설검정·효과크기·주피터 범용 파이프라인
Ames Housing 데이터를 활용하여 주피터 노트북(`.ipynb`)과 파이썬 스크립트(`.py`) 환경 양쪽에서 에러 없이 실행되는 범용 경로 제어 및 $t$-검정, Cohen's d 산출 파이프라인을 구축함.

```python
"""
Filename: ames_hypothesis_testing.py
Description: CentralAir 유무에 따른 주택가격 t-검정 및 실질적 유의성(Cohen's d) 평가
"""
from pathlib import Path
import numpy as np
import pandas as pd
from scipy import stats

# 1. .py 와 .ipynb 환경을 모두 지원하는 범용 경로 핸들러
try:
    ROOT = Path(__file__).resolve().parent
except NameError:
    ROOT = Path.cwd()

data_path = ROOT / "ames_housing.csv"
if not data_path.exists():
    data_path = ROOT / "data" / "ames_housing.csv"

# 2. 데이터셋 로드 (한글/BOM 방어)
df = pd.read_csv(data_path, encoding="utf-8-sig")

# 3. 데이터 분리 및 통계량 추출
air_yes = df[df["CentralAir"] == "Y"]["SalePrice"].dropna()
air_no = df[df["CentralAir"] == "N"]["SalePrice"].dropna()

n1, n2 = len(air_yes), len(air_no)
m1, m2 = air_yes.mean(), air_no.mean()
s1, s2 = air_yes.std(ddof=1), air_no.std(ddof=1)
mean_diff = m1 - m2

# 4. 합동 표준편차(Pooled SD) 및 Cohen's d 계산 함수
sp = np.sqrt(((n1 - 1) * (s1**2) + (n2 - 1) * (s2**2)) / (n1 + n2 - 2))
cohens_d = mean_diff / sp

# 5. 등분산성(Levene) 및 Welch's t-test 수행
stat_lev, p_lev = stats.levene(air_yes, air_no)
t_stat, p_val = stats.ttest_ind(air_yes, air_no, equal_var=False)

print("=" * 65)
print("[Ames Housing: 중앙 냉방시설(CentralAir) 유무에 따른 분석 결과]")
print(f"- CentralAir 'Y': n = {n1:>5}, 평균 = ${m1:>10,.2f}, 표준편차 = ${s1:>10,.2f}")
print(f"- CentralAir 'N': n = {n2:>5}, 평균 = ${m2:>10,.2f}, 표준편차 = ${s2:>10,.2f}")
print(f"- 두 집단 평균 차이: ${mean_diff:>10,.2f}")
print("-" * 65)
print(f"- Levene 등분산 검정: F = {stat_lev:.4f}, p-value = {p_lev:.4e} (등분산 위반)")
print(f"- 웰치 t-검정 결과   : t = {t_stat:.4f}, p-value = {p_val:.4e} (통계적 유의)")
print(f"- 표준화 효과크기(d) : {cohens_d:.4f} (|d| >= 0.8 -> 대형 효과)")
print(f"- 회사 실무 기준($10만): {'충족 (채택)' if abs(mean_diff) >= 100000 else '미달 (사업 보류)'}")
print("=" * 65)
```

### ② 알고리즘: 인접 근무 배제 최대 일당 계산 동적 계획법(DP) 엔진
이틀 연속 근무가 불가능한 제약 조건 하에서 메모이제이션을 통해 시간복잡도 $O(N)$, 공간복잡도 $O(1)$로 최대 급여를 추출하는 객체지향 DP 클래스를 구현함.

```python
"""
Filename: dp_part_time_worker.py
Description: 점화식 dp[i] = max(dp[i-1], dp[i-2] + payments[i]) 기반 DP 최적화
"""
class PartTimeWorker:
    def __init__(self, payments: list[int]):
        self.payments = payments

    def max_payment(self) -> int:
        n = len(self.payments)
        if n == 0: return 0
        if n == 1: return self.payments[0]

        # O(1) 공간 최적화: 직전 값(prev1)과 전전 값(prev2)만 상태 유지
        prev2 = self.payments[0]
        prev1 = max(self.payments[0], self.payments[1])

        for i in range(2, n):
            current = max(prev1, prev2 + self.payments[i])
            prev2 = prev1
            prev1 = current

        return prev1

# 테스트 케이스 검증
assert PartTimeWorker([3, 5, 2, 7]).max_payment() == 12
assert PartTimeWorker([4, 1, 6]).max_payment() == 10
assert PartTimeWorker([5, 10, 4, 11, 3]).max_payment() == 21
print("✅ DP PartTimeWorker 모든 테스트 케이스 통과 완료")
```

### Issue 1: Jupyter Notebook 환경에서의 `NameError: name '__file__' is not defined` 경로 크래시
* **현상:** `.py` 파일에서 정상 실행되던 `ROOT = Path(__file__).resolve().parent` 코드가 주피터 노트북(`.ipynb`) 셀에 붙여넣는 즉시 `NameError`를 발생시키며 데이터 로드가 전면 중단됨.
* **원인:** `.py` 스크립트는 인터프리터가 파일 모듈을 실행하며 파일의 절대 경로를 `__file__` 전역 변수에 자동 할당하지만, 대화형 셀 환경인 IPython 커널은 메모리상에서 동적 코드 블록으로 실행되므로 `__file__` 변수 자체가 생성되지 않음.
* **해결:** `try - except NameError` 구조를 적용하여, 스크립트 실행 시에는 파일 경로를, 노트북 셀 환경에서는 `Path.cwd()`(현재 작업 디렉토리)를 동적으로 바인딩하는 무결점 범용 경로 패치 적용.

## 4. 퀀트 & 통계학적 인사이트 (Key Takeaways)

### 1. "t-통계량은 표본 신호 대 잡음비이며, Levene 등분산성 검정의 알고리즘적 실체는 편차에 대한 t-검정이다"
* t-통계량은 "평균의 차이(Signal)"를 "표본오차(Noise)"로 나눈 값이다. $t = 4.323$은 관측된 차이가 우연한 노이즈보다 4.3배 크다는 뜻이며, 데이터가 충분하다면 이는 정규분포의 $4.3\sigma$와 동일한 개념이다.
* "분산을 비교하는데 왜 t-검정과 연결되는가?"에 대한 답은 알고리즘 내부에 있다. **Levene 검정은 원데이터에서 중앙값을 뺀 편차 절댓값 $Z = |X - \text{median}|$을 생성한 뒤, 두 집단의 $Z$ 평균이 같은지를 '독립표본 t-검정'($k=2$일 때 $F = t^2$)으로 판별하는 기법**이다. 결국 중심 위치 비교(t-test)의 응용이 흩어짐의 비교(Levene)를 완성한다.

### 2. "통계적 유의성은 $n$의 함수이고, 비즈니스는 효과 크기와 경제적 임계값으로 결정된다"
* Ames Housing 실습에서 중앙 냉방시설(CentralAir) 유무는 $t = 24.32$, $p = 1.18 \times 10^{-74}$로 통계적으로 극단적으로 유의했고, Cohen's $d = 1.05$로 '대형 효과'를 기록했다.
* 그러나 실거래 가격 차이는 약 $\$80,481$로 회사의 설치 지원 사업 손익분기점인 $\$100,000$에 미달하여 **사업 보류(실질적 유의성 결여)** 판정이 내려졌다.
* 퀀트 전략에서도 수백만 틱 데이터 백테스트 시 샤프지수 $p < 0.001$이 나오더라도, 슬리피지와 거래세(비즈니스 임계값)를 공제한 순수익이 기준치에 미달하면 폐기해야 한다는 절대적 규율을 재확인함.

### 3. "완만한 손실 곡선에서 조기종료(Early Stopping)는 최악의 노이즈 유발자다"
* LightGBM에서 `stopping_rounds=40`은 단조 감소하는 뚜렷한 손실 함수에서는 유효하나, 최적점 부근에서 평탄하게 눕는 LogLoss 곡선 위에서는 4만 건 검증셋의 미세한 샘플링 노이즈에 카운터가 리셋되며 트리를 50그루에서 560그루까지 폭주시키는 참사를 낳았다.
* 이로 인해 모델이 훈련셋의 고유 노이즈를 암기하여 테스트 Fold의 ROC-AUC가 0.025 급락했다.
* **해법은 단순했다. 조기종료를 끄고 트리를 50개(`n_estimators=50`)로 강제 고정하는 것만으로 LogLoss 0.4470, ROC-AUC 0.6451, Macro F1 0.5770이라는 역대 최고 성능이 도출**되었다. 모델링에서 가장 강력한 정규화(Regularization)는 불필요하게 깊고 많은 트리를 애초에 자라지 못하게 쳐내는 것이다.

### 4. "인프라와 AI는 '수석 아키텍트'와 '돌격대장'의 분업으로 지배해야 한다"
* 1년 걸릴 퀀트 틱 파이프라인과 머신러닝 감사를 몇 주 만에 돌파하며 겪은 '내 손을 벗어나는 공포'는 과도한 컨텍스트와 인프라 비대증에서 비롯되었다.
* 86%의 토큰을 낭비하던 150k 컨텍스트를 `/clear`로 쳐내고, **거시적 감사와 프롬프트 설계는 묵직한 두뇌(Claude Opus 5)**에게, **터미널 파일 수정과 단위 테스트는 기민한 손발(Claude Sonnet 5)**에게 맡기는 2-Tier 지휘 체계를 확립했다.
* 플랫폼 엔진 코드는 당당하게 오픈소스 포트폴리오로 공개하되, 진짜 수익을 결정짓는 핵심 알파와 실계좌 키는 Private으로 분리하는 듀얼 레포 전략을 통해 포트폴리오 가치와 독점적 수익성을 완벽히 양립시켰다.
