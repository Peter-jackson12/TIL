### 1장 — 텍스트 전처리와 TF-IDF

- 텍스트 분석은 리뷰 본문의 결측·공백 처리, 문장 보존, 토큰화부터 시작한다. 공백 기준 `split()`과 형태소 분석은 다르다. 공통 명사만 추출하면 긍정/부정이나 속성별 문맥을 놓칠 수 있다.
- **TF (Term Frequency)**: 문서 `d`에 단어 `t`가 등장한 횟수. `TF(t,d)=f(t,d)`. 경우에 따라 `f(t,d)/(문서 d의 전체 단어 수)`로 정규화한다.
- **DF (Document Frequency)**: 단어 `t`가 등장한 **문서의 수**. `DF(t)=Σ 1(t∈d)`. 같은 문서에서 1번 등장하든 100번 등장하든 DF에는 문서 1개로 센다.
- **DF 비율**: `DF(t)/N`은 등장한 문서의 *비율*이며, 정수 개수인 DF와는 다르다.
- **IDF (Inverse Document Frequency)**: `IDF(t)=ln(N/DF(t))=-ln(DF(t)/N)`. 전체 문서에서 흔할수록 작고, 드물수록 크다.
- **TF-IDF**: `TF(t,d) × IDF(t)`. 특정 문서에서 자주 나오지만 다른 문서에는 드문 단어를 강조한다. 단어 자체의 의미적 중요도와 동일하지 않다.

예: 전체 문서 `N=1,000`개 중 '삼성전자'가 100개에 등장하면 **DF=100**, **DF 비율=0.1**, **IDF=ln(1000/100)≈2.303**이다.

| 가상 단어 | DF | 기본 IDF |
| --- | ---: | ---: |
| 주식 (1,000개 문서에 등장) | 1,000 | 0 |
| 삼성전자 (100개 문서) | 100 | 약 2.303 |
| 상장폐지 (10개 문서) | 10 | 약 4.605 |

**중요한 구분**: '특정 구간에 몰린다'는 것이 특정 **문서들에 집중되어 나타난다**는 뜻이라면 TF-IDF가 높아질 수 있다. 일반적인 TF-IDF는 단일 문서의 앞부분/뒷부분처럼 **단어가 나온 위치**를 고려하지 않는다. DF=0일 때는 기본 로그 식이 정의되지 않고, 실제 `TfidfVectorizer`는 평활화·정규화 등 구현 설정에 따라 값이 달라진다.

### 2장 1강 — 임베딩과 코사인 유사도

- **TF-IDF**는 단어의 출현·희소성에 기반하고, **텍스트 임베딩**은 모델이 학습한 의미적 특징을 벡터로 표현한다. 다른 단어를 쓴 비슷한 문장에도 임베딩이 유용할 수 있다.
- **내적(Dot Product)**: `A·B=Σ A_i×B_i`. **Norm(벡터 크기)**: `||A||=√(Σ A_i²)`.
- **코사인 유사도**: `cos(A,B)=(A·B)/(||A||×||B||)`. 두 벡터의 크기보다 **방향**을 비교하며, 값이 높을수록 임베딩 공간에서 방향이 비슷하다.
- 강의의 가상 2차원 벡터 `Q=[1,0]`, `A=[0.8,0.6]`, `B=[0.6,0.8]`, `C=[0,1]`에 대한 코사인 유사도는 각각 **0.8 / 0.6 / 0.0**이다.
- **Top-K**는 질문과 각 문서의 유사도를 구한 뒤 점수가 높은 K개 문서를 선택하는 방법이다. 질문과 문서는 호환되는 임베딩 표현을 사용해야 한다.
- '환불이 완료되었습니다'와 '환불이 완료되지 않았습니다'는 비슷한 단어를 쓰지만 결론은 다르다. 높은 유사도나 Top-K 포함만으로 정확한 답변 근거라고 단정하지 않고 원문을 확인한다.

### BERTopic과 RAG의 연결

- **BERTopic**: 문서 임베딩 → 차원 축소 → 군집화 → **c-TF-IDF**로 그룹 대표 키워드 추출 → 실제 문서로 토픽 해석. c-TF-IDF는 개별 문서 점수 평균이 아니라 토픽 단위로 계산한 가중치다.
- **RAG**: 질문 → 외부 문서 검색 → 검색 내용을 LLM에 제공 → 답변 생성. 임베딩 검색 외에 키워드·혼합 검색도 사용할 수 있다.
- **차이**: BERTopic은 전체 문서의 *주제 발견*, RAG 검색은 질문에 필요한 *근거 문서 선택*이다. BERTopic은 RAG의 필수 단계가 아니다.

### 내적과 행렬곱: NumPy의 `@` 연산자

`@`는 **행렬곱** 연산자다. **1차원 벡터 두 개**를 `@`로 계산하면 **내적 결과(숫자 하나)**가 나온다. **2차원 행렬**끼리의 `@`는 왼쪽 행과 오른쪽 열의 내적을 반복해서 새로운 행렬을 만든다. 반면 `*`는 원소별 곱셈이다.

```python
import numpy as np

a, b = np.array([1, 2]), np.array([3, 4])
a @ b  # 11 = 1*3 + 2*4 (벡터 내적)

A = np.array([[1, 2], [3, 4]])
B = np.array([[5, 6], [7, 8]])
A @ B  # [[19, 22], [43, 50]] (행렬곱)

query_vector = np.array([1.0, 0.0])
document_vectors = np.array([[0.8, 0.6],
                             [0.6, 0.8],
                             [0.0, 1.0]])
dot_products = document_vectors @ query_vector  # [0.8, 0.6, 0.0]
cosines = dot_products / (
    np.linalg.norm(document_vectors, axis=1) * np.linalg.norm(query_vector)
)
top2 = np.argsort(cosines)[::-1][:2]
```

강의의 `document_vectors`는 **(3, 2)** 행렬, `query_vector`는 **길이 2**인 벡터다. `@`로 문서 3개와 질문 벡터의 내적을 **한 번에** 얻고, 각각의 Norm으로 나누어 코사인 유사도를 계산한다.

## 2. 내가 궁금했던 질문과 이해한 답

1. **IDF가 높으면 왜 더 중요하게 보나?** 전체 문서에서 드물면 문서를 구분하는 데 유용하기 때문이다. 그렇다고 의미적 중요성을 보장하지는 않는다.
2. **TF-IDF가 낮다면?** 문서 안에서 적게 등장하거나(TF↓), 여러 문서에서 흔히 등장하기 때문(IDF↓)일 수 있다.
3. **많이 나오고 특정 구간에 몰리면 높나?** 특정 *문서들*에서 집중적으로 나온다는 의미라면 그렇다. 문서 *내부 위치*의 집중 여부는 일반 TF-IDF가 평가하지 않는다.
4. **1,000개 문서 중 100개에 나오면 DF는 100인가?** 그렇다. `100/1000=0.1`은 별도의 DF 비율이고, `IDF=ln(10)`이다.
5. **행렬곱은 내적과 같은가?** 두 1차원 벡터 사이의 `@`는 내적이지만, 일반적인 행렬곱은 여러 행·열 내적을 모아 행렬을 만드는 연산이다.
