## 1. 오늘 배운 것

어제 학습한 임베딩·코사인 유사도·BERTopic을 확장해, **임베딩 벡터의 차원**, **검색의 Top-K와 생성의 Temperature**, **K 자동 최적화와 역전파의 차이**, **uv의 프로젝트별 설치·공용 캐시**를 질문하며 개념을 연결했다. 아래 숫자와 코드는 설명용이며 오늘 직접 실험한 결과가 아니다.

### BERTopic은 어떤 임베딩 모델을 사용할까?

- **BERTopic은 '버트 토픽'**으로 읽는다. 이름에 BERT가 있지만 BERT만 사용할 수 있는 것은 아니다.
- SBERT(Sentence-BERT), RoBERTa 계열의 문장 임베딩 모델, E5, BGE, OpenAI 임베딩 API 등 호환되는 임베딩 출력을 사용할 수 있다. 단순히 모델이 BERT 계열이라는 사실만으로 좋은 문장 임베딩을 보장하지는 않는다.
- 대표적인 처리 흐름: **문서 → 임베딩 → UMAP 차원 축소 → HDBSCAN 군집화 → c-TF-IDF로 토픽 대표 키워드 추출**. 각 구성요소는 교체할 수 있다.
- BERTopic은 비슷한 문서를 묶어 **주제를 발견**하는 도구다. 질문에 유사한 문서를 찾는 RAG의 Top-K 검색과 목적이 다르다.

### Transformer는 임베딩을 어떻게 만들까?

- 먼저 문장의 토큰을 초기 임베딩으로 바꾸고 위치 정보를 반영한다. Transformer의 **Self-Attention**이 토큰 사이의 문맥 관계를 반영해 각 토큰의 표현을 갱신한다.
- SBERT 등의 문장 임베딩 모델은 토큰 표현에 Pooling 등을 적용해 **문장 하나를 대표하는 벡터**를 만든다.
- **Embedding Layer(초기 토큰 벡터) / Transformer(문맥 반영) / Sentence Embedding(문장 벡터)**은 서로 같은 단계가 아니다.
- Transformer 이전에도 Word2Vec, GloVe 같은 임베딩 기법이 있었다. Transformer는 임베딩을 생성하는 방법 중 하나다.

### 문장 임베딩은 정말 2차원일까?

- 대화에서 사용한 `[0.8, 0.6]` 등의 2차원 벡터는 **계산 원리 설명을 위한 가상 예시**다.
- 실제 문장 임베딩 모델은 예를 들어 **384차원**(all-MiniLM-L6-v2), **768차원**(all-mpnet-base-v2), **1,536차원**(text-embedding-3-small 기본값) 등을 사용한다.
- GPT-3 175B의 예에서는 **어휘 약 50,257개**, **토큰 임베딩/은닉 차원 12,288**, **모델 파라미터 약 1,750억 개**를 구분해야 한다. 어휘 수와 벡터의 차원 수는 다르다.
- **토큰 임베딩**은 토큰마다 하나의 벡터가 대응하는 것이고, **문장 임베딩**은 문장 전체를 하나의 벡터로 표현한다. 범용 GPT의 토큰 표현을 그대로 좋은 문장 검색 임베딩으로 가정하면 안 된다.
- 코사인 유사도를 계산하려고 벡터를 2차원으로 축소할 필요는 없다. BERTopic의 UMAP은 군집화를 위한 별도 차원 축소 단계다.

### 코사인 유사도와 Top-K 검색

임베딩 모델로 생성한 두 벡터 $A, B$의 **방향**을 비교한다.

$$
\operatorname{cosine}(A,B)
= \frac{A \cdot B}{\lVert A\rVert\lVert B\rVert}
= \frac{\sum_i A_i B_i}{\sqrt{\sum_i A_i^2}\sqrt{\sum_i B_i^2}}
$$

- 코사인 유사도는 일반적으로 **-1부터 1** 범위다. 두 벡터가 같은 방향이면 1, 직각이면 0, 반대 방향이면 -1이다.
- 질문 문장과 여러 문서의 임베딩 사이 유사도를 계산하고 높은 순서로 정렬한 뒤 **K개를 반환**하면 Top-K 유사도 검색이다.
- 예를 들어 유사도가 A=0.95, B=0.87, C=0.72라면 **K=2일 때 A와 B를 선택**한다(설명용 숫자).
- 높은 유사도는 임베딩 공간의 방향이 유사하다는 뜻이지, 원문의 사실·부정 표현까지 정확히 일치한다는 보장은 아니다.

### Top-K 검색, Top-K Sampling, Temperature의 차이

| 개념 | 무엇을 선택·조정하나? | 주 사용처 |
| --- | --- | --- |
| **Top-K 검색** | 질문에 가까운 **문서 K개** | 임베딩 검색·RAG |
| **Top-K Sampling** | 확률이 높은 **다음 토큰 후보 K개** | LLM 생성 |
| **Temperature** | 토큰 Logit에서 확률 분포의 뾰족한 정도 | LLM 생성 |

Temperature를 적용한 Softmax의 개념식:

$$
P_i = \frac{\exp(z_i/T)}{\sum_j \exp(z_j/T)}
$$

- $z_i$는 토큰의 원시 점수(Logit), $T$는 Temperature다. **낮은 T**는 높은 점수에 더 집중시키고, **높은 T**는 확률을 더 고르게 만든다.
- 일반적인 **코사인 유사도 기반 Top-K 문서 검색**에는 Temperature가 필요하지 않다.
- 다만 임베딩 모델의 **대조학습(Contrastive Learning)**처럼 유사도 점수를 Softmax에 넣는 학습 상황에서는 Temperature가 쓰일 수 있다.

### 최적의 K를 찾는 것도 학습인가?

- 사람이 K를 하나씩 확인할 수도 있지만, **Grid Search나 Optuna로 K 후보를 자동 평가하고 선택**할 수 있다.
- 정답 문서가 알려진 평가 질문을 마련하고, K별 **Precision@K, Recall@K, 최종 답변 품질, 지연시간, 토큰 비용** 등을 비교한다. 어떤 지표를 최적화할지는 검색 목적에 따라 정해야 한다.
- Recall@K는 K를 늘리면 일반적으로 감소하지 않는다. **Recall만 최대화**하면 큰 K가 유리하기 때문에 비용·정밀도 등을 함께 평가해야 한다.
- K는 불연속적인 정수 설정값이므로 일반적인 미분·역전파보다 **하이퍼파라미터 탐색**이 자연스럽다.
- 반대로 **임베딩 모델 자체를 학습**할 때는 관련 문서의 벡터를 가깝게, 무관한 문서는 멀게 만드는 손실을 정의하고 **역전파로 가중치**를 업데이트할 수 있다.
- 따라서 **K 탐색(설정값 최적화)**과 **Transformer 학습(가중치 최적화)**은 다르며, 필요하면 함께 사용할 수 있다. K를 고를 때는 평가 데이터에 과적합되지 않도록 별도 검증이 필요하다.

### uv로 패키지를 설치할 때 프로젝트마다 다시 설치할까?

```powershell
uv add pandas scikit-learn sentence-transformers
uv sync
uv cache dir
```

- `uv add`: **현재 프로젝트**의 `pyproject.toml`에 의존성을 기록하고 lockfile·가상환경을 동기화한다.
- `uv sync`: 현재 프로젝트의 잠금 파일·의존성에 맞춰 가상환경을 동기화한다.
- 다른 프로젝트는 각자의 `.venv`에 설치해야 하지만, **uv의 공용 캐시를 재사용**하므로 같은 호환 패키지를 매번 다시 다운로드할 필요는 없다.
- 캐시된 패키지는 가능한 경우 **하드링크** 등으로 재사용해 설치 시간과 저장 공간을 절약한다. 볼륨·파일시스템 조건에 따라 복사가 필요할 수도 있다.
- 버전, Python 버전, 운영체제, CPU 아키텍처가 다르거나 캐시를 지웠다면 다시 다운로드할 수 있다.
- **Stock의 키움 OCX용 32비트 환경**과 **ML 수업용 64비트 환경**은 분리해서 유지하는 편이 안전하다. 큰 PyTorch 의존성이 있는 `sentence-transformers` 실습은 64비트 Python 환경이 적합하다.

## 2. 내가 궁금했던 질문과 이해한 답

1. **BERTopic은 BERT만 사용하나?** 아니다. Sentence-Transformers 등 호환되는 여러 임베딩 모델을 사용할 수 있다.
2. **임베딩을 Transformer로 만들 수 있나?** 가능하다. Self-Attention으로 문맥을 반영하고 문장 단위 표현을 만든다.
3. **코사인 유사도는 문장 임베딩 벡터끼리 계산하나?** 그렇다. 임베딩 자체를 생성하는 것이 아니라 이미 생성된 벡터의 방향을 비교한다.
4. **문장 벡터는 2차원인가?** 아니다. 2차원은 설명용이며 실제 모델은 보통 수백~수천 차원이다.
5. **Top-K와 Temperature는 연결되나?** 문서 검색의 K와 생성 토큰 Sampling의 K가 다르다. Temperature는 주로 생성 확률 분포를 조절한다.
6. **최적 K를 찾으려면 사람이 하나씩 확인해야 하나?** 아니다. 평가 기준과 정답 데이터가 있다면 자동 탐색할 수 있다. 이 과정 자체가 LLM 역전파 학습은 아니다.
7. **uv로 한번 설치한 패키지는 재사용되나?** 프로젝트별 가상환경은 별개지만, 다운로드된 패키지는 호환 조건에서 공용 캐시를 재사용한다.
