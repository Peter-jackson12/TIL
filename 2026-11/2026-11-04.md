### 6장 1강 — Pretrained Model, Feature Extraction, Fine-tuning

- **Pretrained Model**: Source 데이터에서 미리 학습된 모델. **Transfer Learning**: 그 모델의 학습된 표현이나 파라미터를 Target에 재사용하는 과정.
- 실습은 Source 건물 1~4의 2,880행으로 학습한 모델을 Target 건물 5의 학습 168행·검증 168행에 적용한다. 입력은 기온, 습도, 시간, 요일, 연면적, 냉방면적 6개이며 예측 대상은 전력소비량(kWh)이다.
- 모델: 입력 6개 → Tanh 은닉 뉴런 8개 → 출력 1개. **Backbone 56개 + Head 9개 = 전체 65개** 파라미터.
- **Feature Extraction**은 W1/b1(56개)을 고정하고 W2/b2(9개)만 업데이트한다. Freeze는 출력을 0으로 만들거나 레이어를 삭제하는 것이 아니라 **가중치 업데이트를 멈추는 것**이다.
- **Fine-tuning**은 사전학습 가중치를 이어받아 Backbone까지 추가 학습한다. 이번 실습에서는 전체 65개 업데이트, Feature Extraction 후 학습률 0.003으로 추가 100 epoch를 진행한다.
- 전체 업데이트가 항상 더 좋은 것은 아니다. 검증 지표와 학습 비용으로 판단해야 한다.

**순전파와 손실**

```math
H = \\tanh(XW_1+b_1), \\qquad \\hat{y}=HW_2+b_2
```

```math
L=\\frac{1}{N}\\sum_{i=1}^{N}(\\hat{y}_i-y_i)^2
```

- Shape: `X (N,6)` → `W1 (6,8)` → `H (N,8)` → `W2 (8,1)` → `y_hat (N,1)`.
- MSE의 출력 기울기는 `grad_output = 2 * (prediction-y) / N`.
- 출력층: `grad_W2 = H.T @ grad_output`, `grad_b2 = grad_output.sum(axis=0, keepdims=True)`.
- 은닉층: `grad_H = (grad_output @ W2.T) * (1-H**2)` (`tanh` 미분), `grad_W1 = X.T @ grad_H`. `train_backbone=False`이면 은닉층 업데이트를 생략한다.
- 경사하강법: `theta -= lr * grad_theta`; 작은 학습률은 같은 기울기에서 1회 업데이트 폭을 줄인다.

**원본 NumPy 실습에서 확인한 코드 흐름**

```python
# 노트북 코드의 핵심 호출 (원본 변수명)
feature_model, feature_history = train_model(
    feature_start, X_train, y_train,
    lr=0.03, epochs=300, train_backbone=False
)
fine_model, fine_history = train_model(
    feature_model, X_train, y_train,
    lr=0.003, epochs=100, train_backbone=True
)
```

- Freeze 실습에서 W1·b1 변화량은 모두 0, W2 최대 변화량 2.087094, b2 0.394808이었다.
- Fine-tuning에서 W1 변화량 0.125444, b1 0.016804, W2 0.055335, b2 0.006976으로 Backbone도 수정되었다.

**1강 저장된 성능 결과 — Source 표준화 기준 MSE**

| 모델 | Train MSE | Validation MSE |
| --- | ---: | ---: |
| Pretrained only | 6.295834 | 7.568610 |
| Feature Extraction | 1.318850 | 2.346366 |
| Fine-tuning | 1.088650 | **2.239531** |

- 1강에서는 Fine-tuning이 가장 좋은 검증 MSE를 보였으나 **Scratch와 비교하지 않았으므로 전이학습이 Scratch보다 좋다고 결론 내릴 수 없다.**
- 기초 과제: Feature 모델에서 같은 100 epoch·lr 0.003 조건으로 은닉층을 계속 고정한 경우(9개 업데이트, 검증 MSE 2.339512)와 해제한 경우(65개, 2.239531)를 비교했다.

### 6장 2강 — Scratch vs Feature Extraction vs Fine-tuning

- **Scratch**: 무작위 초기화에서 전체 네트워크 학습.
- **Feature Extraction**: 사전학습 Backbone 고정, Head만 학습.
- **Fine-tuning**: 첫 300 epoch는 Backbone 고정, 마지막 100 epoch는 동결을 해제.
- 세 전략 모두 Target 168행으로 **총 400 epoch** 학습(초기 300회 lr=0.03, 이후 100회 lr=0.003). 출력층 시작값을 공통 난수 시드로 통제한다.
- 1강과 달리 2강은 입력에 **고정 중심·스케일**, 정답에 **`y / 1000`** 을 사용한다. 따라서 두 강의의 MSE를 직접 비교할 수 없다.

```python
# 2강 원본 전략별 Freeze 분기
first, h1 = fit_segment(
    start, X_train, y_train, lr=0.03, epochs=300,
    freeze=(strategy != "Scratch"),
    X_check=X_valid, y_check=y_valid
)
final, h2 = fit_segment(
    first, X_train, y_train, lr=0.003, epochs=100,
    freeze=(strategy == "Feature extraction"),
    X_check=X_valid, y_check=y_valid
)
```

- 주의: 1강의 `train_backbone=True`는 학습, 2강의 `freeze=True`는 고정으로 **True의 의미가 반대**다.
- Backbone이 고정되면 `H=tanh(XW1+b1)`를 한 번 계산해 재사용할 수 있으나, Fine-tuning에서는 가중치가 변하므로 H를 다시 계산해야 한다.

**2강 저장된 최종 성능 — y/1000 기준 MSE**

| 전략 | Train MSE | Validation MSE |
| --- | ---: | ---: |
| Scratch | 0.614796 | **1.326033** |
| Feature Extraction | 1.163568 | 1.646490 |
| Fine-tuning | 0.875200 | 1.560943 |

- 이 실험에서는 **Scratch의 검증 MSE가 가장 낮았다.** 사전학습이 항상 성능 개선으로 이어지지는 않는다.
- 300 epoch 시점에는 Feature Extraction과 Fine-tuning의 Validation MSE가 둘 다 1.654438이었다. 이후 Fine-tuning의 Backbone 해제가 차이를 만든다.
- 가능한 원인으로 Source/Target 분포 차이, 초기화, 학습률, 모델 적합성을 검토할 수 있지만 **이번 기록만으로 부정적 전이가 원인이라고 단정할 수 없다.**

**2강 저장된 시간 측정 — 3회 중앙값**

| 전략 | Target 학습 시간 | Source 사전학습 포함 추정 총시간 |
| --- | ---: | ---: |
| Scratch | 0.023993초 | 0.023993초 |
| Feature Extraction | **0.006659초** | 0.260407초 |
| Fine-tuning | 0.010844초 | 0.264592초 |

Source 사전학습 시간은 0.253748초로 기록되었다. 이미 Pretrained Model이 있는지, 직접 만들어야 하는지에 따라 선택이 달라진다. 작은 연산의 실행 시간은 환경에 민감하므로 절대적 속도 보장으로 해석하지 않는다.

**2강 기초 과제 — 검증 MSE ≤ 1.60 조건**

1. 성능만 우선: **Scratch** (검증 MSE 1.326033).
2. 사전학습 모델이 이미 있고 Target 학습 시간 최소: **Fine-tuning** (조건 통과 모델 가운데 더 빠름).
3. 사전학습 모델이 없고 한 번만 학습하며 전체 시간 최소: **Scratch**.

## 2. 내가 궁금했던 질문과 이해한 답

1. **사전학습과 전이학습은 같은가?** 아니다. Pretrained Model은 학습된 결과물이고 Transfer Learning은 그 결과물을 다른 데이터에 재사용하는 방법이다.
2. **Freeze하면 계산도 멈추는가?** 아니다. Forward에서 특징 H는 계속 계산하고, 동결한 W1/b1만 업데이트하지 않는다. 고정 입력에서는 H를 캐시할 수 있다.
3. **왜 Fine-tuning은 작은 학습률을 쓰는가?** 이미 학습된 특징을 과도하게 바꾸지 않도록 1회 업데이트 크기를 제한하기 위한 실용적 선택이다. 최적 값은 검증해야 한다.
4. **왜 1강에서는 Fine-tuning이 좋고 2강에서는 Scratch가 좋은가?** 평가에 포함된 전략과 전처리·학습 설정이 다르기 때문이다. 서로 다른 실험 결과를 직접 대조해서 일반화할 수 없다.
5. **Validation MSE만으로 최종 일반화 성능을 확정할 수 있나?** 아니다. 전략 선택에 Validation을 활용하면 별도 Test Set에서 최종 성능을 평가하는 것이 필요하다.
