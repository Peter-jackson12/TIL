### 1-1. 단어가 여러 토큰으로 나뉘는 기준은? 토큰화에도 추론이 필요한가?

- LLM은 문장을 곧바로 이해하는 것이 아니라 우선 **토크나이저(tokenizer)**로 텍스트를 토큰 ID의 시퀀스로 변환한다. 하나의 단어가 여러 토큰이 될 수도, 공백이나 문장부호가 토큰에 포함될 수도 있다.
- **BPE(Byte Pair Encoding)** 계열의 토크나이저는 학습 말뭉치에서 빈번한 조각들의 결합 패턴을 바탕으로 어휘와 병합 규칙을 만든다. 실제 입력을 처리할 때는 정해진 규칙을 적용하는 **알고리즘적 전처리**이며, 매 단어마다 LLM이 추론해서 분할하는 방식이 아니다.
- 단어 길이만으로 토큰 수가 결정되지는 않는다. 자주 나오는 단어·조각, 공백, 언어, 특수문자, 모델별 토크나이저에 따라 분할이 달라진다. BPE 외에도 Unigram 등 다른 방식이 있다.
- **구분:** 토큰화(문자열 → 토큰 ID) → 임베딩(토큰 ID → 벡터) → Transformer 문맥 처리 → 다음 토큰 예측. 앞의 분할 규칙과 뒤의 모델 추론은 별개의 단계다.

### 1-2. 하네스 엔지니어링과 코드 에이전트의 관계

- **코딩 에이전트**는 코드를 탐색·작성·실행·검증하는 작업 시스템이다. Codex와 Claude Code는 그 예시다.
- **하네스 엔지니어링(Harness Engineering)**은 모델이 안정적으로 작업하도록 주변 실행 환경을 설계하는 방법론이다. 도구 연결, 컨텍스트 제공, 권한과 승인, Skills, Hooks, 검증 루프, 상태 보존과 실패 복구가 여기에 해당한다.
- 따라서 **하네스 = 코드 에이전트**는 아니다. 코드 에이전트는 하네스가 적용된 시스템 중 하나이며, 하네스는 리서치·브라우저·업무 자동화 에이전트에도 적용할 수 있다.
- 특히 중요한 것은 '모델을 얼마나 똑똑하게 쓰는가'뿐 아니라 **실패 시 어디서 멈추고, 어떤 근거로 재시도하며, 결과를 누가 독립 검증하는가**를 설계하는 것이다.

### 1-3. REST API, OpenAPI, FastAPI, MCP를 혼동하지 않기

| 용어 | 정체 | 기억할 핵심 |
| --- | --- | --- |
| **REST API** | HTTP 자원·메서드 등을 활용하는 API 설계 스타일 | API를 **어떻게 설계하는가** |
| **OpenAPI Specification (OAS)** | HTTP API의 엔드포인트·요청·응답·인증 등을 기술하는 표준 명세 | API를 **어떻게 기술하는가** |
| **FastAPI** | Python에서 웹 API 서버를 구현하는 프레임워크 | API를 **무엇으로 만드는가** |
| **MCP** | AI 애플리케이션과 외부 도구·데이터를 연결하는 프로토콜 | 에이전트가 외부 기능을 **어떻게 호출·연결하는가** |

- OpenAPI는 단순한 사람이 읽는 안내문 이상의 **기계가 해석 가능한 계약/명세 형식**이다. 예를 들어 FastAPI로 만든 REST API의 OpenAPI 문서를 자동 생성할 수 있다.
- 키움증권의 **'OpenAPI+'** 같은 상표·상품명과 일반 표준인 **OpenAPI Specification**은 구분해야 한다.
- 기존 REST API나 IMAP·CalDAV 등의 기능을 AI에서 호출하도록 **MCP 서버로 감싸는 방식**이 가능하다. MCP가 데이터 제공자의 인증·권한·API 제한을 없애 주는 것은 아니다.

### 1-4. 네이버 개인 메일·캘린더를 Claude Code와 ChatGPT에서 쓰려면?

- 네이버 개인 메일은 **IMAP(읽기/동기화)**, **SMTP(발송)**를 이용하는 연결 경로가 있다. 네이버 메일 설정에서 IMAP/SMTP를 켜고 **2단계 인증과 애플리케이션 비밀번호**를 사용해야 한다.
- 네이버 캘린더는 **CalDAV** 연결 경로가 있다. 공식 안내의 서버는 `caldav.calendar.naver.com`(SSL/443)이다. 단, 클라이언트 환경에 따라 읽기·쓰기 가능 범위가 달라질 수 있고 네이버 공식 도움말은 Android 미지원, Mac 읽기 전용 등 제약을 안내한다.
- 네이버 개발자 센터의 공식 **캘린더 API**는 기본적으로 네이버 로그인을 통해 사용자의 캘린더에 일정을 **담는 기능**을 제공한다. 이를 일반적인 일정 목록 조회·수정·삭제 전체를 제공하는 API와 동일시하면 안 된다.
- Claude Code는 **로컬 MCP 서버**를 연결하는 방식이 자연스럽지만, ChatGPT에서 같은 로컬 프로세스를 그대로 호출할 수 있는 것은 아니다. ChatGPT 쪽은 지원하는 **원격 연결 방식과 인증**을 별도로 확인해야 한다.
- 기존 메일/CalDAV MCP 패키지를 후보로 살펴봤지만, 특정 패키지의 최신 유지보수 상태나 네이버 계정에서의 **실제 정상 동작은 검증하지 않았다**. 초기 도입은 읽기 전용·최소 권한·별도 애플리케이션 비밀번호·비밀정보 미커밋 원칙을 적용한다.

### 1-7. 활성화 함수가 필요한 이유: 비선형 관계와 선형 베이스라인

- 각 레이어가 활성화 함수 없이 `h = W₁x + b₁`, `y = W₂h + b₂`만 계산한다면, 합성 결과는 `y = (W₂W₁)x + (W₂b₁ + b₂)`다. 즉 **여러 아핀 변환은 하나의 아핀 변환으로 합쳐진다**. 층을 깊게 쌓는 것만으로 곡선형 관계를 표현할 수는 없다.
- **ReLU·tanh·Sigmoid 같은 비선형 활성화 함수**가 중간에 들어가면 이 합성이 단일 아핀 변환으로 축약되지 않고, 더 복잡한 함수를 학습할 수 있다.
- 실제 예측 관계가 단순한 선형에 가깝다면 복잡한 신경망은 계산 비용·과적합 위험 면에서 불필요할 수 있다. 다만 **딥러닝도 선형 관계를 학습할 수 있으므로 반드시 예측이 부정확해진다는 뜻은 아니다.**
- 금융 시계열에서 실제 관계가 비선형일 수 있어도, 그 패턴이 미래에도 유지되는지는 별개다. **선형회귀 같은 단순 모델을 베이스라인으로 두고 시간순 검증으로 성능을 비교**해야 한다.

### 1-8. 은닉층과 출력층의 활성화 함수는 역할이 다르다

- 일반적인 MLP는 은닉층마다 `z = Wx + b` 다음에 활성화 함수 `a = f(z)`를 적용한다. 다만 모든 연산이나 모든 블록에 활성화 함수가 반드시 하나씩 필요한 것은 아니다.
- **tanh**는 출력 범위가 **-1~1**이며 0을 중심으로 대칭이다. RNN·LSTM에서 사용되지만 큰 절댓값 영역에서 기울기가 작아지는 **기울기 소실**에 주의한다.
- **ReLU**는 `max(0, x)`로, 음수 구간을 0으로 만들고 양수 구간은 그대로 통과시킨다. 깊은 MLP에서 흔히 사용한다.
- **은닉층에서 tanh를 사용해 -1~1 값이 나오더라도 출력값이 그 범위에 갇히지는 않는다.** 출력층의 가중치와 편향이 `y = W_out h + b_out`처럼 결합해 더 큰 값을 만들 수 있기 때문이다.
- 최종 출력층은 문제에 맞춰 선택한다. **수치 회귀는 선형(활성화 없음)**, **이진 확률 예측은 Sigmoid**, **서로 배타적인 다중 클래스 확률은 Softmax**가 대표적이다. 출력층만 선형이어도 앞선 은닉층이 비선형이면 **신경망 전체는 비선형 모델**이다.

### 1-9. 편향이 있는데 왜 비선형 활성화 함수가 또 필요한가?

- 수학에서 `y = Wx`는 **선형 변환**, `y = Wx + b`는 **아핀 변환(Affine Transformation)**이다. 편향이 있는 함수는 일반적으로 `f(0) = 0`을 만족하지 않기 때문에 엄밀한 선형 변환은 아니다.
- 하지만 아핀 변환도 직선을 직선으로 보내며, 아핀 변환 여러 개를 쌓아도 하나의 아핀 변환으로 합칠 수 있다. **편향이 있다고 곡선형 비선형 표현 능력이 생기는 것은 아니다.**
- 편향은 `ReLU(wx+b)`에서 활성화가 시작되는 **경계 위치를 이동**시키고, ReLU는 그 경계에서 함수를 꺾는다. 두 요소의 역할이 다르다.
- PyTorch의 `nn.Linear`는 이름과 달리 `bias=True`가 기본이므로 실제로 아핀 변환을 수행한다. `bias=False`이면 편향 없는 선형 변환이다.

### 1-10. TensorFlow보다 PyTorch가 주류가 된 배경과 코드 비교

- **TensorFlow 1.x**는 정적 계산 그래프를 미리 정의하고 Session으로 실행하는 방식이 중심이었고, **PyTorch**는 실행하면서 그래프를 구성하는 동적 방식으로 실험·디버깅이 편했다. 연구자들이 PyTorch를 채택하고 논문 구현·사전학습 모델·라이브러리 생태계가 성장한 것이 확산의 주요 배경이다.
- **현재의 차이를 초창기 특징으로 단정하면 안 된다.** TensorFlow 2.x는 Eager Execution을 기본으로 하고, PyTorch 2.x는 `torch.compile` 최적화를 제공한다. 학습 속도는 모델·하드웨어·설정에 따라 달라서 한쪽이 항상 빠르다고 할 수 없다.
- **TensorFlow/Keras**는 간단한 모델 작성 및 기존 배포 생태계에서 강점이 있고, **PyTorch**는 자유로운 학습 루프·최신 연구·LLM 모델 생태계에서 강점이 있다. Keras 3는 TensorFlow 외에 PyTorch·JAX 백엔드도 지원한다.
- 기본적인 회귀 MLP는 다음처럼 은닉층에 ReLU를 넣고 **마지막 출력층에는 활성화 함수를 넣지 않는 식**으로 구성할 수 있다.

```python
import torch.nn as nn

model = nn.Sequential(
    nn.Linear(10, 64), nn.ReLU(),
    nn.Linear(64, 32), nn.ReLU(),
    nn.Linear(32, 1),  # 회귀 출력: 선형
)
```

### 1-11. ReLU와 콜옵션 매수 포지션의 수학적 연결

- ReLU의 모양은 **콜옵션 매수의 만기 페이오프**와 정확히 대응한다. `ReLU(x) = max(0, x)`이고, 행사가격 `K`인 콜옵션의 만기 페이오프는 `max(0, S_T - K) = ReLU(S_T - K)`다.
- 뉴런 `ReLU(wx+b)`에서 `w=1`, `b=-K`라 두면 행사가격만큼 이동된 콜 페이오프와 같은 모양이 된다. 여러 ReLU의 가중합은 콜 스프레드 등 **구간별 선형 페이오프**와 연결된다.
- 예컨대 `K₁ < K₂`일 때 불 콜 스프레드의 **만기 페이오프**는 `ReLU(S_T-K₁) - ReLU(S_T-K₂)`다.
- **페이오프와 순손익을 구분**한다. 콜옵션 매수의 실제 만기 **순손익**은 지불한 프리미엄을 빼야 하고, 만기 전 옵션 가격은 시간가치·변동성 등이 반영되므로 단순 ReLU 모양과 다르다.

## 2. 내가 궁금했던 질문과 이해한 답

1. **'한 단어가 왜 여러 토큰이 되지?'** → 고정 길이 글자 분할이 아니라 모델별 어휘·병합 규칙에 따라 쪼개진다.
2. **'토큰화도 매번 추론해야 하나?'** → 토크나이저 규칙을 적용하는 처리이며 모델의 문맥 추론과는 다르다.
3. **'코드 에이전트가 하네스 엔지니어링의 결과물 아닌가?'** → 대체로 맞지만, 하네스는 더 넓은 설계 영역이고 코드 에이전트는 적용 사례다.
4. **'REST API와 OpenAPI는 키움증권의 특수용어인가?'** → 둘 다 범용 개념이며, 키움의 OpenAPI+는 별개 상품명이다.
5. **'OpenAPI는 그냥 설명서인가?'** → 사람이 읽는 설명을 넘어 자동화 도구가 활용할 수 있는 표준 구조화 명세다.
6. **'네이버에 Gmail처럼 바로 붙는 AI 플러그인이 없다면 MCP를 쓰나?'** → 기존 IMAP/SMTP·CalDAV 또는 공식 API를 감싼 MCP가 한 경로다. Claude Code와 ChatGPT는 연결 방식이 다르다.
7. **'매월 지급받은 Claude API 크레딧을 CLI로 못 쓰나?'** → 대화형 `claude`는 대상이 아니지만, 조건을 갖춘 **직접 실행 `claude -p` + API 키**는 대상이다.
8. **'Luna, Carbon, Argon 중 무엇이 가성비·한국어 작업에 낫나?'** → 가격표와 동일한 테스트셋이 필요하며, 한국어에 관한 커뮤니티 평판은 검증과 구분한다.


9. **'비선형 함수를 쓰는 이유는 예측 대상이 비선형인 경우가 많아서인가?'** → 비선형 표현 능력을 얻기 위해서다. 선형 문제가 맞다면 복잡한 딥러닝보다 단순 모델이 더 효율적일 수 있다.
10. **'활성화 함수는 모든 은닉층에 쓰나?'** → 전형적 MLP에서는 은닉층마다 사용하지만 모든 블록의 모든 연산에 필수인 것은 아니다.
11. **'tanh도 활성화 함수인가?'** → 맞다. -1~1 범위의 비선형 함수이며 기울기 소실에 주의한다.
12. **'은닉층 출력이 -1~1이어도 주가처럼 큰 값을 예측할 수 있나?'** → 가능하다. 은닉층 범위와 최종 선형 출력층의 범위는 다르다.
13. **'편향이 있으면 활성화 함수 없이도 비선형 아닌가?'** → 엄밀히 아핀 변환이지만, 여러 아핀 층은 하나로 합쳐져 곡선 표현 능력이 생기지 않는다.
14. **'편향이 들어간 선형 변환을 아핀 변환이라 하나?'** → 맞다. `Wx+b`는 아핀이고 `Wx`는 선형이다.
15. **'TensorFlow보다 PyTorch를 많이 쓰는 이유는?'** → 초기의 개발·디버깅 경험, 연구 코드 및 생태계 효과가 컸다. 현재는 두 프레임워크 모두 동적 실행과 성능 최적화 수단이 있다.
16. **'ReLU는 콜옵션 매수와 닮지 않았나?'** → 닮은 정도가 아니라 콜옵션 **만기 페이오프**는 행사가격만큼 이동한 ReLU와 동일하다.

## 3. 확인 범위와 주의점

- **오늘 ChatGPT 질문과 공식 문서로 확인한 개념을 정리**한 기록이다. 네이버 MCP의 설치·인증·송수신, Claude 크레딧 실제 차감, 모델별 벤치마크를 오늘 직접 실행했다고 볼 근거는 없다.
- 서비스 정책·모델 단가·지원 범위는 바뀔 수 있다. 특히 네이버 CalDAV와 Anthropic 크레딧의 **제품별 적용 조건**은 도입 직전에 다시 확인해야 한다.
- 개인 건강 상태 등 공개 저장소에 남길 필요가 없는 질문은 기록에서 제외했다.
- 활성화 함수·프레임워크·옵션 페이오프 내용은 **대화에서 이해한 개념과 예시**이며, PyTorch/TensorFlow 학습 실험이나 옵션 매매 백테스트를 직접 수행한 결과는 아니다. 이 대화의 마지막 연계 질문은 11월 13일에 이어졌지만, 요청에 따라 11월 12일 TIL에 한데 묶었다.
