## 1. 오늘 배운 것

오늘은 ChatGPT에서 이어 간 질문을 바탕으로 **LLM의 내부 구조**, **OCR 모델과 학습 데이터**, **DB·API 기본 개념**, **국내 장 시작 전 주문 체결 구조**, **AI 시대의 단기 매매 전략 검증**을 정리했다. 수업·질문에서 이해한 개념과 실제 구현·실험 결과를 혼동하지 않는다.

### 1-1. CNN → RNN/LSTM → Transformer: 무엇이 달라졌나?

- **CNN**은 합성곱 필터로 국소 패턴을 추출한다. 이미지 처리에 강하고, 텍스트·시계열에도 1D 합성곱 형태로 적용할 수 있다.
- **RNN**은 이전 시점의 hidden state를 다음 시점으로 전달하며 순서대로 처리한다. 장기 의존성과 기울기 소실·폭주에 취약하다.
- **LSTM**은 RNN의 변형으로, cell state와 입력·망각·출력 게이트를 이용해 필요한 정보를 선택적으로 유지·갱신한다. 이름의 'long-term memory'가 무제한의 외부 저장소라는 뜻은 아니다.
- **Transformer**는 순환 연결 대신 Attention을 중심으로 토큰 간 관계를 계산한다. 학습 중 여러 위치를 병렬 처리하기 쉬우며, 현대 LLM의 주류 구조다. 다만 RNN/CNN이 시간순으로 완전히 대체되어 사라졌다는 뜻은 아니다.
- 유명한 논문 **Attention Is All You Need (2017)**는 원래 Encoder–Decoder Transformer를 제안했다. GPT 계열의 일반적인 텍스트 생성은 주로 **Decoder-only**와 causal(masked) self-attention을 사용한다.
- **학습/프리필(prefill)**에서는 알려진 토큰들을 행렬 연산으로 병렬 처리할 수 있지만, **자기회귀 생성(decode)**에서는 새 토큰을 다음 토큰의 입력으로 써야 하므로 출력은 순차적으로 늘어난다. '한 단어씩'이 아니라 **한 토큰씩** 생성한다.

### 1-2. Query, Key, Value를 검색 비유로 이해하기

예를 들어 '동물은 도로에서 뛰었다. 그것은 빨랐다.'에서 '그것'이 무엇을 참조하는지 판단한다고 가정하자.

- **Query (Q)**: 현재 토큰('그것')이 찾는 관련 정보의 조건을 표현한다.
- **Key (K)**: 각 토큰이 무엇과 관련 있는지 비교하는 표식 같은 벡터다. Q와 K의 유사도로 주의 점수를 만든다.
- **Value (V)**: 주의 가중치가 결정된 뒤 실제로 모아올 내용 벡터다.
- **수식:** `Attention(Q,K,V) = softmax(QKᵀ / √dₖ) V`.
- **Multi-Head Attention**은 서로 다른 학습 가중치로 여러 Q/K/V 투영을 만든다. 한 head는 대명사 참조, 다른 head는 구문·거리·의미 관계 등에 반응할 수 있다. 이 역할들은 학습으로 생길 수 있는 **직관적 예시**이지 head별 고정 역할이 아니다.
- **Causal mask**는 현재 위치에서 미래 토큰을 보지 못하게 하는 제한이다. **KV cache**는 생성 과정에서 이전 토큰의 K/V 결과를 보관해 매 단계에 다시 계산하지 않도록 하는 추론 최적화다. 두 개념은 관련되지만 목적이 다르다.
- **MLA(Multi-head Latent Attention)**는 KV를 압축한 잠재 표현으로 다루어 캐시 부담을 낮추는 Attention 설계다. **MLP(Multi-Layer Perceptron)**와 이름이 비슷해 혼동했지만 다른 개념이다.
- **MLP/FFN**은 Transformer 블록에서 Attention 다음에 각 토큰 표현을 비선형 변환하는 층이다. Attention이 토큰 간 정보를 섞는다면, FFN은 각 위치의 표현을 가공한다.

### 1-3. LLM의 추론 레벨, 레이어 수, 출력 토큰 한도

- 같은 모델에서 **추론 강도(thinking effort)**를 올린다고 일반적으로 가중치 수나 Transformer 레이어 수가 바뀌는 것은 아니다. 주로 답을 내기 전 추가 추론 계산/토큰에 더 많은 예산을 허용하는 방식이다. 구체적인 구현은 제공사별로 다르다.
- **컨텍스트 윈도우**는 입력과 출력 등 모델이 다룰 수 있는 토큰 범위와 관련되고, **최대 출력 토큰**은 한 응답에서 생성할 수 있는 분량에 대한 별도 제한이다. 추론 토큰과 사용자에게 보이는 출력 토큰의 집계 방식도 모델별로 다를 수 있다.
- 긴 독립 코드 리뷰가 토큰 한도에 걸려 결과가 사라지거나 실패하면 비용·시간이 낭비될 수 있다. 대응책은 리뷰 분할, 출력 형식 제한, 체크포인트식 부분 산출, 스트리밍·중단 사유 확인 및 중단 지점부터 이어가기다. **부분 출력 회수 가능 여부는 API/도구별로 달라 직접 확인해야 한다.**

### 1-4. CAPTCHA OCR: CNN, CRNN, 경량 Transformer의 비교

오늘의 문제의식은 이미지 속 왜곡된 문자를 읽는 모델의 학습 난도와 GPU 비용이었다.

| 방식 | 특징 | 고려할 점 |
| --- | --- | --- |
| **CNN + 문자별 분류** | 문자 위치·길이가 고정적이면 단순하고 빠르다 | 분할이 어렵거나 길이가 가변적이면 불리 |
| **CRNN + CTC** | CNN으로 이미지 특징 추출, 순서 모델로 문자열 예측 | 문자를 정확히 잘라내지 않아도 학습 가능 |
| **경량 Transformer OCR** | Attention으로 복잡한 글자 간 관계 처리 가능 | 일반적으로 데이터·메모리·튜닝 비용 고려 필요 |

- 노트북의 **RTX 5060 Laptop GPU와 RAM 32GB 이상** 조건에서 작은 CNN/CRNN과 경량 Transformer OCR의 **학습·추론 가능성**을 비교했다. 정확한 속도·VRAM 사용량은 모델, 이미지 해상도, batch size, GPU의 실제 VRAM·전력 설정에 따라 달라진다.
- **Kaggle 등의 공개 데이터셋**은 빠르게 출발하기 좋고, **CAPTCHA 생성기**는 레이블을 자동으로 갖는 합성 데이터를 대량 생성하는 데 유리하다. 하지만 생성 이미지와 실제 대상의 글꼴·왜곡·노이즈 분포가 다르면 일반화 성능이 떨어질 수 있다.
- 처음부터 모델을 새로 만들기보다 검증 가능한 기존 OCR 구현을 **베이스라인**으로 시작하는 편이 개발·평가에 유리하다. 실제 자동화 방지 장치 우회 여부와 무관하게, 이번 정리는 일반적인 OCR 아키텍처 학습에 한정한다.
- **직접 학습·벤치마크를 실행한 것은 아니다.**

### 1-5. `.db` 확장자는 데이터베이스 형식을 보장하지 않는다

- `.db`는 흔히 데이터베이스 파일에 붙이는 **관례적 확장자**일 뿐, 특정 엔진·파일 구조를 보장하지 않는다.
- **SQLite**의 대표적인 데이터베이스 파일은 파일 시작 부분에 `SQLite format 3` 시그니처를 사용한다. 반면 다른 프로그램의 `.db`는 전용 형식일 수 있다.
- **Parquet**는 일반적으로 `.parquet` 확장자를 갖는 컬럼형 파일 포맷이며, SQLite와 같은 DB 엔진이 아니다. `.db` 파일이라고 해서 Parquet 뷰어로 열리는 것은 아니다.
- 파일을 전달받을 때는 **생성 도구/엔진·버전·스키마·인코딩·필요한 읽기 도구**를 함께 받는 편이 안전하다. 모르는 파일은 원본을 보존하고 헤더·메타데이터를 확인한 뒤 적합한 도구로 열어야 한다.

### 1-6. REST API / FastAPI / OpenAPI 다시 구별하기

| 이름 | 역할 | 외우는 기준 |
| --- | --- | --- |
| **REST API** | 자원·HTTP 메서드 기반 API 설계 스타일 | **설계 방식** |
| **FastAPI** | Python에서 API 서버를 개발하는 프레임워크 | **구현 도구** |
| **OpenAPI Specification** | HTTP API의 엔드포인트·입력·출력 등을 기술하는 표준 명세 | **사용 설명서 + 기계가 읽는 계약** |

FastAPI는 OpenAPI 명세와 대화형 문서를 자동 생성할 수 있다. 세 개는 경쟁 기술이 아니며, **FastAPI로 REST 스타일 API를 만들고 OpenAPI 명세로 설명**하는 식으로 함께 쓰인다.

### 1-7. 국내 주식 장전 시간: NXT 프리마켓과 KRX 시가 단일가

- **NXT 프리마켓**은 **08:00~08:50**에 실제 주문이 연속 체결되는 시장이다. 08:50~09:00에는 KRX 시가 형성을 위해 NXT 프리마켓 거래가 끝난다.
- **KRX 정규장 시가 단일가**는 일반적으로 **08:30~09:00**에 호가를 모아 개장 시점의 **하나의 시가**를 결정하는 방식이다. 30분 동안 몇 분 간격으로 계속 체결하는 것이 아니다. 시가 단일가 마감에는 **임의종료(random end)** 가능성이 있어 '마지막 순간'의 정확한 종료를 전제로 해서는 안 된다.
- 단일가에서 결정되는 가격은 한쪽의 최고 제시가나 마지막 주문가 자체가 아니라 **누적 주문의 체결 가능 수량 등을 반영해 결정된 단일가**다. 더 높은 매수 지정가를 써도 그 높은 가격에 반드시 체결되는 것은 아니며, 체결된다면 보통 결정된 단일가로 체결된다.
- **체결 우선순위는 가격 우선 → 같은 가격이면 시간 우선**을 기본으로 한다(가격제한폭에서 결정되는 경우 등 예외 존재). 따라서 같은 가격의 경쟁 주문이 많으면 먼저 낸 주문이 유리할 수 있다.
- 주문을 늦게 내는 것은 최종 수급을 관찰하는 장점이 있지만 **동일 가격 주문의 시간 우선순위를 잃고 임의종료 위험**이 있다. 반대로 높은 가격으로 일찍 주문하는 것은 체결 가능성을 높이는 대신 불리한 주문 조건을 부담할 수 있다. **무조건 마지막에 내는 전략이 유리하지는 않다.**
- 정정·취소 허용 범위, 장전 시간외 종가와 일반 시가 단일가의 구분, 증권사 주문 접수 시점은 거래소·상품·주문 유형의 세부 규칙을 따로 확인한다.

### 1-8. AI 시대 스캘핑 경쟁력: 진입장벽보다 검증·실행 품질

- AI가 코드 작성·데이터 정리·백테스트를 저렴하게 만들면 신규 참여자와 기관의 전략 탐색 비용이 줄어들 수 있다. 다만 경쟁 심화의 **실제 정도**는 가설이며 시장 데이터로 평가해야 한다.
- 경쟁력을 유지할 후보는 남들이 쉽게 복제할 수 없는 **데이터 품질·시점 정합성**, 호가/체결 **미시구조의 이해**, **슬리피지·수수료 반영**, 실행 지연·오류 관리, 독립된 **홀드아웃 검증**, 전략 중단 규칙이다.
- **높은 인샘플 Sharpe**만으로 미래 성과가 보장되지 않는다. 다수 후보를 실험한 뒤 최고 성과만 고르는 선택 편향과 과최적화에 특히 주의한다.
- 대화에서 언급한 **'888개 알고리즘 전략 연구'의 샤프비율 설명력 주장**은 원문 전체와 연구 설계를 이번 기록에서 독립 검증하지 않았다. 따라서 이를 일반 법칙이나 확인된 결론으로 인용하지 않는다.
- 이전에 관심을 둔 **TPI**도 약어의 구체적 정의·산식이 이 대화에 명시되지 않았으므로 임의로 설명하지 않았다. 지표의 가치를 보려면 **미래 기간 순위 예측력(예: Spearman 상관), net 수익·drawdown, 거래 횟수와 비용 민감도, 다른 시기·종목·시장으로의 재현성**을 확인해야 한다.
- 독립 리뷰를 자동화하더라도 리뷰 모델의 일치가 **독립된 시장 검증**을 대체하지는 못한다. 실제로 미래 정보를 사용하지 않는 데이터 분리와 실거래/모의 실행 검증이 따로 필요하다.

## 2. 오늘 질문으로 정리된 핵심 답

1. **'Transformer는 RNN을 병렬화한 다음 세대인가?'** → 순환 구조 대신 Attention을 활용하며, 학습 과정의 병렬 처리 이점이 크다. 생성은 자기회귀라 토큰 단위로 이어진다.
2. **'KV cache와 causal attention은 같은 건가?'** → 전자는 과거 계산 재사용, 후자는 미래 정보 차단이다.
3. **'Multi-head, MLA, MLP가 헷갈린다.'** → Multi-head는 여러 Attention 관점, MLA는 잠재 표현을 활용한 Attention 설계, MLP는 토큰 표현을 변환하는 피드포워드 층이다.
4. **'추론 강도를 높이면 레이어나 파라미터를 더 쓰나?'** → 일반적으로 동일 모델의 추가 추론 예산 문제이지 파라미터 수 변경이 아니다.
5. **'`.db`는 무슨 프로그램으로 열어야 하나?'** → 확장자가 아닌 **실제 파일 포맷과 생성 엔진**을 확인한다.
6. **'NXT 프리마켓과 KRX 동시호가는 어떻게 다른가?'** → 08:00~08:50은 NXT 연속매매, 08:30~09:00은 KRX 시가 결정을 위한 호가 집계다.
7. **'단일가에서 막판 주문이 무조건 유리한가?'** → 수급을 더 관찰하지만, 시간 우선순위와 임의종료 측면에서는 불리할 수 있다.
8. **'샤프보다 TPI로 미래 수익을 예측할 수 있나?'** → 지표 정의를 고정한 뒤 표본 외 예측력과 비용 차감 후 성과로 검증해야 한다.

- NXT/KRX 거래시간·매매 원칙은 **거래소 공식 안내**를 기준으로 적었다. 거래소 운영시간이나 예외 규정은 실제 주문 전에 재확인해야 한다.
- 공개 TIL이므로 개인 일상·건강·구매 상담 등 학습 기록의 목적과 직접 관계없는 대화는 제외했다.
