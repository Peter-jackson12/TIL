### 1장 — HTML·JSON 구조와 공통 스키마

- **HTML:** 웹 문서의 태그·속성·계층 구조. `div`, `span`, `a`, `class`, `id`, `href` 및 DOM의 부모·자식 관계로 데이터 위치를 찾는다. 브라우저 Elements 탭에 보이는 DOM은 JavaScript가 변경한 결과일 수 있어 초기 응답 HTML과 구분한다.
- **JSON:** Key–Value로 구성된 Object와 순서 있는 Array, 중첩 구조를 이해한다. 파싱 결과는 Python `dict`·`list`; `true/false/null`은 `True/False/None`에 대응한다.
- 예: `data["quotes"][0]["author"]["name"]`은 첫 명언의 작성자 이름을 찾아간다.
- **분석 단위(grain):** 명언 하나를 한 행으로 정하고, 출력 스키마를 `text`, `author`, `tags`, `source_url`로 통일한다. `source_url`은 반드시 원본에 있던 필드가 아니라 수집 시점의 출처 추적을 위해 구성한다.
- HTML은 `BeautifulSoup.select()/select_one()`과 `get_text(strip=True)`, JSON은 Key/인덱스를 이용하여 같은 형태의 Dictionary를 만든다.
- `pd.DataFrame(records)`로 변환하여 `shape`, `columns`, `info()`, `head()`를 검사하고 `to_csv(index=False, encoding="utf-8-sig")`로 저장 후 `read_csv()`로 재검증한다. CSV는 모든 자료형을 보존하지 않는다.
- 동일한 명언을 HTML/JSON 양쪽에서 수집해 단순 결합하면 중복 데이터가 될 수 있다.

### 2장 — API·HTTP와 여러 페이지 수집

- **클라이언트–서버:** Python의 HTTP GET 요청에 서버가 상태 코드, 헤더, 본문으로 응답한다. URL은 프로토콜·도메인·경로·Query Parameter로 구분하며 `params={"page":1}`로 조건을 전달할 수 있다.
- 대표 응답: `200` 정상 처리, `403` 접근 거부, `404` 자원 없음, `429` 요청 제한, `500` 서버 내부 오류.
- `requests.get(..., timeout=...)`와 `raise_for_status()`, `response.json()`을 사용한다. **요청 성공(HTTP 200) ≠ JSON 파싱 성공 ≠ 필수 필드 추출 성공**이다.
- API 페이지네이션은 `page`를 증가시키고 `has_next`로 마지막 페이지를 판단한다. HTML은 `li.next a`의 `href`에서 Next 링크를 찾고 `urljoin(response.url, href)`로 전체 주소를 만든다.
- 정적 크롤링은 초기 HTML에 데이터가 있을 때 Requests+BeautifulSoup을 이용한다. 동적 페이지에서는 먼저 Network 탭의 실제 JSON/API 요청과 script 안 데이터의 존재 여부를 확인한 후 필요할 때 Selenium·Playwright를 검토한다. **JavaScript 사용 = 무조건 브라우저 자동화 필요**는 아니다.
- 각 명언을 `div.quote` 내부에서 `span.text`, `small.author`, `a.tag`로 함께 뽑아야 레코드가 섞이지 않는다. `select_one()`은 요소가 없으면 `None`을 반환한다.
- 수집 안정성: timeout, 예외 처리, `max_pages`, `time.sleep()`, 페이지별 누적 건수, 정상적인 종료 조건을 점검한다. 중간 페이지가 실패했다면 남은 부분 데이터만으로 수집 완료라고 표시하지 않는다.
- `quotes_raw.csv`(API)와 `quotes_html_raw.csv`(HTML)는 각각의 수집 결과로 보존한다. 데이터 출처와 수집 방식이 다르므로 합치기 전에 중복을 확인한다.

```python
# 교안에서 다룬 메서드를 묶은 흐름 요약(재작성 예시, 실제 실행 아님)
import requests
from bs4 import BeautifulSoup
from urllib.parse import urljoin

response = requests.get("https://quotes.toscrape.com/", timeout=10)
response.raise_for_status()
soup = BeautifulSoup(response.text, "html.parser")
for block in soup.select("div.quote"):
    text_node = block.select_one("span.text")
    author_node = block.select_one("small.author")
    if text_node is None or author_node is None:
        raise ValueError("필수 명언 요소 누락")
    text = text_node.get_text(strip=True)
    author = author_node.get_text(strip=True)
next_link = soup.select_one("li.next a")
next_url = urljoin(response.url, next_link["href"]) if next_link else None
```

### 3장 — 원시 데이터의 품질 진단과 정제

- **구조 검사:** `shape`, `columns`, `dtypes`, `info()`, `head()`. 컬럼 개수가 4개라도 `text`가 빠지고 `Unnamed: 0`이 있다면 올바른 스키마가 아니다.
- **중복 기준:** 명언의 `text` + `author`. `duplicated(subset=["text","author"], keep=False)`는 첫 행까지 포함한 **중복 그룹의 모든 행**을 표시한다. 이는 `drop_duplicates(keep="first")`로 **실제 제거될 행 수**와 다르다.
- **결측 검사:** `NaN`, `None`, `pd.NA` 외에 `""`, `"   "`도 확인한다. `isna()`만으로 빈 문자열·공백 문자열을 놓칠 수 있으므로 `str.strip()` 후 빈 문자열을 결측으로 통일한다.
- **완전성 판단:** 파일 안의 값들이 정상이어도 일부 페이지가 누락됐을 수 있다. `source_url`별 건수와 별개로 요청 로그·페이지별 수집 건수·최종 종료 조건을 검증한다.
- **분석 목적에 따라 필수 필드가 다르다:** 단어 빈도는 `text`, 작성자별 분석은 `text + author`, 태그별 분석은 `text + tags`가 필요하다. 본문이 있다면 작성자·태그 누락만으로 모든 행을 제거하지 않는다.
- **정제 순서:** 원본 보존 → `copy()` → 문자열 양끝 공백 제거 → 빈 문자열을 `pd.NA`로 통일 → `dropna(subset=["text"])` → `drop_duplicates(subset=["text","author"],keep="first")` → 컬럼 정렬·결측 표현 통일 → `quotes_clean.csv` 저장·재검증.
- **손실 정보 점검:** 본문+작성자가 같아도 태그나 출처가 다르면 중복 제거 시 부가 정보가 사라질 수 있다. 출처 누락 시 임의 URL을 채우지 않는다. 원문의 문장부호·단어 사이 공백도 무조건 삭제하지 않는다.
- **건수 보존식:** 최종 행 수 = 원시 행 수 − 본문 누락으로 제외한 행 수 − 그 이후 중복으로 제거한 행 수. 순차 처리 기준으로 계산해야 이중 계수를 피한다.

```python
# 3장의 처리 원리를 재구성한 정제 예시(원본 실행 결과 아님)
import pandas as pd

raw = pd.read_csv("quotes_raw.csv", dtype="string", keep_default_na=False)
required = ["text", "author", "tags", "source_url"]
assert set(required).issubset(raw.columns)

clean = raw[required].copy()
for col in required:
    clean[col] = clean[col].str.strip().replace("", pd.NA)

raw_count = len(clean)
without_text = clean.dropna(subset=["text"])
missing_text_count = raw_count - len(without_text)
clean = without_text.drop_duplicates(
    subset=["text", "author"], keep="first"
).copy()
removed_duplicates = len(without_text) - len(clean)

assert len(clean) == raw_count - missing_text_count - removed_duplicates
assert clean["text"].notna().all()
assert not clean.duplicated(subset=["text", "author"]).any()

clean = clean.fillna("")
clean.to_csv("quotes_clean.csv", index=False, encoding="utf-8-sig")
reloaded = pd.read_csv("quotes_clean.csv", dtype="string", keep_default_na=False)
assert clean.reset_index(drop=True).equals(reloaded.reset_index(drop=True))
```

**정제 후 확인:** 컬럼 순서, 필수 본문 존재, 정한 기준의 중복 없음, 단계별 제외 건수 합계, `source_url` 누락, 저장 전후 행 수·값·자료형. 정제 성공은 **전체 페이지 수집 완료의 증거가 아니다.**

1. **200 OK면 데이터 수집이 성공했나?** 아니다. 파싱 성공, 필드 존재, 값의 품질, 모든 페이지 수집 여부는 별도로 확인한다.
2. **HTML과 JSON 중 무엇을 써야 하나?** 제공 형태, 필요한 필드, 접근 정책, 안정성으로 선택한다. 가능하면 적절한 공식 API를 우선 검토하지만 API가 있다고 항상 충분하지는 않다.
3. **중복 후보 수와 제거 수는 같은가?** 아니다. 중복 2행 그룹은 후보 2개지만 하나를 남기면 제거 1개다.
4. **결측이 있는 행은 모두 제거해야 하나?** 아니다. 분석 목적의 필수 필드 여부에 따라 달라진다.
5. **CSV를 저장했으면 작업이 끝났나?** 아니다. 원시·정제 파일을 분리하고 다시 읽어 구조·내용을 확인하며, 별도로 수집 완료 로그도 점검한다.
