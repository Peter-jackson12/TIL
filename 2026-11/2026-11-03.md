### 데이터 수집 1장 2강 — 데이터 추출과 저장

- 분석 목적에 맞게 먼저 데이터의 **한 행(grain)** 과 필수 컬럼·자료형을 정의한다. Quotes to Scrape 예시에서는 명언 1개가 1행이고 `text`, `author`, `tags`, `source_url`을 공통 스키마로 삼는다.
- **HTML**은 태그·속성으로 구조화한 웹 문서이며, **JSON**은 키/값·배열/객체로 데이터를 표현하는 형식이다. 양쪽에서 추출한 값도 같은 스키마의 Dictionary 목록으로 정리하면 DataFrame으로 만들 수 있다.
- HTML: `BeautifulSoup`에서 `div.quote` → `span.text`, `small.author`, `a.tag`를 선택한다. JSON: `quote["text"]`, `quote["author"]["name"]`, `quote["tags"]`를 가져온다.
- `pd.DataFrame(records)` → `to_csv(..., index=False)` → `read_csv()`로 저장 여부·컬럼·행 수를 다시 확인한다. 수집 원본(raw)과 정제 데이터는 구분한다.

### 데이터 수집 2장 1강 — API 요청, JSON 파싱, 페이지네이션

- 클라이언트가 HTTP `GET`으로 서버 API에 요청하고, 상태 코드·`Content-Type`을 확인한 다음 JSON 응답을 파싱한다.
- `requests.get(url, params={"page": 1}, timeout=10)`, `response.raise_for_status()`, `response.json()`의 역할을 구분한다. `200 OK`가 반환되어도 필요한 필드가 존재하는지, 데이터가 실제로 추출되는지는 별도 확인이 필요하다.
- 실습 API: `https://quotes.toscrape.com/api/quotes?page=1`
- `data["quotes"]`를 순회해 데이터를 누적하고 `data["has_next"]`가 거짓일 때 페이지 수집을 중단한다. 무한 반복을 막는 최대 페이지 수와 요청 실패 처리도 중요하다.

```python
# 강의 흐름을 요약한 예시. 직접 실행 결과 아님.
import requests
import pandas as pd

records = []
page = 1
while page <= 20:
    response = requests.get(
        "https://quotes.toscrape.com/api/quotes",
        params={"page": page}, timeout=10
    )
    response.raise_for_status()
    data = response.json()
    for quote in data["quotes"]:
        records.append({
            "text": quote["text"],
            "author": quote["author"]["name"],
            "tags": quote["tags"],
            "source_url": response.url,
        })
    if not data["has_next"]:
        break
    page += 1

df = pd.DataFrame(records)
```

### 딥러닝 기초 4장 1~2강 — Attention에서 Transformer로 연결

10월 29일 [기초 개념 정리](../2026-10/2026-10-29.md)에 이어 오늘은 계산 과정과 실제 PyTorch 모델 코드의 의미를 더 자세히 확인했다.

**Q/K/V의 역할과 Scaled Dot-Product Attention**

- `Q=XW_Q`, `K=XW_K`, `V=XW_V`: Q는 찾을 정보의 질의, K는 비교 기준, V는 가중합할 정보다.
- `Q @ K.T`는 **Attention Score**를 만들며, V를 직접 만든다는 뜻이 아니다. Score를 `sqrt(d_k)`로 나누고 Softmax로 **Attention Weight**를 구한 다음 `Weight @ V`를 계산한다.

```math
Attention(Q,K,V) = softmax(\\frac{QK^T}{\\sqrt{d_k}})V
```

**Multi-Head Attention**

- 각 Head는 서로 다른 학습 가능한 Q/K/V 투영을 거쳐 Attention을 병렬 계산하고, 결과를 `Concat`한 뒤 `W_O`로 출력 투영한다.
- `d_model=16`, `nhead=4`이면 Head당 차원은 `16/4=4`다. Head를 늘린다고 반드시 성능이 좋아지는 것은 아니다.
- 예: 입력 `(Batch=2, Seq=3, d_model=8)` → Head별 `(2,3,4)` → 연결·출력 투영 `(2,3,8)`.

**Positional Encoding과 Encoder/Decoder**

- 순수 Self-Attention에는 절대 위치가 명시되지 않는다. 대표적인 방식은 `Token Embedding + Position Embedding`이며 덧셈 방식은 Shape를 유지한다. Sinusoidal, Learned, RoPE는 서로 다른 방식이다.
- Encoder는 입력 전체의 문맥을 반영하는 Self-Attention과 FFN을 사용하고, 원래 Encoder-Decoder Transformer의 Decoder는 **Causal Self-Attention → Cross-Attention → FFN**을 사용한다(Residual/LayerNorm 포함).
- **Self-Attention:** Q/K/V가 같은 시퀀스에서 생성된다. **Cross-Attention:** Decoder에서 Q를 만들고 Encoder 출력에서 K/V를 만든다. 공식은 동일하지만 출처가 다르다.
- **Causal Mask:** 미래 위치의 Score에 `-inf`를 적용하여 Softmax 후 해당 가중치를 0으로 만든다. GPT 계열 Decoder-only는 일반적으로 Encoder 출력과의 Cross-Attention이 필수는 아니다.

```math
MaskedAttention(Q,K,V) = softmax(\\frac{QK^T}{\\sqrt{d_k}}+M)V
```

### Transformer Encoder Classifier — PyTorch 실습 코드 해설

강의의 예제는 8개 시계열(각 4시점의 값 1개)에서 **상승(1)/하락(0)** 패턴을 분류하는 장난감 데이터다. 코드 설명을 검토했으나 **이 대화에서 직접 실행하거나 성능을 검증한 기록은 없다**.

| 단계 | 코드/설정 | Shape |
| --- | --- | --- |
| 입력 | `tensor(...).unsqueeze(-1)` | `(8,4,1)` |
| 입력 투영 | `nn.Linear(1,16)` | `(8,4,16)` |
| 위치 정보 | `nn.Embedding(4,16)` 더하기 | `(8,4,16)` |
| Encoder | `d_model=16, nhead=4, dim_feedforward=32, num_layers=1` | `(8,4,16)` |
| 평균 풀링 | `h.mean(dim=1)` | `(8,16)` |
| 분류 Logit | `nn.Linear(16,1)` | `(8,1)` |

- `batch_first=True`는 `(Batch, Sequence, Feature)` 순서다.
- `nn.TransformerEncoderLayer`에는 Multi-Head Attention뿐 아니라 FFN·Residual·LayerNorm도 포함된다.
- `BCEWithLogitsLoss`는 학습 시 Logit을 그대로 받는다. 추론 시 `sigmoid(logits) >= 0.5`로 이진 클래스를 판단한다.
- `zero_grad() → forward → loss → backward() → optimizer.step()` 순서로 학습한다.
- 8개 학습 샘플의 예측을 확인하는 것만으로 일반화 성능을 주장할 수 없다. Attention Weight Shape를 직접 점검하는 추가 코드는 **제안된 실습**이지 실행 증거는 아니다.

## 2. 내가 궁금했던 질문과 이해한 답

1. **HTML과 JSON은 어떻게 다른가?** HTML은 웹 문서 구조이고 JSON은 데이터 교환 형식이다. 분석·AI 입력 목적에서는 둘 다 필요한 필드만 정형화해 사용하면 된다. HTML이 PPT보다 항상 낫다고 일반화할 수는 없지만, 구조화된 텍스트 추출과 자동 처리에 유리한 경우가 있다.
2. **예전에 Career Agent에서 API가 충분하지 않아 Markdown 기반 수집을 했던 접근은 오늘 수업과 관련 있나?** 관련 있다. API가 부족한 경우 다른 접근 경로에서 필요한 정보를 추출하고 공통 스키마로 바꾸는 문제다. **BeautifulSoup과 기존 방식의 우열은 사이트별 독립 비교 실험이 필요**하며, 여기서는 우수하다는 결론을 내리지 않았다.
3. **Q × K = V인가?** 아니다. Q/K로 Score와 Weight를 만들고, 그 Weight로 V를 가중합하여 Attention 출력을 얻는다.
4. **Scaled Dot-Product Attention 자체가 Cross-Attention인가?** 아니다. 이는 공통 계산 방식이고 Self/Cross의 구분은 Q/K/V가 생성되는 시퀀스의 차이에서 나온다.
5. **Transformer에서 Shape와 Head 수를 어떻게 연결하나?** 일반적인 동일 차원 Head 구성에서는 `d_head=d_model/nhead`이고 마지막 출력 차원은 Output Projection을 통해 `d_model`로 유지된다.
